# HeuriGym: An Agentic Benchmark for LLM-Crafted Heuristics in Combinatorial Optimization

## 概要

组合优化问题广泛存在于电子设计自动化、编译器设计、计算生物学与物流等工程领域，其求解质量直接影响系统效率与成本。然而，现有LLM基准测试大多停留在静态选择题或主观偏好对决层面，无法评估模型在面对真实约束时**迭代推理、创造性算法设计与工具使用**的核心能力。更关键的是，LLM普遍缺乏基于执行反馈的自适应改进能力，导致生成的启发式方案难以同时满足可行性约束与质量要求。

HeuriGym正是针对这一瓶颈提出的**智能体交互式基准框架**。其核心思路是构建一个包含执行反馈、验证结果与成本指标的迭代闭环，使LLM能够根据具体错误信号和性能指标逐步修正其生成的启发式程序。与依赖模板或仅输出最终得分的既有基准不同，HeuriGym要求模型从仅含函数签名的代码骨架出发，自主完成数据结构设计、算法实现与端到端流水线构建。

实验揭示了当前前沿模型在真实创造力上的根本局限：**GPT-o4-mini-high在10轮反馈后仍有超过四分之一的实例无法生成可行解**（SOLVE_III@10=74.8%），而表现最佳的**Gemini-2.5-Pro的加权QYI仅为0.617，远低于专家启发式的1.0**。对比实验进一步表明，缺乏执行反馈的进化框架（HSEvo、ReEvo、EoH）在相同LLM下QYI均不超过0.45，而HeuriGym的反馈机制使同一模型提升至0.617，验证了迭代反馈闭环的关键作用。消融实验则证明，移除演示实例会导致QYI从0.4196骤降至0.2351，说明在反馈环路中利用示例执行信息对模型改进至关重要。综上，HeuriGym不仅提供了一个衡量LLM算法设计能力的严格测试床，更揭示了当前模型从模式识别走向真实工程创造力之间的巨大鸿沟。



组合优化问题广泛存在于电子设计自动化、编译器、计算生物学、物流等科学与工程领域，其求解通常依赖领域专家手工设计的启发式算法。近年来，大语言模型在代码生成任务上展现出显著能力，促使研究者探索利用LLM自动生成优化启发式的可能性。

然而，现有评估范式存在根本性瓶颈。主流基准如HumanEval采用静态选择题或答案匹配方式，Chatbot Arena依赖人类主观偏好对决，均无法评估LLM在复杂组合优化中所需的迭代推理、创造性算法设计以及工具使用能力。具体而言，当前方法面临三重缺口：

**第一，缺乏执行反馈闭环。** 现有进化启发式生成框架——如**HSEvo**（Dat et al., 2025）、**ReEvo**（Ye et al., 2024）和**EoH**（Liu et al., 2024b）——虽能利用LLM生成候选解，但仅依赖最终得分或自然语言描述进行选择，缺少基于具体执行错误的诊断信息。这导致LLM难以定位代码中的约束违反、逻辑缺陷或性能瓶颈，无法实现有针对性的自适应改进。实验表明，在相同LLM下，这些框架的加权QYI均不高于0.45，而引入执行反馈后基线模型可达0.617（Table 4），差距显著。

**第二，任务选择存在记忆污染风险。** 现有工作多集中于旅行商问题（TSP）、布尔可满足性问题（SAT）等经典组合优化问题，这些问题的解法在预训练语料中大量出现，LLM可能依赖记忆而非真实推理。这掩盖了模型在陌生问题上的根本局限。

**第三，评估指标过于粗糙。** PASS@k仅衡量单次提交的正确率，无法区分“程序能运行但结果错误”与“程序因语法错误而崩溃”等不同失败模式，也无从反映解的质量与可行性的权衡。

上述缺口共同指向一个核心洞察：只有构建一个无模板、全自主的启发式生成智能体框架，并辅以迭代反馈和综合质量-产量指标，才能暴露LLM在真实工程问题求解中的根本局限。HeuriGym正是在这一动机下提出，旨在系统评估LLM从模式识别走向真实创造力之间的巨大鸿沟。



## 核心方法与创新机理

HeuriGym 的核心创新并非提出某种新的启发式算法，而是**重新定义了评估 LLM 创造性算法设计能力的范式**。它通过三个相互耦合的机制变更，将 LLM 从“静态答案生成器”转变为“自主迭代的启发式算法开发者”。

### 1. 从静态评估到智能体交互闭环

现有基准（如 HumanEval）采用静态选择题或答案匹配，无法评估 LLM 在复杂组合优化中迭代推理、工具使用和创造性算法设计的能力。HeuriGym 将评估范式彻底转向**智能体交互环**：LLM 基于结构化问题描述生成完整的启发式程序，通过代码执行获取正确性、资源消耗等反馈，并据此迭代改进。这一闭环的核心在于反馈信号的具体性——不仅是“对/错”，还包括执行日志、验证结果和评估成本，使 LLM 能够针对具体错误逐步修正其生成的启发式程序。

**因果机制**：现有进化框架（HSEvo、ReEvo、EoH）因缺乏执行反馈，在相同 LLM 下 QYI 均不高于 0.45，而 HeuriGym 的反馈机制使基线模型 Gemini-2.5-Pro 达到 0.617（Table 4），验证了**执行反馈是 LLM 自适应改进的关键瓶颈**。

### 2. 从经典问题到低曝光度的工程难题

传统基准广泛使用 TSP、SAT 等经典组合优化问题，这些问题的求解模式高度可被 LLM 预训练记忆。HeuriGym 通过**限制问题曝光度**（最高引用 <1000）筛选实际工程与科学问题，覆盖 EDA、编译器、计算生物学、物流等领域（Table 2）。这一选择策略迫使 LLM 真正理解问题结构并自主设计算法，而非复述记忆中的已知解法。

### 3. 从模板依赖到完全自主的程序生成

与依赖模板或骨架的现有方法不同，HeuriGym 在提示设计中仅提供函数签名（函数名、输入路径、输出路径），**不提供任何数据结构或算法提示**。LLM 必须自主完成从数据结构设计到端到端管线的完整程序构建。这一设计暴露了 LLM 的根本局限：即使最强模型，其加权 QYI 也仅约 0.62（Figure 2），远低于专家基线 1.0，揭示了从模式识别到真实创造力之间的巨大鸿沟。

### 4. 综合评估指标：QYI

为综合评价智能体的推理能力，HeuriGym 引入了**分阶段通过率 SOLVEs@i**（衡量执行、生成、验证三阶段的多轮通过率）和**质量-产量指数 QYI**（QUALITY 与 YIELD 的调和平均，类比 F-score）。QYI 将解的可行性与相对质量统一为一个标量，避免了单一指标（如 PASS@k）无法区分“可行但低质”与“高质但不可行”解的问题。

$$
\mathrm{QYI} = \frac{(1 + \beta^2) \cdot \mathrm{QUALITY} \cdot \mathrm{YIELD}}{(\beta^2 \cdot \mathrm{QUALITY}) + \mathrm{YIELD}}
$$

其中 $\mathrm{QUALITY} = \frac{1}{\hat{N}} \sum_{n=1}^{\hat{N}} \min\left(1, \frac{c_n^\star}{c_n}\right)$ 衡量已通过验证实例中专家成本与 LLM 成本比值的平均，$\mathrm{YIELD} = \frac{\hat{N}}{N}$ 衡量通过验证的实例比例。默认 $\beta=1$ 时，QYI 对质量和产量给予同等权重。

HeuriGym 构建了一个**智能体交互闭环**，将 LLM 从静态答案生成器转变为自主启发式程序设计师。整个框架围绕“生成—执行—验证—反馈—改进”的循环展开，核心设计在于**剥夺模板依赖、强制自主推理、并通过实例级反馈驱动迭代优化**。

### 核心流水线

框架由四个紧密耦合的模块构成，形成一个信息持续回流的闭环：

1. **问题描述**：每个基准任务配备结构化描述，包含三个部分——领域背景、数学形式化、输入/输出格式。这为 LLM 提供了理解问题语义和约束边界的唯一入口，不提供任何算法提示或数据结构建议。

2. **提示设计**：系统提示注入资源限制（8 核 CPU、内存上限、问题特定超时）和可用库版本；用户提示仅给出函数签名（函数名、输入路径、输出路径），不包含任何实现骨架。LLM 必须自主设计数据结构、算法流程和完整程序。

3. **反馈循环**：LLM 生成的程序在演示集上执行，收集三类信号——执行轨迹（错误日志、异常类型）、验证结果（通过/失败）、目标成本（与专家启发式对比）。这些信号被直接追加到下一轮提示中，形成**基于实例错误的定向修正**机制。

4. **评估指标计算**：采用分阶段指标 `SOLVE_s@i` 追踪执行（Stage I）、输出生成（Stage II）、验证通过（Stage III）三个关卡在 `i` 轮内的通过率，最终以 **QYI**（Quality-Yield Index）综合衡量解的质量与可行性。

### 关键设计决策

与现有进化框架（HSEvo、ReEvo、EoH）的根本区别在于**反馈信号的粒度和来源**。这些框架仅依据最终得分进行选择，缺乏执行层面的错误诊断；而 HeuriGym 的反馈循环将具体的执行日志和验证失败信息回传，使 LLM 能够定位约束违反点、逻辑漏洞或资源超限原因。Table 4 的证据支持这一判断：在相同 LLM（Gemini-2.5-Pro）下，进化框架的 QYI 均不超过 0.45，而 HeuriGym 的反馈机制将 QYI 推至 0.617。

问题选择的**低曝光度准则**（最高引用 < 1000）是另一关键设计。通过排除 TSP、SAT 等广泛预训练记忆的问题，基准更真实地测试 LLM 面对陌生工程问题时的推理创造力，而非记忆检索能力。

### 输入输出流

- **输入**：问题描述（自然语言 + 形式化定义）+ 代码接口（仅函数签名）+ 系统资源约束 + 历史反馈日志（从第二轮起）。
- **输出**：完整的启发式程序（Python，部分支持 C++），经执行环境验证后，产出可行性判断、成本指标及下一轮反馈信号。

### 局限性提示

当前框架的反馈机制存在**上下文膨胀**风险：迭代过程中日志和代码量快速增长，可能超出上下文窗口，导致后期改进效益递减。消融实验（Table 23）已观察到这一边际效用递减现象——反馈轮数从 5 轮增至 10 轮时，加权 QYI 反而从 0.6259 下降至 0.6170。此外，框架主要支持 Python 执行，C++ 集成尚不完整，限制了大规模实例的运行效率。



### 3.1 智能体交互闭环

HeuriGym 的核心是一个由四个模块构成的智能体交互闭环，使 LLM 能够在真实执行环境中迭代生成和优化启发式程序。

**问题描述模块**为每个基准任务提供结构化的三部分描述：(1) 领域背景，解释问题的实际来源与工程意义；(2) 数学形式化，以精确符号定义目标函数与约束；(3) 输入/输出格式，规定程序必须遵循的数据接口规范。这种结构化设计确保 LLM 在统一的认知框架下理解异构问题，而非依赖对经典问题（如 TSP）的预训练记忆。

**提示设计模块**通过系统提示与用户提示的分层约束，迫使 LLM 进行自主算法设计。系统提示包含机器配置（8 核 CPU、内存限制）、可用库及版本号、问题特定的执行超时等资源约束；用户提示则仅提供函数签名（函数名、输入路径、输出路径），不给出任何数据结构或算法策略的提示。这一设计消除了模板依赖，要求模型自行完成从问题建模到代码实现的完整推理链。

**反馈循环模块**是 HeuriGym 区别于静态评测的核心机制。在每一轮迭代中，LLM 生成的程序在演示集上执行，系统收集三类信号：(1) 执行轨迹，记录程序是否成功运行、是否超时或抛出异常；(2) 验证结果，判断输出是否满足问题约束；(3) 目标成本，即解的质量分数。这些信号以结构化日志形式附加到下一轮提示中，使模型能够基于具体错误实例进行针对性修正。

**评估指标计算模块**则从多维度量化 LLM 的推理能力，详见下文公式体系。

### 3.2 关键公式与变量含义

HeuriGym 引入了一套分阶段、多轮次的指标体系，以捕捉 LLM 在复杂问题求解中的渐进式改进能力。

**阶段通过率 SOLVE_s@i** 衡量在前 $i$ 轮迭代内通过阶段 $s$ 的实例比例：

$$\operatorname{SOLVE}_s @ i := \frac{1}{N} \sum_{n=1}^{N} \mathbb{1}\left( \text{pass stage } s \text{ in the first } i \text{ iterations} \right)$$

其中 $N$ 为评估实例总数，阶段 $s$ 分为三级：Stage I（执行通过，程序无运行时错误）、Stage II（生成通过，输出文件格式正确且可解析）、Stage III（验证通过，输出满足所有约束条件）。该指标通过追踪不同阶段的通过率，解耦了 LLM 在编码正确性、格式合规性和约束满足性三个层次上的能力。

**质量指标 QUALITY** 衡量已通过验证的实例中，LLM 解相对于专家启发式解的成本比值：

$$\mathrm{QUALITY} = \frac{1}{\hat{N}} \sum_{n=1}^{\hat{N}} \min\left(1, \frac{c_n^{\star}}{c_n}\right)$$

其中 $\hat{N}$ 为通过 Stage III 验证的实例数，$c_n^{\star}$ 为专家启发式在该实例上的目标成本，$c_n$ 为 LLM 生成解的成本。比值截顶至 1，防止单个实例的极端优异表现掩盖整体质量缺陷。

**产量指标 YIELD** 衡量通过验证的实例比例，即解的可行性覆盖范围：

$$\mathrm{YIELD} = \frac{\hat{N}}{N}$$

**综合指标 QYI** 通过调和平均将质量与产量统一为单一分数，类比 F-score 的设计理念：

$$\mathrm{QYI} = \frac{(1 + \beta^2) \cdot \mathrm{QUALITY} \cdot \mathrm{YIELD}}{(\beta^2 \cdot \mathrm{QUALITY}) + \mathrm{YIELD}}$$

其中 $\beta$ 控制 YIELD 相对于 QUALITY 的重要性权重，默认 $\beta = 1$ 时两者等权。最终报告采用加权 QYI，以各任务的实例数量为权重计算加权平均，避免小规模任务过度影响整体评估。专家基线（QYI = 1.0）采用问题特定的已知启发式方法，为 LLM 性能提供实用的上界参照。



## 实验与关键发现

### 主结果：LLM 与专家之间仍存在显著性能鸿沟

Table 3 报告了所有模型在 HeuriGym 全部 9 个问题上的整体 SOLVEs@i 指标。即使是最强模型 **GPT-o4-mini-high**，在给予 10 轮迭代反馈后，其 SOLVE_III@10 也仅达到 74.8%，意味着仍有超过四分之一的实例无法生成通过验证的可行解。其余模型的表现更为逊色：**Gemini-2.5-Pro** 的 SOLVE_III@10 为 65.1%，而 **DeepSeek-V3** 和 **LLaMA-4-Maverick** 等模型则低于 50%。

![[assets/figures/papers/paper_list_l19_https_openreview_net_forum_id_HWxHUO15Yy/figures/004_Table_3.jpg]]
*Table 3: Overall SOLVEs@i metric of models on the whole HeuriGym benchmark*

Figure 2 以加权 QYI 综合衡量解的质量与可行性。专家基线设定为 QYI = 1.0，而 **Gemini-2.5-Pro** 仅取得 0.617 的加权 QYI，**GPT-o4-mini-high** 紧随其后（约 0.61）。这一差距表明，当前 LLM 在无模板、全自主生成完整启发式程序的场景下，其综合求解能力尚不及人类专家实用启发式方案的 60%。值得注意的是，Figure 2 同时展示了各模型的估计 API 成本：**Gemini-2.5-Pro** 以相对适中的成本获得了最高的 QYI，而部分模型（如 **Claude-3.7-Sonnet**）虽成本更高，QYI 却显著更低，说明更高开销并不必然带来更好的优化能力。

![[assets/figures/papers/paper_list_l19_https_openreview_net_forum_id_HWxHUO15Yy/figures/006_Figure_2.jpg]]
*Figure 2: Quality-Yield Index and estimated API cost of different models*

### 与进化启发式框架的对比

Table 4 将 HeuriGym 的智能体循环与三种现有进化启发式生成框架进行了对比。在相同基础模型 **Gemini-2.5-Pro** 下，**HSEvo**（Dat et al., 2025）、**ReEvo**（Ye et al., 2024）和 **EoH**（Liu et al., 2024b）的 QYI 分别仅为 0.4491、0.4486 和 0.4492，而 HeuriGym 的反馈机制使同一模型达到 0.6170。这一约 0.17 的 QYI 提升直接归因于 HeuriGym 的核心设计差异——进化框架缺乏基于执行反馈的自适应改进能力，仅依赖种群级别的变异与选择，无法针对具体错误进行定向修复。

### 消融实验：演示实例与迭代反馈的关键作用

Table 5 在“取送及时间窗”问题上进行了系统的消融研究。当完全移除演示实例（0 demos）时，QYI 从 0.4196（5 demos, 10 rounds）骤降至 0.2351，降幅超过 40%。这一结果验证了在反馈环路中提供实例级别的执行信息对模型理解约束和修正错误至关重要。

![[assets/figures/papers/paper_list_l19_https_openreview_net_forum_id_HWxHUO15Yy/figures/008_Table_5.jpg]]
*Table 5: Ablation study on pickup and delivery with time windows*

迭代轮数的影响同样显著：从 1 轮增至 10 轮带来约 0.18 的 QYI 提升（0.2350 → 0.4196），说明多轮反馈能有效帮助模型逐步修复逻辑错误和约束违反。然而，Table 23 的进一步消融显示，反馈轮数存在边际效用递减：在 Gemini-2.5-Pro 上，加权 QYI 从 1 轮（0.6253）到 5 轮（0.6259）略有上升，但增至 10 轮时反而下降至 0.6170。这暗示随着迭代进行，附加的日志和代码量快速增长，可能超出模型的上下文有效利用范围，导致后期改进效益衰减。

关于演示数量的阈值效应，Table 22 显示：在 Gemini-2.5-Pro 上，完全移除演示（Zero-shot）的加权 QYI 为 0.5999，使用全量演示（Full-shot）为 0.6170（提升约 3%），而 Half-shot 设置反而使 QYI 降低。这表明演示数量并非线性有益，存在一个最优的信息密度区间。

### 温度对质量-产量权衡的影响

Tables 19–21 分别报告了 T = 0、0.5、1 下的模型性能。在 T = 0（贪婪解码）下，**Gemini-2.5-Pro** 以 0.6170 的加权 QYI 领先；而在 T = 1 下，**GPT-o4-mini-high** 以 0.6089 反超。Figure 4 揭示了温度调控下的质量-产量权衡规律：T = 0 倾向于最大化 YIELD（更多实例通过验证），但 QUALITY 相对较低；T = 1 的随机解码能产生更高质量的解，但无效输出增多导致 YIELD 下降。这种权衡在不同模型上表现各异，说明温度是调节 LLM 探索-利用行为的关键杠杆。

### 失败模式分析

Figure 3 对错误类型进行了分类统计。最常见的失败模式包括：（1）**逻辑错误与约束违反**——模型生成的启发式程序未能正确编码问题的核心约束，导致验证阶段失败；（2）**运行时错误**——代码存在语法错误、类型不匹配或超出资源限制（超时、内存溢出）；（3）**算法设计缺陷**——模型采用了次优或根本不适用的算法策略，虽能通过执行和验证，但解的质量远低于专家基线。Table 12 显示，在 **global routing** 问题上，所有模型在所有迭代轮次内均无法生成可行解（SOLVE_III@10 = 0），表明某些高难度组合优化问题对当前 LLM 而言仍是完全不可逾越的障碍。

### 前沿模型的最新进展

Table 6 报告了 2026 年 2 月最新 10 个前沿模型的性能。**Gemini-3.1-Pro** 以 0.878 的加权 QYI 和 0.947 的 QUALITY 领先，**GPT-5.3-Codex** 在 SOLVE_III@5 上达到 93.6%，SOLVE_II@5 达到 100%。尽管相比早期模型有显著进步，但 QYI 仍低于专家基线 1.0，说明即便最新一代 LLM 在自主启发式生成上仍未完全弥合与人类专家的差距。



## 定位与知识库关联

### 与现有LLM启发式生成框架的关系

HeuriGym 与当前主流的基于进化搜索的LLM启发式生成框架形成直接对比。这些框架——**HSEvo** (Dat et al., 2025)、**ReEvo** (Ye et al., 2024) 和 **EoH** (Liu et al., 2024b)——均采用进化算法作为外层搜索策略，通过LLM生成候选启发式程序，再依据适应度得分进行选择与变异。然而，这些框架缺乏执行层面的反馈闭环：LLM仅接收最终的适应度数值，无法获知程序为何失败、何处违反了约束、或如何具体改进。HeuriGym 的核心区分点在于引入了一个包含**执行日志、验证结果和成本指标**的迭代反馈环路，使LLM能够根据具体的错误信息和性能数据逐步修正其生成的启发式程序。

实验证据直接支持这一区分：在相同基座模型 Gemini-2.5-Pro 下，HeuriGym 的 SOLVE_III@10 达到 0.6514，而 HSEvo、ReEvo 和 EoH 分别仅为 0.5000、0.4771 和 0.4954（Table 4）。更关键的是，这三者的加权 QYI 均不高于 0.45，而 HeuriGym 的反馈机制使同一模型达到 0.6170——提升幅度超过 37%。这表明，缺乏执行反馈的进化框架在复杂组合优化任务上严重受限于LLM对“黑箱得分”的解读能力，而结构化反馈是解锁LLM迭代改进能力的关键因果杠杆。

与更早期的静态评估基准（如 HumanEval 的封闭式答案匹配、Chatbot Arena 的主观偏好对决）相比，HeuriGym 将评估范式从“单次生成-判定”推进到“生成-执行-反馈-修正”的多轮智能体交互。这一转变暴露了当前LLM的一个根本局限：即便最强模型（GPT-o4-mini-high）在 10 轮反馈后的 SOLVE_III@10 也仅为 74.8%（Table 3），意味着仍有超过 1/4 的实例无法生成可行解。

### 适用边界与任务设计约束

HeuriGym 的适用边界由其问题选择策略和框架设计共同界定：

**问题选择的低曝光度约束。** 为避免预训练记忆对评估的污染，HeuriGym 排除了广泛使用且引用量极高的经典组合优化问题（如 TSP、SAT），仅纳入最高引用论文引用数低于 1000 的实际工程与科学问题。当前基准覆盖 EDA、编译器、计算生物学和物流四个领域共 9 个问题（Table 2），包含 covering、scheduling、routing 等不同问题类型。这一策略有效降低了记忆效应的干扰，但也意味着基准的领域覆盖度有限，泛化结论需谨慎对待——9 个问题无法代表组合优化的全部多样性。

**代码生成的自主性要求。** 与依赖模板或骨架代码的现有方法不同，HeuriGym 仅向LLM提供函数签名（函数名、输入路径、输出路径），不包含任何数据结构或算法提示。LLM必须自主设计完整的数据结构和端到端求解流程。这一设计放大了LLM在算法创造力上的差异，但也使得某些需要领域特定库支持的任务（如 global routing）对所有模型均构成不可逾越的障碍——Table 12 显示该问题所有模型的 SOLVE 指标均为 0。

**执行环境的语言限制。** 当前框架主要支持 Python，仅对部分任务（如 technology mapping）扩展了 C++ 支持（Table 25）。这限制了大规模实例的运行效率，也可能使某些依赖 C++ 生态的领域问题无法充分发挥LLM的算法设计能力。

**专家基线的相对性。** QYI=1 的专家基线采用已知的实用启发式方法，而非理论最优解。这意味着 QYI 仅反映LLM与实用启发式的差距，不代表与理论下界的绝对距离。对于某些问题，专家启发式本身可能离最优解较远，此时 QYI 可能高估LLM的相对表现。

### 核心局限与失败模式

**反馈环路的边际效用递减。** 消融实验（Table 23）表明，反馈轮数从 1 轮增至 5 轮时加权 QYI 仅有微弱提升（0.6253→0.6259），增至 10 轮时反而下降至 0.6170。这一边际效用递减的根源在于：迭代过程中附加的执行日志和代码量快速增长，可能超出上下文窗口的有效利用范围，导致后期迭代中关键信息被稀释或遗忘。

**演示实例的阈值效应。** Table 22 显示，在 Gemini-2.5-Pro 上，完全移除演示数据（Zero-shot）的加权 QYI 为 0.5999，使用全量演示（Full-shot）为 0.6170（提升约 3%），但 Half-shot 反而降低了 QYI。这表明演示数量存在非线性的阈值效应——过少的演示可能引入噪声而非有效引导，而过多的演示则受限于上下文窗口的边际收益。

**温度对质量-产量的权衡。** 不同温度设置下模型表现波动显著（Tables 19-21）：T=0 时 Gemini-2.5-Pro 的 QYI 最高（0.6170），T=1 时 GPT-o4-mini-high 以 0.6089 领先。更高的温度增加了输出多样性，可能提升解的质量，但同时降低了产出率（YIELD），因为更多生成无法通过验证阶段。这一权衡在 Figure 4 中得到系统刻画：贪心解码（T=0）最大化产出率，而随机采样（T=1）更可能发现高质量解。

**特定任务的系统性失败。** Global routing 问题（Table 12）对所有模型均构成不可逾越的障碍，所有 SOLVE 指标均为 0。这揭示了当前LLM在处理需要复杂空间推理和全局约束传播的任务时的根本性不足，而非简单的提示或反馈策略可解决。

### 开放问题

1. **长期记忆与上下文管理。** 如何设计有效的上下文压缩或外部记忆机制，以避免在长序列迭代中关键反馈信息被稀释？当前框架的简单日志追加策略在 10 轮后已显现边际效用递减，更长的迭代序列需要根本性的架构改进。

2. **多智能体分工协作。** 能否将复杂组合优化任务分解为子任务（如约束解析、数据结构设计、算法选择、局部搜索），由不同智能体分别负责？当前框架将所有认知负荷集中于单一智能体，可能超出了LLM的有效推理深度。

3. **结构化反馈信号。** 当前反馈仅包含执行结果和指标数值。能否引入更丰富的错误分析信号——如符号执行、类型检查、约束违反的具体定位——以指导更精准的程序修复？Figure 3 的错误分类表明，逻辑错误和约束违反是主要失败模式，但当前反馈并未对这些错误类型进行结构化标注。

4. **与理论下界的对比。** 当前 QUALITY 指标依赖专家启发式作为参照，无法反映LLM解与理论最优的绝对差距。建立与理论下界的对比机制，将更准确地度量LLM的真实算法设计能力。

5. **C++ 执行环境的深度集成。** 将框架与 C++ 执行环境深度集成，是提高大规模实例运行效率和可解决性的必要条件。当前部分领域特定的 C++ 库依赖限制了这一扩展，需要系统性的工程解决方案。
