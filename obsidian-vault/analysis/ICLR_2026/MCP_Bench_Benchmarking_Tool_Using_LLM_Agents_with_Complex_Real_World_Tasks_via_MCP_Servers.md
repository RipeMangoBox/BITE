# MCP-Bench: Benchmarking Tool-Using LLM Agents with Complex Real-World Tasks via MCP Servers

> [!tip] 核心洞察
> 通过将LLM代理接入基于MCP的、包含互补工具和跨服务器依赖的真实生产级生态系统，并构建多目标模糊指令任务，MCP-Bench成功将评估焦点从基础API调用转移到复杂推理、信息接地和规划协调，从而使现有基准中未被充分测试的代理能力得到有效暴露和衡量。

## 概要

大语言模型（LLM）的工具使用能力已从简单的API调用走向复杂的真实世界任务自动化，但现有基准大多停留在独立工具、显式指令和少步线性流程的层面，难以揭示代理在长程规划、跨工具依赖推理和模糊目标下的真正瓶颈。MCP-Bench 应运而生：它将 LLM 代理接入由 28 个生产级 MCP 服务器构成的统一生态，这些服务器覆盖金融、科学计算、旅行、学术搜索等领域，共暴露 250 个互补工具，原生支持跨服务器依赖。在此基础上，MCP-Bench 通过一个结构化的任务合成管道，自动发现工具间的依赖链并生成多步、多目标的复合任务，最后将详细指令模糊化为高度抽象的自然语言请求，刻意隐藏工具名称和执行细节，迫使代理自主推断策略。评估体系结合了基于规则的工具调用正确性检查（工具名称有效性、模式合规、执行成功）与基于评分细则的 LLM 裁判框架，从任务完成度、工具使用策略和规划效率三个轴向进行细粒度打分，并通过提示洗牌和多次评分平均提升可靠性与人类一致性。

实验揭示了一个鲜明的矛盾：前沿模型在基本的工具调用“执行”层面已趋于饱和（如 claude-sonnet-4 实现近 100% 的工具名称有效率和模式合规率），但在涉及依赖感知、并行性和任务分解的高层“规划”能力上却远未饱和。以 GPT-5 为例，其整体得分最高（0.749），信息接地（Information Grounding）达到 0.828，但“并行性与效率”得分仅为 0.339，显示其多步协调仍有明显短板。模型间的表现分层显著：GPT-5 的整体得分比最弱的 llama-3-1-8b-instruct 高出 0.321，且在信息接地和任务完成度上的差距尤其悬殊。当任务从单服务器扩展到多服务器时，即使强模型如 o3 的平均交互轮次也从 4.5 增至 8.0、工具调用数从 23.0 增至 33.7，表明跨域协调大幅增加了难度。干扰服务器的引入进一步放大了效率鸿沟：小型模型可能消耗 17 轮、155 次调用，而高效模型仅需 6−8 轮。人工分析规划失败轨迹发现，排序与依赖错误（25.8%）、冗余规划（22.6%）和错误任务分解（21.5%）是最主要的三大失败类型，直指当前 LLM 在结构化推理与全局统筹上的共性弱点。

相比 ToolBench、BFCL v3、τ-Bench 等已有基准，MCP-Bench 通过 MCP 协议的标准化工具连接、刻意模糊的任务指令、多跳多目标的复杂目标设计以及规则与 LLM 裁判结合的稳健评估，首次系统地将评测重心从浅层执行转移到了深层战略推理与真实世界适应性。这一设计使基准能够有效暴露那些在传统评测中被掩盖的规划与接地赤字，为未来工具使用代理的研发提供了更严苛且更具生态效度的检验场。



大语言模型（LLM）通过调用外部工具执行复杂任务的能力正成为智能代理的核心。然而，现有工具使用基准大多聚焦于简单的“指令-调用-结果”模式，未能充分考察代理在真实场景中所必需的**多步规划、跨工具依赖推理以及从模糊指令中推断执行策略**等高阶能力。当前评测的主要缺口体现在三个层面：

- **工具生态的封闭性与碎片化**。早期的代表性基准如 ToolBench 依赖大量独立异构的 API，缺少跨工具依赖链的原语和统一的交互协议；BFCL v3 的任务虽然覆盖多个函数域，但其工具组合通过人工拼接，无法反映真实服务的多样化与动态性；τ-Bench 在数据库交互中引入了部分依赖链，但领域和工具数量极为有限。即便是基于 MCP（Model Context Protocol）的初步尝试 MCP-RADER 和 MCPEval，其连接的服务器数、工具种类以及任务流程长度仍显不足，未能系统性地测试跨域协同和模糊目标场景。
- **任务指令的过度规约**。多数基准向代理提供包含明确工具名称和执行步骤的提示，屏蔽了代理从自然语言中自主推断工具链和规划路径的需求。真实用户通常以模糊、目标导向的方式提出请求，而现有基准很难测量代理在**信息接地**和**任务分解**上的实际差距。
- **评估维度的单一化**。以往评测大多只关注执行成功与否或简单的相似度分数，缺乏对**规划效率、并行调度、依赖顺序正确性**以及**证据溯源**的细粒度度量，导致对模型综合能力的描摹失真。

事实上，尽管前沿模型在工具名识别和参数模式理解等基础调用层面已接近饱和，但它们的**规划效果**远未触顶：例如在单服务器设定下，gpt-5 的“并行性与效率”得分仅为 0.339，排序与依赖错误、冗余规划和错误任务分解三大类规划失败占比分别高达 25.8%、22.6% 和 21.5%（Table 3，Section A.10）。这些差异难以被旧有基准捕捉，根源在于缺少**真实、互补且带有语义依赖的工具生态**以及**多目标模糊指令**这两个关键设计变量。

为此，MCP‑Bench 的动机是通过以下三个核心改变，将评估焦点从基础的 API 调用转移到**复杂推理、信息接地和规划协调**上：

1. **基于 MCP 的真实生产级工具生态**。接入 28 个覆盖金融、科研、生物医学、旅行等领域的线上 MCP 服务器，提供 250 个具有自然输入/输出依赖的互补工具，并支持原生的跨服务器依赖链，从而复现真实世界中工具使用的复杂性。
2. **模糊且面向目标的自然语言任务**。通过结构化的任务合成流水线剥离工具名和显式步骤，只保留关键数值指标，迫使代理自主推断可执行的工具序列。
3. **多轴、去偏的混合评估框架**。将基于规则的执行审查与基于评分细则（rubric）的 LLM 裁判相结合，从**任务完成度、信息接地、工具适宜性、规划效率**四个战略维度进行评分，并通过提示洗牌和多次平均化提升评判稳定性。

这些设计的直接目标是暴露并量化模型在长程规划、跨工具依赖推理和模糊到具体的映射能力上的真实差距，为下一代工具使用代理的发展提供更可信的试金石。



## 核心方法与创新机理

MCP-Bench 的关键创新并非提出新的代理架构，而是通过**三个系统性的基准设计转变**，将评估焦点从低层的工具调用准确性推至代理的高层规划与推理能力。这些转变共同解决了现有基准中普遍忽视的瓶颈：长程多步规划、跨工具依赖推理以及从模糊指令中自主推断策略。

### 1. 基于 MCP 的统一真实工具生态与跨服务器依赖原语

现有基准（如 ToolBench、BFCL v3）使用无统一协议的独立 API 或人工拼接的小型工具集，τ-Bench 虽部分支持依赖链，但领域和工具数量极为有限（Table 1）。MCP-Bench 首次将 28 个生产级 MCP 服务器、250 个互补工具组织成一个结构化的生态，原生支持跨服务器依赖的发现与任务生成（Section 4.1, Table 7）。这一改变迫使代理处理真实世界中的工具输出耦合与跨域协调：在多服务器设置下，强模型如 o3 的平均交互轮次由 4.5 激增至 8.0，工具调用数由 23.0 升至 33.7（Table 6）。同时，故意插入的干扰服务器进一步放大了模型的效率鸿沟——小型模型如 llama-3-1-8b-instruct 平均需要 17.3 轮、155 次调用，而高效模型仅需 6–8 轮（Table 6）——表明规模化工具生态对规划效率的严苛考验远超以往。

### 2. 模糊指令与多步多目标任务合成管线

以往基准或提供显式工具名称与详细步骤，或仅设计简单的单目标信息检索。MCP-Bench 的自动化任务合成管道（Section 4.2）从真实工具依赖链出发，由 LLM 生成 104 个多步复合任务（含 56 个单服务器、30 个二服务器和 18 个三服务器任务），并经过可解性（≥9/10）与实用性（≥5/10）质量过滤。关键创新在于**任务模糊化**：将指令转换为自然、对话式的模糊请求（Table 2），刻意隐藏工具名称和执行顺序，迫使代理自主推断执行策略。这一设计直接暴露了规划层面的三大主要失败模式：排序与依赖错误（25.8%）、冗余规划（22.6%）以及任务错误分解（21.5%）（Section A.10）。实验显示，即使前端模型 GPT-5 的信息接地得分高达 0.828，其规划效果中的“并行性与效率”维度仅为 0.339（Table 3），证明从模糊指令到多步稳健规划的鸿沟远未被填平。

### 3. 混合多维评估框架与裁判校准

传统评估依赖简单的执行成功/失败或单维度指标，无法区分模式理解与战略推理。MCP-Bench 构建了规则检查与 LLM 裁判相结合的双层评估（Section 5）。规则层通过工具名有效性、模式合规率和执行成功率（三者公式定义见 Section 5.1）作为鲁棒的下限检查，而 LLM 裁判层采用结构化评分细则，从任务完成度、工具使用质量与规划效果三个轴进行多维打分，并通过**提示洗牌与多次评分平均**将裁判变异系数从 16.8% 降至 15.1%，与人类评分一致性提升至 1.43/2（消融 Table 12）。这一组合不仅提供了对代理战略推理、依赖意识和并行效率的细粒度测量，还通过非 OpenAI 裁判模型对比（Section A.9）证明了框架的厂商中立性，使评估结果更具信度与区分度。

三者协同，使 MCP-Bench 得以有效暴露并量化现有 LLM 代理在真实复杂工具使用场景中的关键规划短板，从而为未来的能力改进提供明确的因果性衡量标尺。

MCP-Bench 整体的评估管线围绕“真实工具生态—复杂任务合成—多轮代理执行—双阶段评估”的主轴展开，并通过模糊指令与跨服务器依赖放大规划能力的区分度（Figure 1）。相比现有基准（Table 1），其核心差异在于将代理接入基于 MCP 的统一工具协议生态，从而自然引入跨服务器依赖、信息接地与大规模干扰工具等现实挑战，再通过自动化任务合成与多轴评估框架将这些挑战转化为可量化信号。

**管线模块与数据流**

1. **依赖链发现**  
   首先分析所有接入 MCP 服务器中工具的输入/输出签名，识别自然依赖（如一个工具的输出可作为另一个工具的输入）以及场景依赖，构建任务生成所需的结构化骨架。这一步骤的输出是若干候选依赖链，为后续任务合成提供语义约束基础。

2. **任务生成与质量过滤**  
   基于上一步的依赖链，使用 LLM（o4-mini）自动生成多目标、多步组合的任务草案。每项草案经自动评分：可解性须 ≥9/10，实用性须 ≥5/10，低于阈值的任务被滤除，最终保留 104 项高质量任务（包含 56 项单服务器、30 项双服务器、18 项三服务器任务）。该模块的输入是依赖链集合，输出是经过筛选的、附带详细步骤定义的任务实例。

3. **任务模糊化**  
   将筛选后的任务从显式步骤描述转化为自然对话式的模糊指令：保留关键数值（如日期、坐标、参数），但刻意隐藏工具名称、执行顺序和服务器身份，迫使代理自行推断工具选择与执行策略。输入为原始任务描述，输出为目标导向的模糊用户查询。

4. **多轮代理执行**  
   代理以模糊指令为输入，在最多 20 个交互轮次内与 MCP 服务器交互。每轮遵循“规划—工具调用—观察压缩—状态更新”循环（参见 Algorithm 1）。执行环境支持单服务器和多服务器模式，并会随机附加 10 个干扰服务器以增加检索和选择难度。该模块产生的输出是包含所有交互记录的执行轨迹。

5. **基于规则的执行评估**  
   从执行轨迹中提取三项机械性指标，作为对基本模式理解能力的鲁棒性下限：工具名称有效性比例（公式 $R_{\mathrm{valid}}$）、模式合规比例（公式 $C_{\mathrm{schema}}$）以及执行成功率（公式 $R_{\mathrm{success}}$）。输入为轨迹，输出为三个标量。

6. **LLM-as-a-Judge 战略评估**  
   采用 o4-mini 作为评判模型，基于结构化评分细则对三个战略维度打分：任务完成质量（含指令遵循、目标达成与信息接地）、工具选择与使用合理性、规划有效性（分步分解、依赖感知、并行与效率）。为降低题目顺序偏倚，评估时对评分轴顺序进行五次独立洗牌，取四次中间值的平均作为最终单任务评分。输入为执行轨迹和任务描述，输出为经过平均化的多维度分数。

7. **整体得分计算**  
   将各战略维度得分归一化至 $[0,1]$，与规则指标按任务取未加权平均，得到单任务整体分；再对所有任务的整体分取平均，产生面向整个基准的总分（Overall Score）。该总分是排行榜的核心比较指标（Table 3）。

整个管线中，“依赖链发现—任务生成—模糊化—多轮执行—双阶段评估”构成闭环：模糊指令和干扰服务器放大代理在规划、信息接地与跨域协调上的差距，而规则评估捕捉模式理解的饱和与否，LLM 裁判评估则深入量化高层推理质量。这种组合使 MCP-Bench 能够有效暴露即使强模型在长程规划、冗余调用和依赖感知等方面的不足（如 GPT-5 的并行性与效率得分仅为 0.339，Table 3），从而将评估焦点从基础 API 调用转移到复杂推理与协调能力。



### 任务生成流水线

MCP‑Bench 的任务合成流水线由三个紧密耦合的模块构成（第4.2节）：

1. **依赖链发现**：静态分析每个MCP服务器中工具输入/输出签名，自动识别跨工具的自然数据依赖（如前一工具的输出作为后一工具的必需参数）和场景依赖，形成结构化的任务骨架。
2. **自动质量过滤**：基于依赖链，先用大型语言模型（o4‑mini）批量生成候选任务，再通过可解性≥9/10 和实用性≥5/10 的双阈值自动滤除低质量样本。
3. **任务模糊化**：将包含工具名、执行步骤的详细描述转化为自然、对话式的模糊指令，仅保留关键数值与目标约束，强制代理自行推断工具选择与执行序列。

该流水线最终产出104个任务，覆盖56个单服务器、30个双服务器和18个三服务器场景。

### 代理执行框架

代理与MCP服务器的交互被形式化为部分可观测马尔可夫决策过程的扩展（第3节），定义为八元组：
$$(\mathcal{S}, \mathcal{A}, \mathcal{O}, T, R, \mathcal{U}, \Sigma)$$
其中$\mathcal{S}$为真实及信念状态空间；$\mathcal{A}$为动作空间，由规划动作集$\mathcal{A}_{\mathrm{planning}}$和工具调用动作集$\mathcal{A}_{\mathrm{tools}}$的并集构成；$\mathcal{O}$为观测空间；$T$为状态转移函数；$R$为奖励函数；$\mathcal{U}$为自然语言指令集；$\Sigma$为MCP服务器集合。每个工具调用动作具体表示为：
$$a_{\mathrm{tool}} = \langle \sigma_i, \text{tool\_name}, \text{parameters} \rangle$$
即指定目标服务器索引$\sigma_i$、工具名称和参数字典。

执行遵循**多轮规划与观测**范式（Algorithm 1）：代理在最多20轮循环中，每轮根据历史观测生成下一个规划动作或工具调用计划，执行后获得观测结果并更新状态。这一范式使模型能在跨域长程任务中逐步积累信息。

### 评估指标与公式

评估体系由基于规则的执行检查和基于LLM的战略评分共同构成（第5.1–5.2节）。

#### 规则基准指标

三个基础指标从轨迹中直接计算，用于衡量工具调用的表层合规性：

- **工具名称有效性比例**
  $$R_{\mathrm{valid}} = \frac{ |\{ e \in E : \mathrm{tool}(e) \in \mathcal{T}_{\mathrm{available}} \}| }{|E|}$$
  $E$为全部工具调用事件，$\mathcal{T}_{\mathrm{available}}$为当前任务可用的工具集合。该指标反映代理是否只调用允许的工具。

- **模式合规比例**
  $$C_{\mathrm{schema}} = \frac{ |\{ e \in E : \mathrm{valid\_tool}(e)\,\wedge\,\mathrm{valid\_schema}(e) \}| }{ |\{ e \in E : \mathrm{valid\_tool}(e) \}| }$$
  分母为有效工具调用，分子为同时通过参数模式校验的调用。衡量代理在参数层面的正确性。

- **执行成功比例**
  $$R_{\mathrm{success}} = \frac{ |\{ e \in E : \mathrm{success}(e) \}| }{|E|}$$
  统计无运行时错误且返回有效结果的调用占比，作为执行层面的基础质量。

实验结果显示（Table 3），前沿模型（如claude‑sonnet‑4）在此类指标上已接近饱和，而小型模型存在明显差距，说明这些指标能充当能力分化的下限检测。

#### LLM裁判评分

为评估代理的战略推理质量，MCP‑Bench引入基于o4‑mini的评委框架，按1–10分对三个轴进行细粒度打分，各轴均值归一化至$[0,1]$：
- **任务完成质量**（含任务完成度、信息接地）；
- **工具使用合理性**（含工具选择、参数适用性等）；
- **规划有效性**（含依赖感知、并行效率、跨域协调等）。

为降低评委主观偏差，采用**提示洗牌**与**评分平均**：随机排列各轴的评分顺序，独立执行5次打分，取四个中间值的均值作为最终轴分。消融实验（Table 12）表明，该策略将不同模型间的评分变异系数从16.8%降至15.1%，并将与人类一致性从1.24/2提升至1.43/2。

#### 整体得分整合

各轴得分经归一化后未加权平均得到单任务整体分，再对所有104个任务取均值，输出基准总分。此设计使得总分能同时反映表层执行熟练度和深层规划协调能力。



## 实验与关键发现

### 基本工具调用趋于饱和，但复杂推理瓶颈显著

MCP-Bench 通过系统集成 28 个生产级 MCP 服务器和 250 个工具，构建了 104 个多步、跨域、模糊指令的复合任务。在 20 个代表性 LLM 代理的评估中，规则性执行指标（工具名称有效性、模式合规性、执行成功率）在强模型上已接近上限：例如 claude-sonnet-4 分别达到 100%、99.8% 和 98.8%（Table 3）。这表明模型已能可靠地理解工具模式并完成基本的单步调用。

![[assets/figures/papers/iclr26_0014_fe8mzHwMxN_MCP-Bench_Benchmarking_Tool-Using_LLM_Agents_wit/figures/006_Table_3.jpg]]
*Table 3: Leaderboard on MCP-BENCH, i.e., results of different models, averaged across settings with single server and multiple servers*

然而，LLM 裁判评分的多维度战略指标揭示出巨大分化。综合得分最高的 gpt-5 获得 0.749，而最低的 llama-3-1-8b-instruct 仅为 0.428，差距达 +0.321（Table 3）。尤其在信息接地（Information Grounding）上，gpt-5 达到 0.828，llama-3-1-8b-instruct 仅为 0.295；在规划效率（Parallelism & Efficiency）上，gpt-5 也仅有 0.339。这些维度直接反映模型依据模糊指令推断所需工具、协调跨工具依赖链以及高效并行执行的能力，是当前代理的核心瓶颈。

### 多服务器协调加剧执行冗余与效率分化

按服务器数量拆分后，性能格局保持稳定：单服务器场景下 gpt-5 综合 0.749，llama-3-1-8b-instruct 为 0.438；多服务器场景下分别为 0.750 和 0.415（Table 4, Table 5）。多服务器任务对小型模型的退化更为明显，因为其需要同步理解不同服务器的工具生态并消除跨域冲突。

![[assets/figures/papers/iclr26_0014_fe8mzHwMxN_MCP-Bench_Benchmarking_Tool-Using_LLM_Agents_wit/figures/007_Table_4.jpg]]
*Table 4: Detailed results with different models on single-server setting*

效率数据进一步揭示了模型间的规划能力差距。Table 6 显示，o3 从单服务器到多服务器场景，平均交互轮次由 4.5 增至 8.0，工具调用数由 23.0 增至 33.7，说明跨服务器依赖显著增加了执行复杂度。干扰服务器的引入放大了这一效应：llama-3-1-8b-instruct 在每任务附带 10 个干扰服务器的条件下平均消耗 17.3 轮、超过 155 次工具调用，而高效的 gpt-4o、o3、qwen3 等模型仅需 6–8 轮、30–40 次调用。这表明从模糊指令和大量噪声工具中精准锁定有效工具并保持简洁执行路径，是区分弱模型与强模型的关键能力。

### 规划失败集中在依赖推理、冗余与任务分解

对失败轨迹的人工分析（Section A.10）揭示了三类主要规划错误：排序与依赖错误占 25.8%、冗余规划占 22.6%、错误的任务分解占 21.5%。这些错误直接对应长程任务中排序工具调用、重用已有结果以及将多目标指令拆解为正确子任务的能力缺陷。该发现与裁判评分中的“依赖意识”和“错误累积”低分相呼应，表明即使单一工具调用正确，错误的整体流程设计仍会导致任务失败。

### 裁判框架的消融：提示洗牌与评分细则降低偏差

为确保 LLM 裁判的可靠性，MCP-Bench 引入提示洗牌和多次评分平均化。消融实验（Table 12）显示，该策略将各任务在不同模型间评分的平均变异系数从 16.8% 降至 15.1%，并使与人类评分的一致性从 1.24/2 提升至 1.43/2。在此基础上，纳入更细粒度的客观评分细则（每个轴细分子维度，1–10 评分）进一步将一致性从 1.09 提升至 1.43（Section A.9）。在裁判模型选择上，o4-mini 以 $4.40/1M token 的成本实现 1.43 的人类一致性，接近 claude-sonnet-4 的 1.48，是目前性价比最优的评估后端。

![[assets/figures/papers/iclr26_0014_fe8mzHwMxN_MCP-Bench_Benchmarking_Tool-Using_LLM_Agents_wit/figures/028_Table_12.jpg]]
*Table 12: Ablation study on prompt shuffling and score averaging*

综合而言，MCP-Bench 的各项分析结果表明，基本的工具调用执行已不是前沿模型的短板；真正的挑战在于长程多步规划、跨域依赖推理以及从高噪声工具集中获取执行线索。这些能力在现有基准中未被充分衡量，正是 MCP-Bench 通过模糊指令、跨服务器依赖和干扰工具设计所暴露出的核心缺口。



## 定位与知识库关联

### 与现有基准的关系
MCP‑Bench 在工具使用能力评估的演进中定位明确。早期的 **ToolBench** 构建了大规模 API 基准，但因依赖独立异构 API 而缺乏跨工具依赖链；**BFCL v3** 侧重于多领域函数调用，却依赖人工拼凑任务且缺少模糊指令和复杂多目标支持；**τ‑Bench** 虽尝试解决依赖链，但领域和工具数量有限；**MCP‑RADER** 与 **MCPEval** 作为较早的 MCP 基准，同样未系统测试模糊指令和复杂跨域协调。  
相较之下，MCP‑Bench 在三个关键维度上实现升维：
1. **工具生态与协议**：从独立 API 或小型固定集合转向基于 **MCP 的统一服务协议**，连接 28 个生产级服务器和 250 个互补工具，原生支持跨服务器依赖（Table 1）。
2. **任务指令性质**：从显式工具名称和步骤转向 **模糊的、目标导向的自然语言请求**，刻意隐藏工具和步骤，要求代理自主推断执行策略（Table 2）。
3. **评估视角**：从单一的成败或相似度指标转向 **规则检查与多轴 LLM‑as‑a‑Judge 协同**，同时覆盖工具名有效性、模式合规、执行成功率等底层鲁棒性，以及任务完成度、工具使用合理性和规划效率等高层战略能力（Table 3）。  
通过上述变动，MCP‑Bench 成功将评估焦点从基础 API 调用转移到复杂推理、信息接地和跨域规划，揭示出前沿模型在基本工具调用趋于饱和的背景下，长程多步规划与依赖感知仍显著不足的瓶颈 —— 例如，GPT‑5 的“并行性与效率”得分仅 0.339（Table 3）。

### 适用边界
MCP‑Bench 的评估范式适用于以下场景：
- 代理通过 MCP 协议接入 **生产级工具生态**，需处理既有单服务器任务又有多服务器跨域依赖的复杂工作流。
- 用户以 **自然模糊的方式表述多目标需求**，要求代理自主完成信息接地、任务分解和顺序规划。
- 期望通过 **规则+LLM 裁判双重检验** 区分模型的整体策略能力，尤其适合对比不同规模模型在高层决策上的差距（如信息接地：GPT‑5 达 0.828，而 llama‑3‑1‑8b‑instruct 仅 0.295，Table 3）。
- 允许在 **生态复杂性可控** 的前提下暴露模型在干扰环境下的效率差异：例如，多服务器设置使 o3 的平均交互轮次从 4.5 增至 8.0，工具调用也从 23.0 升至 33.7（Table 6）；小型模型（如 llama‑3‑1‑8b）在干扰服务器存在时消耗更高轮次和调用资源。

然而，该基准**不适用于**需动态用户交互或对话协商的场景 —— 当前仅支持一次性用户输入，无法评估代理在多轮协商、偏好学习或用户反馈适应中的表现。此外，任务合成管道依赖 LLM（o4‑mini），虽经自动质量过滤，仍可能引入模板化偏差，使得任务分布偏向某种结构模式。评估本身以 LLM 裁判为核心，尽管通过提示洗牌和评分平均提升了鲁棒性（变异系数从 16.8% 降至 15.1%，人类一致性从 1.24 升至 1.43，Table 12），但对于极端复杂任务的评分可靠性仍存在上限。

### 局限与开放问题
当前 MCP‑Bench 的主要局限及由此衍生的开放问题包括：
- **基础设施依赖**：基准依赖外部的在线 MCP 服务器和真实 API（如 Google Maps、Reddit），尽管冻结了服务器版本与 API 快照，其长期可重复性仍受制于第三方服务的稳定性。如何在生态复杂性与评估可控性之间取得平衡，是长期维护的核心挑战。
- **评估维度局限**：评估集中于任务完成度和规划效率，对代理行为的安全性、价值对齐等方面的考查不足。未来需扩展更全面的安全与对齐指标。
- **规划脆弱性**：人工失败分析显示，排序/依赖错误（25.8%）、冗余规划（22.6%）和错误任务分解（21.5%）是三大主要规划失败模式（Section A.10）。当前模型在高度模糊且含大量干扰工具的指令下，如何实现鲁棒的多步依赖执行仍是开放难题。
- **裁判可靠性**：尽管已通过消融优化，LLM 裁判的主观偏差问题尚未根本解决。能否通过对抗性测试或增加更多客观执行信号来进一步提升评估可信度，是值得探索的方向。
- **场景扩展**：当 MCP 生态从当前财经、旅行、学术等领域扩展到 IoT 设备控制、企业系统等新场景时，可能会涌现出新的跨域协调挑战。同时，多代理协作场景下的任务分配、信息传递和共识达成等能力也尚未被纳入评估视野，这构成未来工具使用基准演进的重要方向。
