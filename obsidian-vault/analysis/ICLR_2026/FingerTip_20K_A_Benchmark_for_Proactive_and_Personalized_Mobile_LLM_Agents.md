## 概述

移动设备上的大语言模型（LLM）智能体正逐渐成为人机交互的核心载体，然而现有智能体普遍仅能**被动执行用户的明确指令**，无法主动利用用户上下文与历史数据推测潜在意图并提供建议，同时也忽略了不同用户的个性化操作偏好。这一瓶颈的根源在于：当前移动 GUI 控制基准缺失丰富的用户相关信息，使得主动服务与个性化执行能力的评估和开发无从开展。

针对上述问题，本文提出 **FingerTip 20K** 基准，核心洞察在于：通过在用户真实日常手机使用中持续采集包含用户画像（U）、时间（T）、场景（S）、历史意图（I_history）及历史动作（A_history）等多维上下文数据，构建面向主动意图建议与个性化动作执行的双轨评测体系，并利用这些数据微调小型多模态模型，可有效驱动智能体理解用户意图偏好、对齐个性化操作风格。

该基准包含两条全新轨道：
- **主动任务建议**：智能体需根据用户画像、时间、场景、历史意图及当前截屏，主动预测用户可能的意图，形式化为 $I = f(U, T, S, I_{\mathrm{history}}, O)$。
- **个性化任务执行**：智能体需结合用户画像、真实意图、历史动作序列及当前界面状态，以符合用户偏好的方式执行任务，形式化为 $A_{t+1}, O_{t+1}, AT_{t+1} = f(U, I_{\mathrm{true}}, A_{\mathrm{history}}, A_{\mathrm{agent}}, O_t, AT_t)$。

数据采集历时一个多月，来自 95 名用户的日常手机使用，共收集 21,437 个 episode，覆盖 506 款应用。该基准与现有移动 GUI 控制数据集的关键区别在于：首次引入了任务来源为真实用户意图、用户画像与场景上下文、以及历史意图/动作数据（见 Table 1）。

**核心实验结果**：
- 最佳通用模型 **Qwen-QVQ-Max** 在主动任务建议上的成功率仅为 12.8%，远低于人类标注者的 30.3%，揭示当前智能体在主动意图预测方面存在巨大差距（见 Table 3）。
- 使用 FingerTip 20K 全部训练数据微调 **Qwen-2.5-VL-7B** 后，主动任务建议成功率从 3.1% 跃升至 26.0%（+22.9），个性化执行相似度 Sim2 从 0.95 提升至 1.42（+0.47），证明所采集的用户上下文数据对提升两类能力高度有效（见 Table 5）。
- 消融实验表明，在主动任务建议中去除时间上下文导致性能衰减最为显著，确认时间是调控用户意图模式的关键因果要素（见 Table 11）。
- 用户间动作序列的 Levenshtein 相似度分析显示，不同类型用户的动作相似度显著低于同一用户或同类型用户，从数据层面验证了个性化操作偏好的客观存在（见 Figure 5）。

综上，FingerTip 20K 为移动 LLM 智能体从“被动执行”迈向“主动服务与个性化适配”提供了首个系统性的评测基准与数据基础。

## 背景与动机

移动设备已成为人们日常生活的核心交互终端，用户频繁通过手机完成信息获取、社交互动、内容消费与生活服务等各类任务。近年来，基于大语言模型（LLM）的图形用户界面（GUI）智能体取得了显著进展，能够根据用户指令自动操作手机应用，展现出替代人工执行繁琐操作的潜力。然而，现有移动 LLM 智能体普遍存在两个根本性局限。

**被动响应而非主动服务。** 当前智能体仅能在接收到明确指令后被动执行任务，无法像一位贴心的个人助理那样，主动感知用户所处的时间、场景与历史行为模式，推测其潜在意图并提供前瞻性建议。例如，当用户每天早晨通勤时习惯打开音乐应用播放特定歌单，智能体理应能够捕捉这一规律，在合适时机主动询问是否需要执行该操作，而非等待用户手动触发。

**忽略个性化操作偏好。** 不同用户即使执行相同任务，其操作路径、应用选择与交互习惯也往往存在显著差异。然而，现有智能体通常以统一的方式执行任务，未能依据用户的历史操作数据来对齐其个性化风格，导致服务体验缺乏“量身定制”的贴合感。

上述缺陷的根源在于，现有的移动 GUI 控制数据集与基准（如 AITW、MoTIF、AutoDroid 等）在设计上存在关键信息缺失：它们不提供用户画像、操作时间、地点场景、历史意图与历史动作序列等多维上下文信息。这使得基于此类数据训练或评估的智能体，天然不具备主动预测与个性化执行的能力，相关研究也因此缺乏有效的衡量标尺。

为填补这一空白，本文提出 **FingerTip 20K** 基准，首次将**主动任务建议**与**个性化任务执行**纳入移动 LLM 智能体的评估体系。该基准的核心动机在于：通过系统性地采集和提供用户日常手机使用中的丰富上下文数据，驱动智能体从“被动执行者”向“主动、贴心的个人助理”演进。

## 核心创新

FingerTip 20K 的核心创新在于将移动 LLM 智能体的能力边界从“被动执行明确指令”推至“主动理解用户意图并提供个性化服务”。这一转变通过两个相互关联的任务轨道实现，并在数据构建与任务设计上做出了四项关键改变。

### 1. 从单轨执行到“主动建议 + 个性化执行”双轨

现有基准（如 **AutoDroid** (Wen et al., 2024)、**AppAgent** (Zhang et al., 2025)）仅评估智能体在给定明确指令下的任务执行能力。FingerTip 20K 首次引入双轨评估：

- **主动任务建议**：智能体需根据用户当前的部分截屏与历史上下文，主动预测用户可能想要执行的任务意图。
- **个性化任务执行**：智能体在执行已知意图时，需模仿用户特有的操作风格与路径偏好。

这一设计使基准能够同时衡量智能体的“预判能力”与“贴合度”，而非仅仅评估其能否完成任务。

### 2. 注入多维用户上下文，构建“可操控的因果开关”

现有数据集中完全缺失用户相关信息。FingerTip 20K 在输入中系统性地引入了四类上下文要素：

| 上下文要素 | 符号 | 作用 |
|---|---|---|
| 用户画像 | $U$ | 年龄、性别、职业、偏好等 |
| 时间 | $T$ | 具体时间戳 |
| 场景 | $S$ | 用户所处地点类别 |
| 历史意图与动作 | $I_{\text{history}}$, $A_{\text{history}}$ | 用户过去的意图记录与操作序列 |

这些要素构成了控制智能体行为的关键“因果开关”。消融实验证实，**去除时间上下文会导致主动建议成功率从 7.2% 骤降至 4.1%，降幅最大**（Table 11），表明时间是预测用户意图模式的最关键因素。用户画像与场景的移除同样造成显著性能衰减。这一发现为后续研究提供了明确的优化方向：要提升主动预测能力，必须优先建模时间维度的用户行为规律。

### 3. 从人工定义任务到真实用户意图驱动

传统基准的任务通常由作者预定义或由 LLM 生成，脱离真实使用场景。FingerTip 20K 的任务来源发生了根本性改变：95 名用户在一个月的日常手机使用中，通过 FingerTip APP 实时记录自己的真实意图并演示操作过程。这产生了 21,437 个 episode，覆盖 506 个应用，意图类别涵盖社交、娱乐、购物、出行等真实场景。

这一改变的意义在于：智能体面对的不再是精心设计的“实验室任务”，而是用户日常生活中自然涌现的、具有高度情境依赖性的真实需求。这使得基准评估结果更能反映智能体在实际部署中的表现。

### 4. 历史数据从“无”到“有”，驱动个性化对齐

现有基准不提供任何用户历史行为数据。FingerTip 20K 为每个用户保留了完整的历史意图序列与历史动作序列，使智能体有机会学习用户的个性化模式。

个性化动作分析（Figure 5）为这一设计提供了实证基础：**同一用户或同类型用户在执行相似任务时的动作序列相似度显著高于不同类型用户**，证实用户间确实存在可度量的操作偏好差异。基于此，基准定义了 $Sim_2 = S_I / S_{II}$ 作为个性化度量——$S_I$ 是智能体动作序列与当前用户历史数据的 Levenshtein 相似度，$S_{II}$ 是与不同类型用户数据的相似度。比值越大，说明智能体越贴近目标用户的个性化风格。

### 5. 微调验证：上下文数据的有效性

使用 FingerTip 20K 全部训练数据（16,000 episodes）微调 Qwen-2.5-VL-7B 后，性能出现跳跃式提升（Table 5）：

- 主动任务建议成功率从 **3.1% → 26.0%**（+22.9 个百分点）
- 个性化执行相似度 $Sim_2$ 从 **0.95 → 1.42**（+0.47）

这一结果表明，FingerTip 20K 所采集的用户上下文数据对提升主动预测与个性化执行两类能力高度有效，验证了基准设计的合理性。但需注意，微调模型在个性化任务执行的成功率（15.5%）仍远低于专用 GUI 模型 UI-TARS-1.5-7B（38.5%），说明通用视觉语言模型在精确 GUI 定位上的短板尚未通过数据微调完全弥补。

### 局限性提示

上述创新在当前阶段存在明显边界：所有模型的主动建议成功率仍远低于人类水平（最佳模型 12.8% vs 人类 30.3%），且 $Sim_2$ 指标上所有模型均接近 1，表明现有模型尚未真正通过上下文示例习得用户的个性化动作风格。这些缺口指向了下一阶段的核心挑战——如何设计更有效的融合机制与训练策略，使智能体真正“理解”而非“模仿”用户行为。

FingerTip 20K 基准围绕两个核心轨道构建：**主动任务建议**与**个性化任务执行**。其整体框架由数据采集、任务形式化、模型评估三条主线交织而成，目标是从用户日常手机使用中捕获多维上下文，驱动智能体从“被动执行”转向“主动预测与个性化适配”。

### 任务形式化

两个轨道在数学上被明确定义为条件函数，明确了智能体的输入要素与输出目标。

**主动任务建议**的形式化为：

$$I = f ( U , T , S , I_{\mathrm{history}} , O )$$

其中 $U$ 为用户画像，$T$ 为时间，$S$ 为场景（如地点类别），$I_{\mathrm{history}}$ 为用户历史意图，$O$ 为当前屏幕截图序列。智能体需融合这些多源信息，预测用户当前最可能的意图 $I$。这一设定将意图预测从单一的屏幕理解，扩展为对用户行为模式的时序建模。

**个性化任务执行**的形式化为：

$$A_{t+1}, O_{t+1}, AT_{t+1} = f ( U , I_{\mathrm{true}} , A_{\mathrm{history}} , A_{\mathrm{agent}} , O_t , AT_t )$$

在已知真实意图 $I_{\mathrm{true}}$ 的前提下，智能体每步需根据用户画像 $U$、该用户的历史动作序列 $A_{\mathrm{history}}$、智能体自身已执行的动作 $A_{\mathrm{agent}}$、当前屏幕截图 $O_t$ 及辅助功能树 $AT_t$，输出下一步动作 $A_{t+1}$。关键在于 $A_{\mathrm{history}}$ 的引入——它编码了用户的个性化操作偏好，要求智能体不仅完成任务，还要以“该用户惯用的方式”完成任务。

### 数据采集流水线

数据采集依赖 **FingerTip APP** 在用户真实日常使用中运行，流水线如 Figure 3 所示，包含以下关键模块：

- **意图记录**：当用户产生真实使用手机的意图时，打开 FingerTip APP，用一句话记录当前意图，并选择所在场景类别。这保证了任务来源于真实需求，而非人工预定义。
- **动作演示**：用户随后执行该意图对应的操作，APP 自动采集屏幕截图序列、对应的辅助功能树 XML 文件序列，以及用户的操作动作序列（点击、滑动、输入等）。
- **云端上传**：意图文本（含时间戳和场景标签）与演示数据自动上传至云端服务器，形成完整的 episode。
- **辅助功能树提取**：从 XML 元数据中提取所有可交互 UI 元素的坐标与属性，为模型提供精确的界面结构信息。

这一流水线在一个月内从 95 名用户处采集了 21,437 个 episode，覆盖 506 个应用，构成了当前唯一同时包含用户画像、时间、场景、历史意图与历史动作的移动智能体数据集（Table 1 对比）。

### 评估流水线

评估分为两条独立轨道，各自采用不同的环境与指标：

- **主动任务建议**：以离线方式运行，向模型提供统一设计的 prompt（包含 $U$、$T$、$S$、$I_{\mathrm{history}}$、$O$），模型输出预测意图。评估指标包括综合文本相似度 $Sim_1 = (S_1 + S_2) / 2$（结合余弦相似度与 Levenshtein 相似度）以及基于 DeepSeek-V3 二元判定的成功率 SR1。
- **个性化任务执行**：在真实物理手机上通过 ADB 连接进行在线评估。通用模型使用统一 prompt 引导输出动作（动作空间定义见 Table 2），专用 GUI 模型则使用其原生接口。评估指标包括人工核验的任务成功率 SR2、个性化动作序列相似度 $Sim_2 = S_I / S_{II}$（当前用户动作相似度与异类用户动作相似度之比），以及步骤效率比。

### 模块间关系

数据采集流水线为任务形式化中的 $U$、$I_{\mathrm{history}}$、$A_{\mathrm{history}}$ 等关键变量提供了真实来源；任务形式化则直接决定了评估 prompt 的输入结构。微调实验进一步闭合了循环：使用采集数据对 Qwen-2.5-VL-7B 进行 LoRA 微调，验证了从数据到能力提升的因果链路——全量数据微调使主动建议 SR1 从 3.1% 跃升至 26.0%，个性化执行 Sim2 从 0.95 提升至 1.42（Table 5）。

## 核心模块与公式推导

### 双轨任务设定

FingerTip 20K 基准围绕两个核心任务轨道构建，分别对应智能体的主动感知能力与个性化执行能力。两个轨道共享同一套用户上下文数据，但在输入输出形式与评估逻辑上相互独立。

**主动任务建议（Proactive Task Suggestion）** 要求智能体在用户尚未明确发出指令时，根据当前环境状态与历史行为模式，推测用户此刻可能想要执行的任务。其形式化定义为：

$$I = f ( U , T , S , I_{\mathrm{history}} , O )$$

其中各变量含义如下：
- $U$：用户画像，包含年龄、性别、职业、兴趣标签等静态属性；
- $T$：当前时间戳，用于捕捉用户行为的周期性模式；
- $S$：场景类别，如“家中”“办公室”“通勤途中”等；
- $I_{\mathrm{history}}$：用户近期历史意图序列，提供行为上下文；
- $O$：当前手机截屏，作为视觉环境感知输入；
- $I$：模型输出的预测意图，以自然语言描述。

该公式的核心设计在于将时间、场景、历史意图三类上下文显式纳入输入，使智能体能够建模“某用户在特定时空条件下倾向于做什么”的因果关联。消融实验（Table 11）证实，移除时间上下文 $T$ 会导致成功率出现最大幅度的衰减，说明时间信息是驱动意图预测的关键因果变量。

**个性化任务执行（Personalized Task Execution）** 则关注智能体在已知用户真实意图后，如何以符合该用户操作习惯的方式完成整个任务流程。其逐步决策过程定义为：

$$A_{t+1}, O_{t+1}, AT_{t+1} = f ( U , I_{\mathrm{true}} , A_{\mathrm{history}} , A_{\mathrm{agent}} , O_t , AT_t )$$

各变量含义：
- $U$：用户画像，同上；
- $I_{\mathrm{true}}$：用户真实的当前意图；
- $A_{\mathrm{history}}$：该用户历史上执行类似任务时的完整动作序列，作为个性化风格参考；
- $A_{\mathrm{agent}}$：智能体在当前 episode 中已执行的动作序列，用于避免重复与保持连贯；
- $O_t$：当前时刻的手机截屏；
- $AT_t$：当前界面的辅助功能树（Accessibility Tree），提供可交互 UI 元素的精确坐标与语义标签；
- $A_{t+1}$：智能体输出的下一步动作，包含动作类型（点击、滑动、输入等）与目标元素坐标；
- $O_{t+1}, AT_{t+1}$：执行动作后的新观察与新辅助功能树。

该公式的因果机制在于：通过将 $A_{\mathrm{history}}$ 作为条件输入，智能体可以学习到“这类用户通常如何完成这类任务”的模式，从而在动作选择上对齐用户的个性化偏好。Figure 5 的分析表明，不同用户类型之间的动作序列 Levenshtein 相似度显著低于同一用户或同类型用户内部，为这一机制提供了实证基础。

### 数据采集流水线

上述公式所需的多维上下文数据通过 Figure 3 所示的流水线采集，核心模块包括：

1. **FingerTip APP**：部署在用户日常使用的物理手机上。当用户产生真实使用意图时，打开该 APP 用一句话记录意图内容，并选择当前所在场景类别；随后正常执行操作，APP 在后台自动采集截屏序列、辅助功能树 XML 文件及触摸动作序列。
2. **Cloud Server**：自动接收并存储用户上传的意图文本（含时间戳与场景标签）及操作演示数据。
3. **Accessibility Tree Extractor**：从系统 XML 元数据中解析所有可交互 UI 元素的边界框坐标与语义信息，为动作空间的精确坐标输出提供基础。
4. **Data Split Generator**：按用户维度进行时间顺序随机采样，构建训练/验证/测试集，确保 user-unseen 等 out-of-domain 测试的有效性。

### 评估指标公式

两个轨道采用不同的评估指标，以分别衡量语义理解能力与个性化对齐程度。

**主动任务建议的文本相似度** $Sim_1$ 定义为：

$$Sim_1 = (S_1 + S_2) / 2$$

其中 $S_1$ 为模型预测意图与用户真实意图之间的余弦相似度，$S_2$ 为两者之间的 Levenshtein 相似度。该指标综合了语义层面的向量相似与字面层面的编辑距离，用于评估预测意图与真实意图的文本一致性。成功率 $SR_1$ 则由 DeepSeek-V3 对预测意图是否“成功满足用户需求”进行二值判断得出。

**个性化任务执行的相似度比值** $Sim_2$ 定义为：

$$Sim_2 = S_I / S_{II}$$

其中 $S_I$ 为智能体完整动作序列与当前用户历史数据的动作序列之间的 Levenshtein 相似度，$S_{II}$ 为智能体动作序列与不同类型用户数据的动作序列之间的相似度。该比值的核心逻辑是：若智能体真正习得了当前用户的个性化风格，其动作序列应更贴近当前用户而非其他类型用户，因此 $Sim_2$ 越大表示个性化程度越高。成功率 $SR_2$ 通过人工检查任务是否在真实手机上正确完成来判定。

值得注意的是，所有基线模型在 $Sim_2$ 上均接近 1.0，表明现有模型即使看到历史动作示例，也未能有效提取并模仿用户的个性化操作风格——这是当前方法的一个显著瓶颈，也是该基准暴露出的核心开放问题。

### 消融实验

**输入截屏数量的影响**。Figure 6(a) 展示了主动任务建议中不同输入截屏数量对 SR₁ 的影响。随着输入截屏数量增加，所有模型的成功率均呈上升趋势，表明更完整的屏幕上下文有助于智能体更准确地推断用户意图。反之，减少截屏数量使任务更具挑战性，性能明显下降（Table 10）。

**动作步骤长度的影响**。Figure 6(b) 显示，随着用户参考动作序列的长度增加，个性化任务执行的成功率 SR₂ 普遍下降。长序列任务涉及更多决策点，对模型的规划和 GUI 定位能力提出了更高要求。

**上下文信息的关键性**。Table 11 的消融实验揭示了不同上下文要素对主动任务建议的相对重要性。在完整上下文（用户画像 + 时间 + 场景）设置下，SR₁ 为 7.2%。逐一移除各要素后：

- **移除时间**：SR₁ 骤降至 4.1%，降幅最大（-3.1），证明时间戳是预测用户意图模式的最关键因素。
- **移除场景**：SR₁ 降至 5.1%（-2.1）。
- **移除用户画像**：SR₁ 降至 5.7%（-1.5）。

这一排序表明，用户的行为意图在时间维度上具有最强的规律性，而场景和用户画像信息则提供了补充性的约束。

**输出概率分布的效果**。Table 12 对比了直接输出单一意图与输出意图概率分布两种策略。输出概率分布使 SR₁ 从 7.2% 提升至 11.1%，Sim₁ 从 0.35 提升至 0.42。这表明允许模型表达不确定性、覆盖多个候选意图，有助于提高主动建议的命中率。

**双轨道间的交叉影响**。Table 9 揭示了单独微调与联合微调之间的权衡。单独针对主动任务建议微调（FT-proactive）使 SR₁ 达到 9.7%，但个性化执行 SR₂ 降至 1.0%；单独调整个性化执行（FT-personalized）使 SR₂ 达到 12.5%，但主动建议性能大幅退化。联合微调（FT-joint）在两个轨道上的表现均非最优。这一现象证实了两个轨道测试的是不同性质的能力，且存在一定程度的负迁移，单一模型难以同时在这两个维度上达到峰值。

*Table 9: Performance of the separately fine-tuned model and the jointly fine-tuned model*

**历史动作序列的验证**。Table 14 显示，当使用相似但非同样的任务作为参考动作序列时，个性化任务执行性能无显著变化，排除了模型通过简单抄袭历史动作达成高 Sim₂ 的可能性。这进一步确认了 Sim₂ 指标衡量的是真正的个性化对齐，而非对历史数据的机械复制。

### 失败模式分析

**通用模型的 GUI 定位缺陷**。通用视觉语言模型在个性化任务执行中失败的首要原因是无法输出精确的动作坐标。即使模型正确理解了任务目标和用户偏好，其生成的点击坐标往往偏离目标 UI 元素，导致任务执行中断或错误。这解释了为何专用 GUI 控制模型（如 UI-TARS-1.5-7B）在 SR₂ 上遥遥领先，而通用模型在 Sim₂ 上同样未能展现个性化能力——它们连基础执行都难以可靠完成。

**多源上下文融合不足**。在主动任务建议中，所有模型的成功率均远低于人类水平（最佳 12.8% vs. 30.3%）。失败案例表明，模型难以有效地将历史意图序列、当前屏幕状态、时间与场景信息有机融合，常常忽略关键上下文线索或产生与用户真实需求无关的建议。

**个性化风格习得困难**。所有模型的 Sim₂ 值均徘徊在 1.0 附近，表明即便提供了用户的历史动作序列作为参考，模型也未能内化用户的个性化操作偏好。当前提示工程和微调策略可能不足以让模型从动作序列中提取并迁移行为风格。

## 方法谱系与知识库定位

### 与现有移动 GUI 智能体基准的关系

FingerTip 20K 在移动 GUI 智能体基准谱系中占据一个此前未被覆盖的位置：它首次将**主动意图预测**与**个性化动作执行**引入基准设计，从而将评估从“能否执行指令”推进到“能否理解用户并提供贴合其偏好的服务”。表 1 的对比清晰展示了这一差异化定位——现有基准（如 AutoDroid (Wen et al., 2024)、AppAgent (Zhang et al., 2025) 等）仅关注给定明确指令下的任务执行，既不提供用户画像、时间戳、场景等上下文信息，也不包含用户历史意图与动作序列。FingerTip 20K 通过双轨设计填补了这一空白：主动任务建议轨要求智能体根据用户上下文与历史数据推测潜在意图，而个性化任务执行轨则要求智能体在已知真实意图的前提下模仿该用户的特定操作风格。

从数据采集范式来看，FingerTip 20K 的独特之处在于**任务来源于用户日常使用中的真实意图**，而非作者预定义或 LLM 生成的合成任务。用户通过 FingerTip APP 在产生真实手机使用需求时即时记录意图并演示操作，这使得数据天然携带了时间、场景、用户画像等多维上下文信息。这种“原位采集”策略与现有基准的“预定义任务 + 众包/自动执行”范式形成根本性差异。

### 与通用视觉语言模型及专用 GUI 控制模型的关系

该基准的实验设计系统性地评估了两类模型的适用边界。**通用视觉语言模型**（GPT-4.1、Qwen-VL-Max、DeepSeek-VL2 (Wu et al., 2024)、Qwen-2.5-VL-7B/72B (Bai et al., 2025)、Qwen-QVQ-Max）在主动任务建议轨上展现出一定的意图理解能力，最佳模型 Qwen-QVQ-Max 的成功率 SR1 达到 12.8%，但**精确 GUI 定位能力的缺失**成为其致命短板——即使能正确分析用户意图，也难以在真实设备上输出可靠的动作坐标来完成任务执行。这一瓶颈在个性化任务执行轨上表现得尤为突出：通用模型在该轨上的成功率远低于专用 GUI 控制模型。

**专用 GUI 控制模型**（Aguvis-7B (Xu et al., 2024b)、CogAgent-9B (Hong et al., 2024)、UI-TARS-1.5-7B (Qin et al., 2025)）在个性化任务执行轨上展现出明显优势，其中 UI-TARS-1.5-7B 以 38.5% 的 SR2 位居榜首。然而，这些模型在 Sim2 指标上均接近 1，表明它们**未能通过上下文示例真正习得用户的个性化动作风格**——它们更像是高效的通用的 GUI 操作器，而非个性化的用户代理。这一发现揭示了一个关键的知识空白：当前专用 GUI 模型的设计目标聚焦于通用 GUI 理解和操作，缺乏对用户个体行为模式建模的机制。

### 微调策略的适用边界与双轨间的张力

使用 FingerTip 20K 数据对 Qwen-2.5-VL-7B 进行 LoRA 微调（rank=4 或 64）的实验揭示了几个重要的适用边界。首先，**数据量的边际收益显著**：使用完整训练集（16,000 episodes）微调的模型在主动任务建议 SR1 上达到 26.0%，相比仅用 1,000 episodes 的 11.8% 提升了超过一倍，表明该任务对训练数据的覆盖度高度敏感。其次，**双轨之间存在负迁移**：单独针对某一轨道微调会导致在另一轨道上的性能下降（Table 9），联合微调也难以同时达到各自的最优水平。这一现象说明主动意图预测与个性化动作执行虽然共享部分上下文理解能力，但在模型内部存在竞争性的表征需求，需要更精细的多任务学习策略来调和。

### 适用边界与局限性

1. **通用模型 GUI 定位瓶颈**：通用视觉语言模型在输出精确动作坐标方面的根本性不足，限制了其在真实手机环境中的端到端可用性。即使微调后 SR2 从 1.5% 提升至 15.5%，仍远低于专用模型的 38.5%。
2. **人类水平差距**：所有模型在主动任务建议上的成功率（最佳 12.8%）远低于人类标注者的 30.3%，暴露出当前模型在融合多源上下文（用户画像、时间、场景、历史意图）进行意图预测方面的深层困难。消融实验证实，时间上下文是最关键的因素——去除时间信息导致性能降幅最大（Table 11）。
3. **个性化习得失效**：所有模型的 Sim2 指标均接近 1，表明现有提示工程和微调策略均未能有效利用历史动作序列来捕捉用户的个性化操作风格。这是一个开放性的方法学挑战。
4. **生态与文化偏差**：由于中国应用在模拟器上的限制，数据偏向中国应用生态，基准结论向其他区域和应用环境的迁移性尚需验证。
5. **用户多样性有限**：数据仅来自 95 名用户，在 user-unseen 测试下微调模型性能出现退化（Table 8），提示用户多样性仍需扩大以增强泛化能力。

### 开放问题与未来方向

1. **个性化动作序列建模**：为何所有现有模型在 Sim2 指标上均接近 1？如何设计更有效的提示模板或训练范式，使模型能够从历史动作序列中真正习得用户的个性化操作风格，而非仅仅执行通用的最优路径？
2. **通用模型的 GUI 定位增强**：如何提高通用视觉语言模型的 GUI 定位精度，使其输出的动作坐标足够可靠？这可能需要结合辅助功能树的结构化信息或引入专门的定位模块。
3. **多源上下文有机融合**：主动任务建议中，如何更有机地融合历史意图、用户画像、场景与实时屏幕信息，使预测接近人类水平？时间上下文被证实是最关键的要素，但其他要素的协同作用机制仍需深入探索。
4. **双轨统一训练范式**：能否开发统一的训练范式，使同一模型同时兼具强大的主动意图预测与个性化执行能力，避免两轨道间的负迁移？这可能需要在架构层面或损失函数设计中显式建模两个子任务的共享与特异性。
5. **长期用户行为建模**：该基准目前基于一个月的采集周期，未来能否扩展至更长期的行为建模（数月至数年），以捕捉更深层的习惯变化和偏好漂移？这将使主动服务从“即时意图预测”演进为“长期需求预判”。
