## 概要

### 问题背景

大语言模型驱动的搜索智能体（LLM-based search agent）通过交错执行推理与检索，在复杂知识任务上展现出强于朴素RAG的生成质量。然而，这种交错范式引入了严重的系统效率瓶颈，阻碍其大规模部署。

**核心瓶颈**来自三个相互关联的因素：

1. **检索精度的非单调效应**：过低或过高的检索召回率均会降低端到端效率——低召回导致智能体发起更多轮检索，高召回则因检索计算量增大而拖慢单次响应。
2. **不合理的调度策略**：现有推理框架（如vLLM）普遍采用先到先服务（FCFS）调度，优先处理短请求会导致长请求的KV缓存被驱逐，造成大量不必要的重计算。实验表明，不当调度导致55.9%的token被重复计算，单请求计算时间增加超过108%。
3. **异步检索引发的停顿与缓存驱逐**：搜索智能体在检索等待期间若错过调度点，其KV缓存可能因GPU显存压力而被清除，进一步放大延迟。当平均检索延迟从0.6s增至4.4s时，端到端延迟被放大超过83倍，而朴素RAG几乎不受影响。

### 核心方法

**SearchAgent-X** 针对上述瓶颈，提出两项协同技术：

- **优先级感知调度（Priority-Aware Scheduling）**：基于检索次数、上下文长度和等待时间三个指标，将请求动态分配到离散优先级等级。同优先级内按等待时间降序排列，优先调度等待最久的长请求，从而显著提升KV缓存复用率。
- **非停顿检索（Non-Stall Retrieval）**：采用高召回近似检索，并通过检索成熟度评估与LLM引擎就绪状态的自适应提前终止策略，避免因检索等待造成的GPU空闲和缓存驱逐。

两项技术协同作用，使KV缓存命中率从0.07飙升至0.65。

### 主要结果

- **生成质量无损**：在六个数据集上，SearchAgent-X的生成准确率（Exact Match均值0.430）与精确检索方法完全一致。
- **离线推理效率**：相较于vLLM精确检索基线，SearchAgent-X实现**1.3–3.4×的吞吐量提升**和**0.2–0.6×的延迟降低**（覆盖MuSiQue、HotpotQA、ReCall等数据集与不同模型规模）。
- **在线推理效率**：在高并发场景下，SearchAgent-X完成至少**1.5×以上的请求量**，同时保持较低的待处理序列比例（约0.2），而基线系统已超过0.6。
- **消融验证**：优先级调度单独降低端到端延迟35.55%；非停顿检索进一步降低6.3%延迟，并将KV缓存命中率推至0.65。

### 方法定位

SearchAgent-X属于**系统级优化方法**，不改变模型权重或搜索智能体的推理逻辑。其技术假设轻量——仅要求token级生成调度和可覆盖的FCFS基础策略——使其可迁移至vLLM、SGLang等主流推理框架。该方法在方法谱系中填补了“搜索智能体专用推理系统”的空白，与通用前缀缓存（Prefix Cache）形成互补：前缀缓存提供KV复用能力，而优先级调度和非停顿检索确保这一能力在交错推理-检索场景下被有效释放。

### 搜索智能体的交错推理模式

大语言模型（LLM）驱动的搜索智能体采用一种“推理–检索–推理”的交错工作模式：模型在生成过程中输出特殊的检索标记，触发对外部知识库的查询，检索结果被拼接回上下文后继续推理（Figure 7）。这种模式使智能体能够在多跳问答、事实验证等复杂任务中动态获取外部知识，但也引入了传统RAG系统所没有的系统效率挑战。

### 现有系统架构的局限

当前主流的LLM推理框架（如vLLM，Kwon et al., 2023）采用**迭代级调度**和**前缀缓存**机制来提升吞吐量。前缀缓存存储注意力机制中先前token的KV对，允许后续生成复用，避免重复计算。然而，这些框架默认采用**先到先服务（FCFS）**调度策略，并未针对搜索智能体的交错检索特性进行优化。实验表明，即使启用了前缀缓存，搜索智能体仍面临严重的效率瓶颈——缓存命中率仅为0.07，超过24%的token重计算开销被节省，但系统整体效率远未达到理想水平。

### 效率瓶颈的双重根因

#### 检索精度的非单调效应

搜索智能体的端到端效率与检索精度之间存在**非单调关系**（Figure 1）。当近似最近邻（ANN）搜索范围过小（如10）时，检索召回率不足，智能体需要发起更多轮检索才能找到所需信息，平均每请求检索次数高达6.5次，吞吐量仅略高于2.1 req/s。随着搜索范围扩大至500，召回率提升，检索次数降至约5.7次，吞吐量升至3.2 req/s以上。然而，过高或过低的召回率均会损害效率：低召回导致无效检索增多，过高召回则使单次检索耗时增加，均无法达到最优吞吐。

#### 检索延迟的放大效应

搜索智能体对检索延迟表现出**极度敏感**的特性（Figure 2a）。当平均检索延迟从0.6秒增至4.4秒时，搜索智能体的端到端延迟被放大超过83倍，而同等条件下朴素RAG的延迟几乎不变。这一放大效应的根因在于KV缓存的低命中率：检索延迟的微小增加即导致缓存命中率急剧下降，进而触发大量重计算。

进一步分析揭示了两个深层机制：

- **不当调度（Figure 2b）**：FCFS策略优先服务短请求，导致长请求在等待期间KV缓存被驱逐。当长请求最终被调度时，必须重新计算被驱逐的前缀token。实验显示，在受影响案例中，55.9%的token被不必要地重计算，单请求计算时间增加超过108%。

- **检索引发的停顿（Figure 2c）**：平均超过25%的序列在完成检索后遭遇调度停顿——检索结果就绪时恰好错过调度点，必须等待下一个调度周期。在此期间，已缓存的KV对面临被其他请求驱逐的风险，进一步降低缓存命中率。

### 本文动机

上述分析表明，搜索智能体的效率瓶颈并非单纯源于计算或检索本身，而是**调度策略、缓存管理与检索机制之间的协同失效**。具体而言：

1. FCFS调度不考虑请求的KV缓存复用潜力，导致长上下文、多次检索的请求频繁遭遇缓存驱逐；
2. 检索引发的停顿使就绪序列无法及时被调度，加剧缓存失效；
3. 现有检索机制缺乏对检索质量饱和的感知，无法在检索充分时提前终止，造成不必要的等待和资源消耗。

因此，本文的核心动机是：**通过协同优化调度策略与检索机制，在保持生成质量不变的前提下，系统性提升搜索智能体的KV缓存利用率和端到端效率**。

## 核心方法与创新机理

SearchAgent-X 的核心创新在于揭示并解耦了 LLM 搜索智能体效率瓶颈的两个关键控制维度——**调度策略**与**检索机制**，并针对性地提出了两个相互协同的 changed slots。

### 瓶颈洞察：效率损失的因果链条

现有系统（以 vLLM 为代表）在交错推理与检索过程中存在双重效率陷阱：

1. **检索精度悖论**：过高或过低的检索召回率均会降低端到端效率（Figure 1）。低召回导致检索次数膨胀，高召回则引入冗余计算开销，二者在 FCFS 调度下均无法有效转化为吞吐量提升。
2. **检索延迟放大效应**：搜索智能体对检索延迟极度敏感——当平均检索延迟从 0.6s 增至 4.4s 时，端到端延迟放大 **83 倍以上**，而朴素 RAG 几乎不受影响（Figure 2a）。根因在于：(a) FCFS 调度优先服务短请求，导致长请求的 KV 缓存被驱逐，造成 **55.9%** 的 token 重计算（Figure 2b）；(b) 异步检索完成后请求错过调度窗口，停顿期间缓存同样面临驱逐风险，超过 **25%** 的序列经历此类停顿（Figure 2c）。

### Changed Slot 1：从 FCFS 到动态优先级调度

**Baseline 值**：FCFS（First-Come-First-Serve），按到达顺序调度，不考虑请求的 KV 缓存复用潜力。

**SearchAgent-X 方案**：基于三项实时指标的层次化动态优先级调度——
- **检索次数** $R_i$：已完成检索越多的请求，其前缀越长，缓存复用价值越高；
- **上下文长度** $C_i$：长上下文请求的缓存驱逐代价更大；
- **等待时间** $W_i^{\mathrm{cur}}$：防止新请求被饿死，保证公平性。

三项指标分别离散化为 $G$ 个优先级等级，阈值计算为：

$$T_{M,k} = \min(M) + \frac{k}{G} \cdot (\max(M) - \min(M)), \quad 0 \leq k < G$$

请求 $i$ 的优先级分配采用“或”逻辑，取至少一个指标超过对应阈值的最高等级：

$$k = \max\{ j \in [0, G-1] \mid R_i > T_{R,j} \lor W_i > T_{W,j} \lor C_i > T_{C,j} \}$$

同优先级内按当前等待时间 $W_i^{\mathrm{cur}} = t_{\mathrm{now}} - t_{\mathrm{arr},i}^{(r_i)}$ 降序排列，优先服务等待最久的序列。

**因果机制**：通过将长上下文、多次检索的请求提前调度，使其 KV 缓存在 GPU 显存中驻留更久，从而在后续检索轮次中直接复用，避免重复 prefill。消融实验证实，该策略将 KV 缓存命中率从 **0.07 飙升至 0.51**，端到端延迟降低 **35.55%**（Figure 6）。

### Changed Slot 2：从阻塞式检索到自适应非停顿检索

**Baseline 值**：精确或普通近似最近邻检索（ANN），检索期间 LLM 推理完全阻塞，检索完成后需等待下一调度窗口。

**SearchAgent-X 方案**：高召回 ANN 图搜索 + 基于**检索成熟度**与 **LLM 引擎就绪状态**的自适应提前终止策略。

检索成熟度通过归一化的候选者质量指标 $RQ_t$ 的指数移动平均（EMA）来判定：

$$\mathrm{RQ}_t = \frac{d_t - d_{\mathrm{best}}}{d_{\mathrm{worst}} - d_{\mathrm{best}}}$$

当 $RQ_t$ 的 EMA 趋近于 0 时，表明新增候选者带来的召回改进已趋于饱和，此时若 LLM 引擎恰好就绪（无其他请求占用），则立即终止检索并返回当前结果，使推理无缝衔接，消除停顿。

**因果机制**：非停顿检索从两个层面协同提升效率——(1) 避免检索完成后的调度等待，减少 KV 缓存在停顿期间的驱逐风险；(2) 通过成熟度评估，在召回率基本无损的前提下缩短有效检索时间。消融显示，该机制将 KV 缓存命中率进一步推高至 **0.65**，额外降低 **6.3%** 的端到端延迟（Figure 6）。尽管仅提前终止约 24% 的检索，但相比普通 HNSW，端到端延迟从 661.85s 降至 620.07s，吞吐量提升约 20%（Table 7）。

### 创新的协同本质

两个 changed slots 并非孤立优化，而是围绕 **KV 缓存命中率** 这一核心因果 knob 形成闭环：优先级调度从“调度侧”确保高价值缓存在显存中驻留，非停顿检索从“执行侧”缩短缓存的“危险窗口期”。单独启用前缀缓存在困难设置下（top-k=5）仅比 vLLM ANN 快 **1.01×**，唯有配合优先级调度和非停顿检索才能充分释放缓存红利（Figure 6 left），验证了二者的强互补性。

### 问题定位：搜索智能体的效率瓶颈

现有基于大语言模型的搜索智能体（Search Agent）在交错执行推理与检索时，面临两个相互耦合的效率瓶颈。其一，检索召回率与端到端效率呈非单调关系——过低或过高的召回率均会损害系统吞吐量（Figure 1）。其二，检索延迟对搜索智能体的影响远大于朴素RAG：当平均检索延迟从0.6秒增至4.4秒时，端到端延迟被放大超过83倍，而RAG几乎不受影响（Figure 2a）。这一现象根源于两个机制：

- **不合理的调度策略**：主流框架（如vLLM）采用先到先服务（FCFS）调度，优先处理短请求会导致长请求的KV缓存被驱逐，造成高达55.9%的令牌被不必要地重计算（Figure 2b）。
- **检索引发的停顿**：请求在完成检索后若错过调度窗口，必须等待下一个调度点，期间KV缓存可能因超时被驱逐，平均超过25%的序列会遭遇此类停顿（Figure 2c）。

### SearchAgent-X 核心设计理念

SearchAgent-X 通过三个协同机制解决上述瓶颈：采用高召回近似检索以保证生成质量，引入优先级感知调度提升KV缓存复用率，设计非停顿检索机制消除检索等待带来的缓存驱逐。三者共同作用，在不牺牲生成质量的前提下，将KV缓存命中率从0.07推至0.65，实现吞吐量的大幅提升与延迟的显著降低。

### 系统架构与数据流

SearchAgent-X 的整体架构如 Figure 3 所示，由四个核心模块串联构成一条闭环处理流水线：

**① 优先级调度器（Priority Scheduler）**
接收并发请求，根据实时采集的三维指标——已完成检索次数 $R_i$、上下文长度 $C_i$ 和累积等待时间 $W_i$——将请求动态分配至 $G$ 个离散优先级等级。同等级内按当前等待时间 $W_i^{\mathrm{cur}} = t_{\mathrm{now}} - t_{\mathrm{arr},i}^{(r_i)}$ 降序排列，优先调度等待最久的序列，防止KV缓存因长时间挂起而被驱逐。

**② 检索器（Retriever）——ANN图搜索**
基于HNSWlib构建的高召回近似最近邻（ANN）索引，支持检索成熟度评估与自适应提前终止。检索过程中实时计算归一化质量指标 $\mathrm{RQ}_t = \frac{d_t - d_{\mathrm{best}}}{d_{\mathrm{worst}} - d_{\mathrm{best}}}$，当新增候选者带来的召回改进趋于饱和时，结合LLM推理引擎的就绪状态，提前终止图搜索，避免不必要的检索等待。

**③ 前缀缓存管理器（Prefix Cache Manager）**
存储并复用已生成序列的KV对。优先级调度器通过优先调度长上下文、高检索次数的请求，使后续相似前缀的请求可直接命中缓存，避免重复计算。非停顿检索进一步减少因检索等待导致的缓存驱逐，将命中率从仅启用前缀缓存时的0.07提升至0.65。

**④ 序列拼接与推理引擎（Sequence Concatenation & LLM Inference）**
监控LLM输出流，检测检索触发标记。当模型发出检索请求时，将检索器返回的文档片段拼接到当前上下文，重新注入LLM继续推理。该模块与优先级调度器和检索器紧密协作，形成“推理→检索→拼接→推理”的交错循环。

### 模块间协作关系

各模块的协同逻辑如下：请求进入系统后，优先级调度器根据其当前状态分配优先级并决定调度顺序；被调度的请求进入推理引擎生成令牌，直至触发检索标记；检索器执行ANN搜索，非停顿机制在检索质量成熟或引擎就绪时提前终止搜索；检索结果经序列拼接后重新注入推理引擎；全程由前缀缓存管理器维护KV缓存，调度策略确保高复用潜力的请求优先获得GPU资源。这一设计将检索延迟对端到端效率的放大效应从83倍压缩至可控范围，实现了搜索智能体系统效率的系统性提升。

### 3.1 系统架构概述

SearchAgent-X 围绕两个核心模块重构了搜索智能体的推理管线：**优先级调度器**与**非停顿检索机制**。系统整体架构如 Figure 3 所示——请求到达后首先进入优先级调度器，由调度器根据实时采集的请求状态（检索次数、上下文长度、等待时间）动态决定调度顺序；推理过程中，LLM 引擎与检索器交错执行，当检测到检索标记时，非停顿检索机制根据检索成熟度与引擎就绪状态自适应提前终止 ANN 搜索，避免不必要的停顿。

### 3.2 优先级调度器

#### 3.2.1 设计动机

现有框架（如 vLLM）普遍采用 FCFS 调度策略。在搜索智能体场景中，FCFS 会优先服务短请求，导致长请求的 KV 缓存被驱逐，引发大量重计算（Figure 2b 显示 55.9% 的 token 被不必要地重新计算）。SearchAgent-X 的优先级调度器通过综合考虑请求的检索进度、上下文规模和等待时间，将调度决策与 KV 缓存复用目标对齐。

#### 3.2.2 三指标离散化

调度器对每个请求 $i$ 采集三个关键指标：

- **$R_i = r_i$**：请求已完成的检索次数，反映推理进度；
- **$C_i$**：当前上下文长度，长上下文请求的 KV 缓存复用收益更大；
- **$W_i$**：请求自到达以来的总等待时间，防止新请求被饿死。

为避免多指标加权求和的繁琐调参，SearchAgent-X 将每个指标 $M \in \{R, W, C\}$ 离散化为 $G$ 个优先级等级。第 $k$ 级的阈值下界由等距划分公式确定：

$$T_{M,k} = \min(M) + \frac{k}{G} \cdot (\max(M) - \min(M)), \quad 0 \leq k < G$$

其中 $\min(M)$ 和 $\max(M)$ 分别为当前活跃请求中指标 $M$ 的最小值与最大值。该公式将指标的值域均匀划分为 $G$ 个区间，$T_{M,k}$ 为进入第 $k$ 级的最低门槛。

#### 3.2.3 优先级分配与排序

请求 $i$ 的最终优先级等级 $k$ 由“或”逻辑确定——只要任一指标超过对应阈值，即可晋升至更高等级：

$$k = \max\{ j \in [0, G-1] \mid R_i > T_{R,j} \lor W_i > T_{W,j} \lor C_i > T_{C,j} \}$$

这意味着请求只需在检索次数、等待时间或上下文长度中有一项表现突出，即可获得高优先级。该设计的直觉是：检索次数多的请求已积累大量 KV 缓存，等待久的请求面临缓存驱逐风险，上下文长的请求复用收益高——三者均值得优先调度。

同一优先级等级内的请求，按**当前等待时间** $W_i^{\mathrm{cur}}$ 降序排列：

$$W_i^{\mathrm{cur}} = t_{\mathrm{now}} - t_{\mathrm{arr},i}^{(r_i)}$$

其中 $t_{\mathrm{arr},i}^{(r_i)}$ 为请求 $i$ 的当前序列 $s_{i,r_i}$ 就绪的时间戳。按等待时间降序排列，确保在同等优先级的请求中，等待最久的请求优先获得服务，从而降低 KV 缓存因长时间排队而被驱逐的风险。

#### 3.2.4 超参数敏感性

消融实验表明，优先级等级数 $G$ 对最终性能不敏感：当 $G \geq 6$ 后，各项指标趋于稳定（Figure 10, Figure 11）。这一特性降低了实际部署中的调参负担。

### 3.3 非停顿检索机制

#### 3.3.1 设计动机

搜索智能体的推理与检索交错执行，检索完成后请求需等待下一次调度点才能继续生成。Figure 2c 显示，平均超过 25% 的序列在检索完成后经历停顿，期间 KV 缓存可能被驱逐。非停顿检索机制通过自适应提前终止 ANN 搜索，使请求在检索质量足够时立即返回结果，减少调度点错失。

#### 3.3.2 检索成熟度评估

非停顿检索的核心是判断 ANN 搜索是否已“成熟”——即继续探索新候选者带来的质量提升已趋于饱和。SearchAgent-X 定义了归一化的检索质量指标 $\mathrm{RQ}_t$：

$$\mathrm{RQ}_t = \frac{d_t - d_{\mathrm{best}}}{d_{\mathrm{worst}} - d_{\mathrm{best}}}$$

其中 $d_t$ 为 ANN 搜索第 $t$ 步新发现候选者与查询的距离，$d_{\mathrm{best}}$ 和 $d_{\mathrm{worst}}$ 分别为当前已探索候选者中的最佳和最差距离。$\mathrm{RQ}_t$ 接近 1 表示新候选者质量接近已发现的最佳候选者，边际改进已趋于零。

系统对 $\mathrm{RQ}_t$ 应用指数移动平均（EMA）平滑，当 EMA 信号降至预设阈值 $\tau$ 以下时，判定检索已成熟，可提前终止。Figure 8 展示了典型的 EMA 信号曲线，垂直线标记成熟点——此时召回率的提升和 EMA 值均已趋近于零。

#### 3.3.3 双重终止条件

非停顿检索的提前终止需同时满足两个条件：

1. **检索成熟**：EMA 平滑后的 $\mathrm{RQ}_t$ 低于阈值 $\tau$，表明继续搜索的边际收益可忽略；
2. **LLM 引擎就绪**：推理引擎当前有空闲计算资源，可立即接收检索结果继续生成。

仅当两个条件同时满足时，检索才提前终止。若引擎繁忙，检索继续执行以充分利用等待时间提升召回率。这一设计在检索质量与调度效率之间取得平衡——Table 7 显示，非停顿检索仅提前终止约 24% 的检索，但端到端延迟从 661.85s 降至 620.07s。

#### 3.3.4 检索质量保障

Figure 9 对比了成熟退出与自然停止的检索轨迹：二者的候选者探索量趋势相近，且成熟退出的召回率始终维持在高水平。这表明提前终止并未损害检索质量，与 Table 1 中 SearchAgent-X 生成精度与精确检索持平的结果一致。

### 3.4 模块协同

优先级调度器与非停顿检索机制存在协同效应。消融实验（Figure 6）揭示了逐层叠加的效果：

- **前缀缓存单独使用**（CachevLLM ANN）：在 top-k=5 的困难设置下，相比 vLLM ANN 仅快 $1.01\times$，KV 缓存命中率仅 0.07——说明 FCFS 调度下缓存红利无法释放；
- **叠加优先级调度**：端到端延迟降低 35.55%，KV 缓存命中率从 0.07 飙升至 0.51——调度策略使长请求的缓存得以保留；
- **叠加非停顿检索**：KV 缓存命中率进一步推高至 0.65，端到端延迟额外降低 6.3%——减少停顿降低了缓存驱逐概率。

三个模块的协同使 SearchAgent-X 在保持生成质量不变的前提下，实现了 1.3–3.4× 的吞吐量提升和 0.2–0.6× 的延迟降低。

## 实验与关键发现

### 效率瓶颈的根因分析

实验首先揭示了一个关键现象：搜索智能体对检索延迟的敏感度远超朴素RAG。当平均检索延迟从0.6s增至4.4s时，搜索智能体的端到端延迟被放大超过83倍，而RAG几乎不变（Figure 2a）。其根因有二：

1. **不合理的调度策略**：FCFS调度优先服务短请求，导致长请求在等待期间KV缓存被驱逐，造成大量重计算。实验显示，受影响请求中55.9%的token被不必要地重计算，单请求计算时间增加超108%（Figure 2b）。
2. **检索引发的停顿**：平均超过25%的序列在完成检索后错过调度点，被迫等待下一轮，期间缓存面临被驱逐的风险（Figure 2c）。

另一项前置发现是检索精度与效率之间的非单调关系（Figure 1）：检索范围过小（如search range=10）时召回不足，平均每请求需6.5次检索，吞吐量仅略高于2.1 req/s；范围增至500时，召回提升使平均检索次数降至5.7次，吞吐量跃升至3.2 req/s以上。这为SearchAgent-X采用高召回近似检索提供了依据。

### 主实验结果

#### 生成质量保持

SearchAgent-X在六个数据集上的平均Exact Match为0.430，与精确检索基线完全一致（Table 1）。两者的平均检索次数（约2.717次）和输出长度（约6822-6826 tokens）也几乎相同（Table 5），证明效率提升不以牺牲生成质量为代价。

#### 离线推理效率

SearchAgent-X在所有top-k设置下均显著优于三个基线系统（vLLM ENN、vLLM ANN、CachevLLM ANN）：

- **MuSiQue数据集**（Table 2）：Search-R1-7B模型下，SearchAgent-X吞吐量达1.84 req/s，是vLLM ENN的1.32倍，延迟仅347.14s（vLLM ENN为1089.37s）。Search-R1-14B模型下，吞吐量提升至1.59-2.36倍。

### 泛化性与鲁棒性

- **搜索引擎泛化**：SearchAgent-X可推广至NSW等不同检索方法，吞吐量提升最高2.7倍，延迟降低最高3.04倍（Table 8）。
- **并发度鲁棒性**：在并发度1-200范围内，SearchAgent-X的KV缓存命中率保持在0.92以上，延迟和吞吐量均显著优于基线；但在极高并发度（>300）下，GPU资源饱和导致缓存命中率和吞吐量下降（Table 6）。
- **优先级等级敏感性**：优先级离散化等级G对性能不敏感，G≥6后各项指标趋于稳定（Figure 10、Figure 11），表明方法无需精细调参即可获得稳定收益。

### 失败模式与局限

1. **极高并发退化**：当并发度超过300时，GPU计算资源成为瓶颈，缓存命中率和吞吐量均出现明显下降，说明调度策略在资源极度饱和时作用有限。
2. **外部搜索API适配**：非停顿检索依赖可控的本地ANN搜索；对于外部搜索API，仅能通过异步并发多个请求来近似，效果可能打折。
3. **优先级等级设定**：虽然G≥6后性能稳定，但最优值仍可能随模型平均检索次数轻微变化，目前缺乏全自动设定方案。
4. **推理引擎依赖**：当前实现基于vLLM，迁移至SGLang等框架需额外适配工作。

## 定位与知识库关联

### 与现有系统的关系

SearchAgent-X 建立在现代 LLM 推理框架的两项基础技术之上：**迭代级调度**（Iteration-Level Scheduling）和**前缀缓存**（Prefix Cache）。vLLM（Kwon et al., 2023）等框架以单 token 生成为粒度进行 GPU 调度决策，并默认采用先到先服务（FCFS）策略；同时通过存储注意力机制的 KV 对来避免重复计算前缀 token。本文的实验基线直接继承自 vLLM 生态：**vLLM ENN** 使用精确最近邻检索，**vLLM ANN** 替换为近似检索，**CachevLLM ANN** 在此基础上启用前缀缓存。

然而，SearchAgent-X 揭示了一个关键断层：**这些通用推理优化在搜索智能体的交错推理-检索范式下严重失效**。FCFS 调度不考虑请求的检索次数和上下文长度差异，优先服务短请求会驱逐长请求的 KV 缓存，导致 55.9% 的 token 被不必要地重计算（Figure 2b）。同时，异步检索完成后的停顿使超过 25% 的序列错过调度窗口，缓存在此期间被其他请求覆盖（Figure 2c）。这些现象说明，**面向普通 LLM 服务的调度和缓存策略无法直接迁移到搜索智能体场景**。

在检索层面，SearchAgent-X 采用基于 HNSWlib 的高召回近似最近邻（ANN）搜索，这与传统 RAG 系统使用精确检索或低召回 ANN 形成对比。论文通过 Figure 1 证实了检索精度与搜索智能体效率之间呈非单调关系：搜索范围过小（如 10）导致过多检索次数，过大则浪费计算，而高召回 ANN 在减少检索次数的同时保持生成质量。

### 适用边界

SearchAgent-X 的设计假设和适用边界可从以下几个维度界定：

1. **推理引擎依赖**：当前实现基于 vLLM 的迭代级调度框架。论文明确指出可迁移至 SGLang 等类似调度框架，但需要额外的适配工作。这意味着对于采用不同调度范式的推理引擎（如静态批处理），核心调度机制无法直接复用。

2. **检索后端限制**：非停顿检索的提前终止策略依赖可控的本地 ANN 搜索（基于 HNSWlib 的图搜索过程可被细粒度监控）。对于外部搜索 API，论文指出仅能通过异步并发多个请求来近似模拟，效果可能打折——因为无法在检索过程中实时评估候选者质量并决定是否提前终止。

3. **并发度上限**：实验覆盖了不同并发度设置，但在极高并发度（>300）下，GPU 资源饱和会导致缓存命中率和吞吐量下降。这表明 SearchAgent-X 的优化红利在资源充裕的中高并发区间最为显著，而在极端过载场景下调度策略的边际收益递减。

4. **任务特性**：优先级调度中三个指标（检索次数 R、上下文长度 C、等待时间 W）的离散化依赖于请求群体的统计分布。当请求高度同质化（如所有请求检索次数相近）时，优先级区分的收益可能减弱。

### 局限与开放问题

**已知局限**：

- 优先级离散化等级 G 的选取虽经实验验证不敏感（G≥6 后性能趋于稳定，见 Figure 10-11），但最优值仍可能随模型平均检索次数轻微变化，目前缺乏全自动设定方案。
- 非停顿检索的成熟度阈值 τ 依赖手动设定，尚未实现根据任务难度或检索类型的自适应调整。
- 当前系统面向单智能体搜索场景设计，未涉及多智能体协作中的全局优先级分配。

**开放问题**：

1. 如何将优先级调度策略扩展到多智能体协作场景，为不同智能体分配合适的全局优先级？
2. 非停顿检索的成熟度阈值 τ 能否根据任务难度或检索类型自适应调整，避免手动设定？
3. 在复杂的搜索 API 环境下，如何设计非停顿检索机制以适应不可控的远程延迟和结果质量？
4. 是否可以将效率目标直接融入搜索智能体的训练过程，使模型学会生成更“缓存友好”的推理路径——例如减少不必要的检索调用或优化推理与检索的交错模式？

> **注意**：上述开放问题均来自论文自身的讨论，目前尚无实验证据支持任何解决方案。第 4 点涉及训练层面的干预，与 SearchAgent-X 纯推理时优化的定位形成互补，但论文未提供任何初步验证。
