## 概述

当前LLM在真实用户交互中的工具使用能力受三大“野性”特征制约：**组合任务（tool orchestration）**、**对话中隐含的用户意图（hidden intention）** 以及**频繁的指令类型转换（instruction transition）**。这些特征在现有基准中被系统性忽略——例如BFCL v2/v3（Patil et al., 2025）不包含隐藏信息或指令切换，ToolBench（Qin et al., 2024）和AnyToolBench（Du et al., 2024）仅支持单轮多步调用——导致模型在WildToolBench上的**会话准确率无一超过15%**，多数模型任务准确率低于60%（Table 2）。这一性能鸿沟的根源在于：LLM在意图推理、策略切换和工具编排规划上存在根本缺陷，而非单纯的任务复杂度问题。

WildToolBench的核心洞察是：真正的挑战不在于人工构造极端复杂的任务，而在于模拟用户自然行为中简单但多变的交互模式。通过在基准中显式引入组合性、语境相关性和指令切换，该工作揭示了现有模型在理解真实对话流和动态调整策略方面的鸿沟。因果分析表明，**推理增强模型**（如Gemini-2.0-Thinking、o1）在组合任务和隐含意图推断上显著优于非推理模型，而专门化的工具调用模型则因缺乏上下文推理能力而表现较差。随着指令转换次数增加，所有模型准确率普遍下降，部分模型降幅达30%（Figure 8），暴露出历史上下文稀释注意力及模型“自条件化”偏见等深层问题。

在方法谱系中，WildToolBench填补了从单轮工具调用评估到真实多轮交互评估的关键空缺。与τ²-bench（Barres et al., 2025）等采用LLM模拟用户的基准不同，WildToolBench从大规模真实用户日志中提取行为模式，通过多智能体系统生成初始轨迹后经人工专家逐条标注，确保数据的真实性。该基准覆盖256个场景、1024个任务，支持顺序、并行及混合工具调用模式的同步评估，其会话准确率指标直接衡量模型在完整对话中连续完成多个关联任务的能力，这是此前所有基准均未触及的评估维度。

## 背景与动机

### 从基准测试到真实交互的鸿沟

大语言模型（LLM）的工具使用能力已成为Agent系统的核心支柱，但现有基准测试与真实用户行为之间存在显著脱节。当前主流基准——如 **BFCL v3**（Patil et al., 2025）、**ToolBench**（Qin et al., 2024）、**AnyToolBench**（Du et al., 2024）——普遍存在三个结构性缺陷：

1. **任务孤立**：将每次工具调用视为独立的单轮请求，忽略了真实对话中跨任务的语义关联。
2. **意图显式**：假设用户会完整、明确地表达所有需求，而真实场景中用户意图常隐含在对话上下文中。
3. **指令静态**：不包含用户在对话中切换任务类型的行为，而真实用户频繁在工具调用、闲聊、澄清之间自然过渡。

这些简化使得现有基准逐渐趋于饱和——例如 **BFCL v2** 上多个模型得分超过75分——但无法反映LLM在真实交互中的实际表现。

### 三大“野性”特征

WildToolBench 的构建动机源于对真实用户日志的分析，识别出三个对用户而言自然、对LLM而言极具挑战的交互特征：

- **组合任务（Tool Orchestration）**：用户请求需要顺序、并行或混合调用多个工具，要求模型具备任务分解与拓扑规划能力。
- **隐含意图（Hidden Intention）**：用户通过指代消解（“上次那个结果再查一次”）、部分信息（省略已知参数）或长距离依赖（依赖超过两轮前的上下文）来表达需求，要求模型具备语境推理能力。
- **指令转换（Instruction Transition）**：用户在对话中频繁切换任务类型（从工具调用到闲聊、从澄清到执行），要求模型具备策略切换与状态追踪能力。

### 核心洞察

该工作的根本判断是：**真正的挑战不在于人工构造极端复杂的单任务，而在于模拟用户自然行为中简单但多变的交互模式**。通过在基准中显式引入组合性、语境相关性和指令切换，WildToolBench 揭示了现有模型在理解真实对话流和动态调整策略方面的根本缺陷——所有主流模型的会话准确率均低于15%，暴露了LLM在意图推理、策略切换和工具编排规划上的系统性不足。

## 核心创新

WildToolBench 的核心创新在于将真实用户交互中三个被现有基准系统性忽略的行为特征——**组合任务（tool orchestration）**、**对话中隐含的用户意图（hidden intention）** 和**频繁的指令类型转换（instruction transition）**——显式地引入评估框架，从而将工具调用评测从“语法正确性”推升至“语义与逻辑推理”层面。这三大特征构成了基准的 changed slots，直接对标并颠覆了以往基准的假设。

### 从孤立任务到语境化多任务：三大 changed slots

与现有基准相比，WildToolBench 在三个关键维度上实现了根本性转变（见 Table 1）：

| 维度 | 先前基准的默认值 | WildToolBench 的值 | 创新含义 |
|------|-----------------|-------------------|---------|
| **Hidden Info in Context%** | 0%（如 BFCL v2、ToolBench 等单轮基准） | **100%** | 每个任务所需的信息分散在对话历史中，模型必须从多轮语境中推理用户意图，而非仅解析当前指令。 |
| **User Instruction Transition%** | 0%（任务间相互独立，无类型切换） | **100%** | 对话中频繁出现工具调用、纯对话、澄清请求之间的指令类型切换，模拟用户自然行为中的非平稳性。 |
| **Tool-use modes supported** | 仅顺序或仅并行（如 BFCL v2 仅并行，ToolBench 仅顺序） | **顺序、并行、混合三种模式同时存在** | 单次对话内可能需要混合编排顺序与并行工具调用，考验模型的拓扑规划能力。 |

这三个维度的组合使得 WildToolBench 成为一个**语境化多任务基准**：模型不仅要在单轮内正确调用工具，更要在多轮对话中持续追踪上下文、推断隐含意图、并在指令类型频繁切换时动态调整策略。

### 为什么这些 changed slots 构成真正的瓶颈

这三个特征并非人为制造的极端困难，而是源自真实用户日志的行为模式提取。从用户视角看，这些交互是连贯、自然的对话；但对 LLM 而言，它们触及了当前能力的根本缺陷：

- **组合任务**要求模型在工具间建立依赖关系图，并规划执行拓扑。当任务混合顺序与并行调用（$g_{multi}^{S+P}$）时，最高任务准确率仅为 25%，最优路径率（OP Rate）峰值仅 42.74%（Table 3），表明模型在工具编排规划上存在严重短板。
- **隐含意图**通过三种策略构建：部分信息（Partial Information）、指代消解（Coreferential Reference）和长距离依赖（Long-Range Dependency，$i-j>2$）。长距离依赖任务中无模型准确率超过 50%，且性能差距高达 17.3（Figure 7），暴露了 LLM 在跨轮次信息整合上的根本缺陷。
- **指令转换**频率增加导致所有模型准确率普遍下降，部分模型降幅达 30%（Figure 8）。原因包括历史上下文稀释注意力，以及模型的“自条件化”偏见——模型倾向于延续先前的行为模式，难以在工具调用与纯对话间灵活切换。

### 推理增强作为关键因果杠杆

分析揭示了一个关键的因果杠杆：**模型是否具备强大的多步推理能力**是影响性能的核心因素。推理增强模型（如 **Gemini-2.0-Thinking**、**o1**）在组合任务和隐含意图推断上显著优于非推理模型；在工具编排中，同系列推理变体的整体任务准确率和最优路径率均高于非推理版本（Table 3）。相反，专门化的工具调用模型（如 xLAM-2-70B、ToolACE-2-8B）虽在单工具任务上表现尚可，但因缺乏上下文推理能力，在需要跨轮次意图推断的场景中性能急剧下降。这一发现表明，**真正的挑战不在于工具调用的语法正确性，而在于理解真实对话流并动态调整策略的语义推理能力**——这正是 WildToolBench 通过三个 changed slots 所精准捕捉的鸿沟。

WildToolBench的构建与评估遵循一条“用户行为建模→数据生成→人工验证→多维评估”的闭环流水线，其核心设计目标是系统性地将真实用户交互中的三个野性特征——组合任务、隐含意图和指令转换——注入基准测试。

### 数据构建流水线

数据构建分为四个串行模块，如Figure 3所示：

1. **场景扩展与用户行为模式提取**：从大规模真实用户日志中提取种子应用场景，总结典型用户行为模式，通过迭代重写与扩展生成256个覆盖多领域的对话场景。

2. **工具集构建与人工验证**：收集超过1600个公开API，针对每个场景筛选合理的工具子集；由LLM智能体领域的专家人工检查并修正不合理的工具组合与参数规格，确保工具调用的真实性与可行性。

3. **多智能体轨迹生成与人工标注**：利用GPT-4o构建多智能体系统，分别模拟用户和助手角色，生成初始对话轨迹；每条工具调用均经过人工检查并标注为ground truth，保证评估参照的准确性。

4. **任务质量强调与统计分析**：在人工检验阶段，重点确保三类关键特征——任务组合性（§3.3）、语境化意图（§3.4）和指令转换（§3.5）——被正确嵌入；最终构建1024个任务，并生成全面的统计信息（§3.6）。

### 评估流水线

评估采用“枚举-匹配-评分”三阶段流水线（Figure 4），专门针对工具编排能力进行细粒度度量：

- **枚举阶段**：对每个组合任务，使用深度优先拓扑排序算法枚举所有合法的工具执行路径（遵守相邻依赖约束）。
- **匹配阶段**：将模型实际生成的工具调用序列与所有合法路径进行匹配。
- **评分阶段**：计算任务准确率（Task Accuracy）、任务完成进度率（Accomplishment Progress Rate, AP Rate）和最优路径率（Optimal Path Rate, OP Rate）。

### 输入输出流

- **输入**：多轮对话上下文，包含用户消息序列 $u_1, u_2, \dots, u_N$ 和助手历史响应 $a_1, a_2, \dots, a_{N-1}$。对话形式化为马尔可夫决策过程（MDP），其中用户消息可能包含部分信息、指代消解引用或远距离依赖（$i-j > 2$）。
- **输出**：模型需在每轮生成正确的工具调用序列 $T^j = \{a_1^T, e_1, a_2^T, e_2, \dots, a_S^T, e_S\}$，其中 $a^T$ 为工具调用指令，$e$ 为环境反馈。任务分为四类：单工具调用（$g_{\mathrm{single}}$）、多步多工具调用（$g_{\mathrm{multi}}$）、纯对话/无工具（$g_{\mathrm{chat}}$）和需澄清说明（$g_{\mathrm{clarify}}$）。
- **评估指标**：任务级准确率（单任务是否正确完成）和会话准确率（对话中全部四个任务均正确完成）。

### 与先前基准的关键差异

Table 1系统对比了WildToolBench与8个先前基准（BFCL v1–v3、ToolBench、AnyToolBench、τ²-bench、τ-bench、T-EVAL、UltraTool）在六个维度上的差异。WildToolBench在三个维度上实现了从0到100%的根本性改变：

- **上下文隐藏信息比例**：从0%提升至100%——所有任务均要求模型从对话历史中推断隐含信息，而非从单条指令中直接获取全部参数。
- **用户指令转换比例**：从0%提升至100%——每个会话均包含用户意图在工具调用、纯对话和澄清请求之间的频繁切换。
- **工具使用模式**：同时支持顺序、并行和混合（顺序+并行）三种模式，而先前基准通常仅支持其中一种。

这些设计使得WildToolBench的会话准确率成为极具挑战性的指标——即便是表现最好的模型Gemini-2.0-Thinking，会话准确率也仅为14.45%（Table 2），远低于其他基准上的表现（如GPT5在BFCL-v2上可达75.0，而在WildToolBench上仅5.9，见Table 5），证实了真实用户行为模式对LLM工具使用能力构成的根本性挑战。

## 核心模块与公式推导

### 3.1 对话与工具调用的形式化

WildToolBench 将用户与 LLM 助手的交互形式化为一个多轮对话序列：

$$D = \{ u _ { 1 } , a _ { 1 } , u _ { 2 } , a _ { 2 } , \dots , u _ { N } , a _ { N } \}$$

其中 $u_i$ 为第 $i$ 轮用户消息，$a_i$ 为对应的助手响应，整个对话包含 $N$ 轮。对于对话中的第 $j$ 个工具使用任务，LLM 需要进行 $S$ 步工具调用，形成如下序列：

$$T ^ { j } = \{ a _ { 1 } ^ { T } , e _ { 1 } , a _ { 2 } ^ { T } , e _ { 2 } , \dots , a _ { S } ^ { T } , e _ { S } \}$$

其中 $a_k^T$ 为第 $k$ 步的工具调用指令，$e_k$ 为环境返回的执行反馈。整个对话被建模为马尔可夫决策过程，每一轮的助手响应 $a_i$ 既可能包含自然语言回复，也可能嵌入工具调用 $a_k^T$。

### 3.2 数据构建流水线的四个核心模块

WildToolBench 的数据构建包含四个关键模块，每个模块均有明确的人工验证介入点：

1. **场景扩展与用户行为模式提取**：从大规模真实用户日志中提取种子应用场景，总结用户行为模式，通过迭代改写和扩展最终生成 256 个场景。这一模块确保基准的对话流源于真实用户交互，而非人工构造的孤立任务。

2. **工具集构建与人工验证**：收集超过 1600 个公开 API，针对每个场景挑选合理的工具子集。由 LLM Agent 领域的专家人工检验并修正不合理的工具组合和参数规格，确保工具集与场景的语义匹配。

3. **多智能体轨迹生成与人工标注**：利用 GPT-4o 构建多智能体系统，分别模拟用户和助手角色，生成初始对话轨迹。随后，每条工具调用均经过人工检查并标注为 ground truth，形成评估的标准答案。

4. **任务质量强调与统计分析**：人工检验阶段重点确保三个核心特征——任务组合性、语境化意图和指令转换——在数据中充分体现。最终构建包含 1024 个任务的基准，并生成详尽的统计信息。

### 3.3 工具编排评估：枚举-匹配-评分流水线

针对组合任务中的工具编排能力，WildToolBench 设计了枚举-匹配-评分三阶段评估方法：

- **枚举阶段**：对给定任务，使用深度优先拓扑排序算法，枚举所有符合相邻依赖关系的合法工具执行路径。
- **匹配阶段**：将模型实际输出的工具调用序列与 ground truth 路径进行匹配。
- **评分阶段**：计算两个细粒度指标——最优路径率和任务完成进度率，而非仅依赖最终任务准确率。

### 3.4 隐含意图的三种构造策略

WildToolBench 通过三种策略在对话中嵌入隐含意图，迫使模型进行多轮上下文推理：

1. **部分信息**：当前用户消息 $u_i$ 仅包含完成任务所需信息的一个子集，其余信息分散在前序消息 $\{u_1, a_1, \dots, u_{i-1}, a_{i-1}\}$ 中。

2. **指代消解**：用户使用代词或省略表达引用前文内容，模型必须正确解析指代关系才能确定工具调用参数。

3. **长距离依赖**：当前用户消息 $u_i$ 所依赖的信息位于超过 2 轮之前的对话中，即满足条件 $i - j > 2$。这类任务在所有隐含意图策略中最为困难。

### 3.5 指令转换与任务类型

WildToolBench 将对话中的任务分为四种类型：

- $g_{\mathrm{single}}$：单工具调用任务
- $g_{\mathrm{multi}}$：多工具多步调用任务
- $g_{\mathrm{chat}}$：纯对话或无工具查询
- $g_{\mathrm{clarify}}$：需要澄清说明的任务

指令转换指对话中任务类型在 $g_{\mathrm{single}}$、$g_{\mathrm{multi}}$、$g_{\mathrm{chat}}$、$g_{\mathrm{clarify}}$ 之间频繁切换的现象。这种切换模拟了真实用户行为的不可预测性，但会导致模型注意力被历史上下文稀释，造成性能显著下降。

### 3.6 评估指标

WildToolBench 的评估基于模型是否生成与 ground truth 一致的工具调用，包含两个层次：

- **任务准确率**：单个任务中工具调用的正确性。
- **会话准确率**：一个对话中全部四个任务均正确完成的比率。由于任一任务失败即导致整个会话失败，该指标远低于任务准确率，是衡量模型在真实多轮交互中稳定性的核心指标。

对于组合任务，额外引入最优路径率和任务完成进度率，以更精细地衡量工具编排的规划质量。

## 实验与分析

### 4.1 总体表现：会话准确率揭示系统性缺陷

WildToolBench 的核心评估指标是**任务准确率**（单轮工具调用是否正确）和**会话准确率**（一个对话中全部四个任务均正确完成）。Table 2 的结果表明，当前主流 LLM 的工具使用能力远未达到实用水平：**没有任何模型的会话准确率超过 15%**，大多数模型的任务准确率也低于 60%。

![[assets/figures/papers/paper_list_l39_https_openreview_net_forum_id_yz7fL5vfpn/figures/008_Table_2.jpg]]
*Table 2: WildToolBench Results*

在参评的 16 个模型中，**Gemini-2.0-Thinking** 取得了最高的整体任务准确率 61.04% 和会话准确率 14.45%，领先于 GPT-4o（54.88%/11.72%）。值得注意的是，**xLAM-2-70B** 在单一工具调用任务（$g_{\mathrm{single}}$）上表现最佳（64.45%），但在需要多步推理的组合任务上显著落后于通用推理模型，这揭示了专用工具调用模型在上下文理解和策略规划上的根本短板。

**跨基准对比**（Table 5）进一步凸显了 WildToolBench 的挑战性：GPT5 在 WildToolBench 上的性能得分仅为 5.9，而在 BFCL-v2 上高达 75.0，差距达 69.1 分。这一鸿沟源于 WildToolBench 系统性地引入了组合性、隐藏意图和指令转换这三项“野生”特征，而现有基准几乎完全忽略了这些真实用户行为的核心维度。

### 4.2 工具编排：混合顺序/并行调用是最大瓶颈

Table 3 将组合任务按工具调用拓扑细分为三类：纯顺序（$g_{\mathrm{multi}}^{S}$）、纯并行（$g_{\mathrm{multi}}^{P}$）和混合顺序/并行（$g_{\mathrm{multi}}^{S+P}$）。结果显示，**混合顺序/并行任务对所有模型构成最严峻挑战**——最高任务准确率仅为 25.00%（Claude-4-Sonnet），而最优路径率（OP Rate）的峰值也仅有 42.74%。

![[assets/figures/papers/paper_list_l39_https_openreview_net_forum_id_yz7fL5vfpn/figures/009_Table_3.jpg]]
*Table 3: WildToolBench tool orchestration evaluation result*

推理增强模型的优势在此维度尤为突出：**Claude-4-Sonnet** 和 **GLM-4.5** 在工具编排上整体领先，且同系列中推理变体（如 Gemini-2.0-Thinking、o1）的任务准确率和最优路径率均显著高于其非推理版本。这证实了多步推理能力是应对复杂工具调用拓扑的关键因素——模型不仅需要选择正确的工具，还必须规划工具间的依赖关系和并行执行时机。

### 4.3 隐藏意图：长距离依赖暴露上下文推理缺陷

WildToolBench 通过三种策略构造需要多轮上下文推理的隐藏意图任务：**部分信息**（Partial Information）、**指代消解**（Coreferential Reference）和**长距离依赖**（Long-Range Dependency，即依赖信息位于超过 2 轮之前的对话中）。

Figure 7 的热力图揭示了两个关键发现：**长距离依赖任务是最具挑战性的子类，没有任何模型准确率超过 50%**，且该子类的模型间性能差距最大（17.3）。这表明 LLM 在处理跨越多个对话轮次的信息检索和整合时存在系统性缺陷——随着对话历史增长，模型难以有效定位和利用分散在早期轮次中的关键信息。

![[assets/figures/papers/paper_list_l39_https_openreview_net_forum_id_yz7fL5vfpn/figures/010_Figure_7.jpg]]
*Figure 7: LLM’s performance under different hidden information strategies*

模型在不同策略上各有所长：o1 在 Partial Info 子类上领先，Claude-4-Sonnet 在指代消解上表现最佳，而 Gemini-2.0-Thinking 在整体隐藏意图任务上保持优势。模型规模与性能呈正相关（Qwen2.5 系列内部趋势明显），但仅靠扩大规模无法解决长距离依赖的根本困难。

### 4.4 指令转换：频繁切换导致准确率大幅下降

WildToolBench 模拟了真实对话中用户在不同任务类型间频繁切换的行为模式。Figure 8 清晰展示了**指令转换次数与任务准确率之间的负相关关系**：随着转换次数从 0 增加到 3，所有模型的准确率均呈下降趋势，部分模型的降幅高达 30%。

![[assets/figures/papers/paper_list_l39_https_openreview_net_forum_id_yz7fL5vfpn/figures/011_Figure_8.jpg]]
*Figure 8: LLM’s performance goes down as the instruction transition goes more frequently*

论文分析指出，这一退化现象的两个可能原因是：（1）历史上下文的累积稀释了模型对当前指令的注意力；（2）LLM 存在“自条件化”偏见——模型倾向于延续先前的任务模式，难以在对话中灵活切换策略。Gemini-2.0-Thinking 虽然起点最高（~0.7），但在多次转换后也降至约 0.45，表明即使是推理增强模型也无法完全免疫指令转换带来的性能衰减。

### 4.5 错误分析：谨慎型与鲁莽型行为风格

Table 4 将错误细分为**动作错误**（Action Errors）和**参数错误**（Parameter Errors）两大类。整体上，参数错误的发生率低于动作错误，说明模型的主要挑战已从句法正确性转向语义和逻辑推理。

错误分布揭示了两种极端的模型行为风格：

- **谨慎型**：以 Gemini-2.0-Thinking 为代表，拒绝率高达 24.56%，倾向于在不确定时拒绝执行而非冒险调用错误工具。
- **鲁莽型**：以 Grok-4 为代表，拒绝率极低，但错误名称/缺失信息错误率高达 24.07%，表现为频繁调用不相关或错误的工具。

这两种风格反映了模型在安全性与可用性之间的不同权衡策略。专用工具调用模型（如 xLAM-2-70B、ToolACE-2-8B）普遍表现出较高的错误名称率和冗余调用率，进一步印证了它们在面对需要上下文推理的野生场景时，倾向于“过度调用”而非“精准判断”。

**总结**：WildToolBench 的实验结果系统性地揭示了当前 LLM 在真实工具使用场景中的三大能力缺口——工具编排规划、跨轮次意图推理和动态策略切换。推理增强模型在各项指标上整体领先，但即使在最优配置下，会话准确率仍低于 15%，表明现有技术在模拟用户自然交互的不可预测性方面存在根本性鸿沟。

## 方法谱系与知识库定位

### 1. 与现有基准的关系

WildToolBench 的核心贡献在于将工具使用评估从“单轮、显式、静态”范式推向“多轮、隐式、动态”范式。现有基准可划分为三个代际，WildToolBench 对每一代际均填补了关键空白：

**第一代：单轮单步/并行基准。** BFCL v2（Patil et al., 2025）和 ToolBench（Qin et al., 2024）分别聚焦并行工具调用和单轮多步工具调用，但二者均假定用户在一次交互中提供完整信息，不存在跨轮次的语境依赖或意图切换。AnyToolBench（Du et al., 2024）延续了类似设定。WildToolBench 将 Hidden Info in Context% 从 0% 提升至 100%，User Instruction Transition% 从 0% 提升至 100%，从根本上改变了任务的信息完整性假设（Table 1）。

**第二代：多轮但无隐式意图的基准。** BFCL v3（Patil et al., 2025）引入了多轮对话，但其任务之间缺乏语义关联，不包含隐藏信息或指令切换。τ-bench（Yao et al., 2024）和 τ²-bench（Barres et al., 2025）采用 LLM 模拟用户进行多轮交互，但模拟行为与真实用户日志中提取的行为模式仍有差距。WildToolBench 从大规模真实用户日志中提取种子场景和用户行为模式，并通过人工验证确保任务的语境化意图和指令转换特征符合真实分布。

**第三代：WildToolBench 的独特定位。** 如 Table 1 所示，WildToolBench 是唯一同时支持 Sequential、Parallel 和 Mixed Tool-Use 三种工具编排模式、且 100% 包含隐藏信息和指令转换的基准。这种设计使其成为评估 LLM 在“野性”真实场景中工具使用能力的唯一选择——跨基准比较（Table 5）显示，同一模型在 WildToolBench 上的性能分数仅为 BFCL-v2 的约 1/12（GPT5: 5.9 vs 75.0），验证了其挑战度的质变。

### 2. 适用边界

**评估范围。** WildToolBench 仅评估工具调用的正确性——即模型是否生成与 ground truth 一致的 tool calls。它不衡量自然语言响应的质量、对话流畅性或用户满意度。这意味着一个在 WildToolBench 上得分高的模型可能在实际交互中给出生硬或不友好的文本响应。

**工具生态。** 工具集来自 1600+ 公开 API，覆盖 8 大类 24 子类，但可能无法完全代表某些垂直领域（如医疗、金融）的真实工具生态。对于需要领域特定工具的评估，WildToolBench 的结论可能不具备直接可迁移性。

**评估格式。** 模型评估仅采用原生 function call 格式，未使用某些模型的微调版或优化版工具调用接口，可能低估了部分专用模型的潜力。

**数据规模。** 256 个场景、1024 个任务的规模限制了统计效力，尤其在分析特定子类别（如 g_multi^{S+P}）时，样本量较小可能导致结论的方差较大。

### 3. 局限与开放问题

**数据扩展与质量平衡。** 当前数据构建依赖 GPT-4o 多智能体生成初始轨迹，再经人工专家逐条检查和标注。这种方式保证了 100% 的数据质量，但成本高昂，难以大规模扩展。如何在保持人工标注质量的同时，通过半自动化或合成方式扩大基准数据规模，是 WildToolBench 社区面临的首要工程挑战。

**评估指标的粒度。** 现有指标（Task Accuracy、Session Accuracy、OP Rate、AP Rate）聚焦于工具调用的正确性和路径最优性，但未考虑效率（如冗余调用次数）与正确性的平衡。更精细的指标——例如惩罚冗余调用但奖励正确路径的加权分数——可能更全面地反映模型的实用价值。

**用户模拟的可复现性。** WildToolBench 的静态对话设计保证了可复现评估，但也意味着它无法捕捉真实用户行为的动态演变。如何构建稳定的用户模拟器，在不牺牲真实性的前提下实现可复现的大规模评估，是一个开放方向。

**行为风格的调控。** 错误分析揭示了模型的两种极端行为风格：Gemini-2.0-Thinking 的“谨慎型”（24.56% 拒绝率）和 Grok-4 的“鲁莽型”（24.07% 错误名称率）。这种风格差异是否可以通过训练干预或推理时策略（如温度调节、拒绝阈值校准）加以调控，尚待研究。

**意图推理的机制改进。** WildToolBench 揭示的核心缺陷——长距离依赖任务中无模型超过 50% 准确率、指令转换导致高达 30% 的准确率下降——指向 LLM 在对话有状态上下文记忆和策略切换上的根本不足。增强对话记忆机制（如结构化上下文摘要）或少样本提示中注入隐式意图推理示例是否能缓解这些问题，是值得探索的方向。
