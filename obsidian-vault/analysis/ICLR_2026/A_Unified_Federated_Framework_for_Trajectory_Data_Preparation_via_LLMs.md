## 概要

在日益严格的数据隐私法规下，大规模轨迹数据按行政区划形成垂直分割，无法直接跨域共享，导致现有的轨迹数据准备方法难以在保护隐私的同时统一处理多种下游任务。针对这一瓶颈，本文提出了 FedTDP，一个基于大语言模型的统一联邦轨迹数据准备框架。框架通过三个核心组件协同运作：轻量级轨迹隐私自编码器（TPA）配合秘密共享实现去中心化的安全聚合，在不引入噪声的前提下提供形式化的隐私保证；轨迹知识增强器（TKE）借助轨迹感知提示工程、离站调优、LoRA 稀疏微调以及双向知识蒸馏，将时空语义注入服务端大语言模型和客户端小语言模型；联邦并行优化（FPO）采用分割学习、交替优化与并行训练策略，显著降低通信量并加速训练。在此基础上，FedTDP 能够在不到原始数据的前提下，以统一的方式执行异常检测、轨迹补全、地图匹配、轨迹‑用户链接等多种轨迹数据准备任务。实验结果表明，FedTDP 在主要任务上的整体性能平均超过单任务轨迹数据准备方法至少 18.38%，超过基于大语言模型的表格数据处理方法至少 32.26%；同时，训练运行时间降低约 11.3‑14.2 倍，通信数据量减少 1.4‑1.8 倍。消融研究进一步确认轨迹知识增强和隐私编码是性能与隐私保护的关键因素。整体而言，FedTDP 提供了一种兼顾隐私、泛化与效率的垂直联邦轨迹数据准备新范式。

轨迹数据是城市计算、智能交通和位置服务的基础燃料，但其天然分布在不同的行政区划或机构之间，形成垂直分割的“数据孤岛”。在日益严格的隐私法规（如GDPR、数据安全法）约束下，原始轨迹无法跨边界自由流动或集中存储，使得各类下游任务——异常检测、轨迹补全、地图匹配、出行方式识别、轨迹简化等——必须在不泄露原始坐标和时序的前提下完成。这种“去中心化、多任务、隐私敏感”的属性，构成了轨迹数据准备（TDP）的核心瓶颈。

现有解决方案存在两个主要缺口。其一，**单任务TDP方法**（如ATROM、Kamel、GraphMM、S3等）针对特定场景独立设计，缺乏统一框架，难以在联邦设置下同时服务多种任务。其二，**面向表格数据的LLM类方法**（如FM4DP、MELD、TableGPT）或**时空基础模型**（PromptGAT、UniST、UrbanGPT）尽管具有通用推理能力，但并未考虑跨客户端隐私保护，且直接应用于轨迹数据时性能差距明显——实验表明，其整体表现比统一联邦方案至少低32.26%。此外，若采用差分隐私加噪保护数据，会显著损失时空相关性及下游效用；而同态加密等方案则会引入难以承受的计算开销。因此，如何在去中心化、隐私合规的条件下，利用大语言模型（LLM）的泛化能力高效统一地完成多类轨迹准备任务，成为一个尚待填补的缺口。

本文提出**FedTDP**——一个基于大语言模型的统一联邦轨迹数据准备框架。其核心动机是通过**轻量级轨迹隐私自编码器（TPA）**配合秘密共享的安全聚合，在不注入噪声的前提下保护客户端参数隐私；同时设计**轨迹知识增强器（TKE）**，借助轨迹感知提示工程、离站调优、LoRA稀疏微调和双向知识蒸馏，将时空模式注入LLM，弥补通用模型对轨迹语义的理解不足；并引入**联邦并行优化（FPO）**，通过分割学习、交替优化与并行训练大幅度削减通信量与训练时间。这一组合为垂直联邦轨迹数据准备提供了隐私保证、知识增强和训练效率三位一体的解决路径，实验证实其总体性能比单任务方法提升至少18.38%，训练运行时间降低约11.3–14.2倍，通信数据量减少1.4–1.8倍，验证了统一联邦框架的可行性与优势。

## 核心方法与创新机理

FedTDP 的核心创新在于针对垂直联邦轨迹数据准备的三个关键槽位进行了系统性重构，形成了一种不依赖原始数据共享的统一大语言模型（LLM）适配方案。整体框架通过**轨迹隐私自编码器（TPA）**、**轨迹知识增强器（TKE）** 与**联邦并行优化（FPO）** 三个模块的协同，解决了传统联邦学习中隐私保护与模型效用之间的张力，以及通用 LLM 对时空模式理解不足的根本问题。

**隐私保护机制的重新设计**。传统联邦轨迹分析通常依赖差分隐私加噪（导致效用下降）或同态加密（计算开销过高）。FedTDP 采用一种轻量级三层 MLP 的自编码器 TPA（隐藏维 256，嵌入维 32，GELU 激活），将原始三维时空点映射到高维嵌入空间，使传输数据不再是可逆的原始轨迹。关键创新在于，TPA 的参数聚合采用成对秘密共享掩码机制：

$$\tilde { P } _ { i } ^ { ( k ) } = P _ { i } ^ { ( k ) } + \sum _ { j = 1 \& j \ne i } ^ { | { \mathcal C } | } a _ { i , j } * s k _ { i , j } , \quad a _ { i , j } = \left\{ \begin{array} { l l } { 1 , \ i < j } \\ { - 1 , \ i > j } \end{array}\right.$$

每个客户端 $C_i$ 在本地参数块 $P_i^{(k)}$ 上叠加成对共享密钥 $sk_{i,j}$，使得所有掩码块在服务端求和时，密钥项相互抵消，精确恢复原始参数之和（定理 1）。这提供了不引入噪声、不损失精度的形式化隐私保证（Appendix C.2 基于互信息 $I(T;E)$ 的分析），在隐私-效用权衡上构成对差分隐私加噪路线的根本性替代。

**轨迹知识注入的协同增强**。通用 LLM 缺乏对时空序列的归纳偏置，单任务模型则无法泛化至未见任务。TKE 通过四条相互增强的路径解决此问题：(i) 定义统一的轨迹指令范式（Task, Data, Information, Format），将异构 TDP 任务转化为结构化提示；(ii) 离站调优（offsite‑tuning）使 LLM 在不直接访问原始数据的前提下获得轨迹初步感知；(iii) LoRA 稀疏微调依据每层参数变化率比例 $R^{(r)}(L_i) = \frac{CR^{(r)}(L_i)}{\sum_{j=1}^N CR^{(r)}(L_j)}$ 动态选择需要更新的层，降低训练开销；(iv) 客户端 SLM 与服务端 LLM 的双向知识蒸馏——SLM 通过逆 KL 散度对齐 LLM 的高频输出分布，LLM 通过前向 KL 散度吸收 SLM 从本地轨迹中学到的知识。消融实验（Fig. 5）证实，移除 TKE 导致性能下降至少 27.52%，说明该模块是框架中获得轨迹理解能力的决定性因素。

**联邦训练效率的结构性优化**。直接对大模型进行联邦微调会带来通信与计算的双重瓶颈。FPO 通过分割学习将训练过程解耦为客户端 SLM 编码与服务器 LLM 推理的交替优化，并结合并行训练策略。实验表明，FPO 使训练运行时间降低约 11.3–14.2 倍，通信数据量减少 1.4–1.8 倍（Fig. 7）。这一效率提升使得在真实联邦环境中部署 LLM 成为可行，且不牺牲模型性能。

综合来看，FedTDP 的创新并非三个模块的简单叠加，而是通过隐私保护编码、轨迹知识蒸馏与高效联邦优化之间的因果耦合，构建了一个在严格数据垂直分割条件下仍可统一执行多种轨迹数据准备任务的 LLM 适配层。

FedTDP 的总体设计目标是在不共享原始轨迹数据的前提下，统一执行多种轨迹数据准备（TDP）任务。为此，框架将去中心化隐私保护、轨迹知识注入与联邦训练效率三个核心瓶颈整合为一条端到端处理管道。整体架构（图2）由部署于多个客户端的**小语言模型（SLM）**和部署于中心服务器的**大语言模型（LLM）**协同构成，并由三个关键模块驱动：**轨迹隐私自编码器（TPA）**、**轨迹知识增强器（TKE）**与**联邦并行优化（FPO）**。

### 1. 客户端侧：隐私编码与局部处理

各客户端持有按行政区划垂直分割的轨迹序列 $T = \{p_1, p_2, \ldots\}$，其中每个点 $p = \langle l, t \rangle$ 包含经纬度和时间。原始点坐标不能直接外传。**TPA**（§4.1）首先将每个三维时空点编码为高维嵌入向量，该编码器是一个轻量级三层的MLP（GELU激活，隐藏层维度256，嵌入维度32），其目标是提取并保留时空相关性，同时隐藏原始坐标。编码后的嵌入与任务指令组合为轨迹感知提示，输入客户端SLM进行本地推理或中间层计算。

在联邦参数聚合时，为保护各客户端的模型更新，TPA采用基于秘密共享的安全聚合：客户端 $C_i$ 对其参数块 $P_i^{(k)}$ 添加成对共享密钥掩码：

$$
\tilde{P}_i^{(k)} = P_i^{(k)} + \sum_{\substack{j=1 \\ j \neq i}}^{|\mathcal{C}|} a_{i,j} \cdot sk_{i,j},\quad
a_{i,j} = 
\begin{cases}
1, & i < j \\
-1, & i > j
\end{cases}
$$

所有掩码块之和等于原始参数块之和（定理1, Eq.2），服务器聚合时掩码相互抵消，从而在不引入噪声或增加计算开销的条件下实现形式化隐私保护（Appendix C.2）。

### 2. 服务器侧：轨迹知识增强与全局推理

聚合后的嵌入和梯度被送往服务器，用于更新全局LLM。**TKE**（§4.2）负责从四个维度向LLM注入领域知识，使其具备跨任务的轨迹理解能力：

- **轨迹感知提示工程**：为每项TDP任务生成统一格式的指令提示，遵循 (Task, Data, Information, Format) 范式。
- **离站调优**：利用大量无标签轨迹数据对LLM进行预适配，使其学习基本时空模式。
- **LoRA稀疏微调**：按层的变化率比例 $R^{(r)}(L_i) = \frac{CR^{(r)}(L_i)}{\sum_j CR^{(r)}(L_j)}$ 选择重要层进行低秩更新，减少微调开销。
- **双向知识蒸馏**：客户端SLM通过最小化逆KL散度 $\min D_{KL}(P_{\theta_{SLM}} \| P_{\theta_{LLM}})$ 对齐LLM的高频输出，服务器LLM则通过最小化正向KL散度对齐SLM的局部轨迹知识，形成知识闭环。

增强后的LLM能够统一处理异常检测、补全、地图匹配、出行方式识别等十类TDP任务，在零样本和小样本设置下均大幅超越单任务专用模型（Table 2）。

### 3. 联邦并行优化：效率保证

直接对LLM进行联邦微调会导致极高的通信和计算开销。**FPO**（§4.3）通过三个策略解决该问题：

- **分割学习**：将训练分解为客户端的编码器/SLM优化与服务器的LLM优化两部分，仅必要中间表示参与传输。
- **交替优化**：客户端与服务器交替执行不同步长的更新，减少同步等待。
- **并行训练**：允许多个客户端同时本地训练，进一步提升收敛速度。

实验表明，FPO使FedTDP的训练运行时间相较于其他基于LLM的方法降低 **11.3–14.2 倍**，通信数据量减少 **1.4–1.8 倍**（Fig. 7）。

### 模块交互总结

| 模块 | 角色 | 数据流向 |
|------|------|----------|
| TPA | 隐私编码与安全聚合 | 原始轨迹 → 高维嵌入；掩码参数块 → 服务器聚合，反向分发更新 |
| TKE | 知识注入 | 聚合嵌入与任务提示 → LLM增强；SLM↔LLM双向知识蒸馏 |
| FPO | 联邦训练优化 | 分解客户端/服务器训练，控制通信频次与并行度 |

三模块紧密耦合：TPA提供无噪声的隐私传输基础，TKE赋予模型跨任务时空推理能力，FPO确保联邦场景下的实际可部署性，三者共同实现了统一、高效且隐私安全的轨迹数据准备。

FedTDP 框架由三个核心模块组成：**轨迹隐私自编码器**（TPA）实现参数的安全聚合与隐私保护；**轨迹知识增强器**（TKE）为大小模型注入轨迹先验知识；**联邦并行优化**（FPO）降低通信开销并加速训练。客户端部署轻量小语言模型（SLM），服务端部署大语言模型（LLM），两者通过双向知识蒸馏协同完成多任务轨迹数据准备。

### 轨迹隐私自编码器（TPA）
TPA 是三层 MLP 编码‑解码器（隐藏维度 256，嵌入维度 32），将原始三维时空点映射为高维嵌入，再经解码器还原序列。为在不牺牲精度的条件下安全聚合各客户端参数，TPA 采用基于**秘密共享的聚合机制**：客户端 $C_i$ 对其参数块 $P_i^{(k)}$ 叠加与其它客户端（$j\ne i$）的成对共享密钥掩码进行混淆：

$$
\tilde { P } _ { i } ^ { ( k ) } = P _ { i } ^ { ( k ) } + \sum _ { j = 1 \,\&\, j \neq i } ^ { | { \mathcal C } | } a _ { i , j } * s k _ { i , j },
\qquad
a _ { i , j } = 
\begin{cases}
 1, & i < j\\
-1, & i > j
\end{cases}
\tag{1}
$$

其中 $sk_{i,j}$ 是客户端 $i$ 与 $j$ 预协商的对称密钥，系数 $a_{i,j}$ 保证掩码相互抵消。定理 1 保证所有客户端掩码块之和等于原始块之和：

$$
\sum _ { i = 1 } ^ { | { \mathcal { C } } | } \tilde { P } _ { i } ^ { ( k ) } = \sum _ { i = 1 } ^ { | { \mathcal { C } } | } P _ { i } ^ { ( k ) } \tag{2}
$$

服务端接收混淆块后求和即得无噪声的聚合参数，同时无法还原任何单一客户端的原始参数，从形式上保证了隐私性（参见附录 C.2 中的互信息分析）。

### 轨迹知识增强器（TKE）
TKE 通过四个机制让 LLM 有效理解轨迹任务：

1. **轨迹提示工程**：定义统一提示范式 `(Task, Data, Information, Format)`，将不同轨迹准备工作转化为结构化指令。
2. **离站调优**：在冻结 LLM 主体的情况下，仅训练轻量适配层，初步适应轨迹语义。
3. **LoRA 稀疏微调**：在每轮训练中，仅更新部分层的 LoRA 参数。层 $L_i$ 在第 $r$ 轮的参数变化率占比为：

$$
R ^ { ( r ) } ( L _ { i } ) = 
\frac { C R ^ { ( r ) } ( L _ { i } ) }
{ \sum _ { j = 1 } ^ { N } C R ^ { ( r ) } ( L _ { j } ) } \tag{3}
$$

其中 $CR^{(r)}(L_i)$ 是该层 LoRA 参数的绝对变化量，$N$ 为层总数。按此概率加权无放回抽取高响应层进行更新，保持训练稀疏且高效。

4. **双向知识蒸馏**：客户端 SLM 通过**逆 KL 散度**对齐服务端 LLM 的高频输出分布：

$$
\operatorname*{min}_{\theta_{SLM}} \, D_{KL}(P_{\theta_{SLM}} \| P_{\theta_{LLM}}) =
\sum_{T} P_{\theta_{SLM}}(T) \log \left( \frac{P_{\theta_{SLM}}(T)}{P_{\theta_{LLM}}(T)} \right) \tag{4}
$$

其中 $\theta_{SLM}, \theta_{LLM}$ 分别为 SLM 与 LLM 的参数，$P_{\theta}(\cdot)$ 为对应模型在输出空间 $T$ 上的分布。同时，LLM 通过**前向 KL 散度** $D_{KL}(P_{\theta_{SLM}} \| P_{\theta_{LLM}})$ 反向对齐 SLM 捕获的局部轨迹知识，构成闭环增强。

### 联邦并行优化（FPO）
FPO 将整体训练过程分解为客户端的 SLM 部分训练和服务端的 LLM 部分训练（分割学习），通过**交替优化**避免两者同时通信；此外，不同任务的训练可在客户端和服务端上**并行执行**，使通信数据量减少1.4–1.8倍，训练运行时间降低约11.3–14.2倍（Fig. 7）。 

多任务训练时，总损失为各轨迹数据准备任务损失之和 $\mathcal{L} = \mathcal{L}_{T1} + \mathcal{L}_{T2} + \dots$，通过联合优化使单一框架同时适配多项 TDP 场景。

## 实验与关键发现

FedTDP 在六个轨迹数据集（GeoLife / Porto / T‑Drive / Tencent / Gowalla / SHL）上针对十类轨迹数据准备（TDP）任务进行了全面评估，涵盖小样本（few-shot）与零样本（zero-shot）两种设置。核心结论是：**FedTDP 在关键指标上大幅超过单任务 TDP 方法及基于大语言模型（LLM）的表格数据处理方法，其隐私保护、轨迹知识注入和联邦并行优化三个组件对性能与效率均有决定性贡献。**

### 1. 主结果：整体性能对比（Table 2）

- **相比单任务 TDP 方法的最优 baseline**（单任务训练，且所有 baseline 均扩展了差分隐私以保证公平对比），FedTDP 在所有任务上的平均提升 **≥ 18.38%**。  
  以 GeoLife 小样本异常检测为例，FedTDP 的 **F1 = 81.20**，而最强单任务 baseline S‑TDP 仅为 **60.36**，绝对提升 **+20.84 个百分点**；轨迹补全准确率也从 73.87 % 提高到 **87.45 %**（+13.58 个百分点）。在其他数据集和任务（如 Porto 轨迹‑用户链接、T‑Drive 出行方式识别）上同样观察到显著且一致的增益。

- **相比基于 LLM 的表格数据处理方法**（FM4DP、MELD、TableGPT），FedTDP 的整体性能至少高出 **32.26%**。这些方法虽也利用 LLM 的语义理解能力，但缺乏对轨迹时空结构的知识注入，导致在轨迹补全、异常检测等需要细粒度序列建模的任务上表现乏力。

### 2. 消融研究：各组件对性能与效率的影响（Figure 5）

为量化 Trajectory Privacy Autoencoder (TPA)、Trajectory Knowledge Enhancer (TKE) 和 Federated Parallel Optimization (FPO) 的贡献，我们移除单个组件并对比其表现：

- **移除 TKE**：在所有任务上性能下降 **≥ 27.52%**。TKE 同时作用于客户端 SLM 与服务端 LLM，通过轨迹感知提示、离站调优、LoRA 稀疏微调和双向 KL 散度知识蒸馏，使模型习得通用的 TDP 语义。失去 TKE 后，LLM 退化为缺乏时空模式的通用语言模型，无法有效处理轨迹补全、异常检测等任务。

- **移除 TPA**：部分任务性能略有上升。这是因为 TPA 传输 32 维嵌入而非原始三维坐标，编码过程引入了一定信息压缩；但**加入 TPA 是保护隐私的前提**，且其通过秘密共享的安全聚合（Eq. (1)–(2)）在**不添加噪声、不降低精度**的条件下实现了形式化的隐私保证。因此，性能上的微小代价是为满足隐私法规所必需的取舍。

- **移除 FPO**：训练运行时间与通信开销增加近 **4 倍**。FPO 通过分割学习（客户端训练本地低层模块，服务端训练高层 LLM）和交替优化，将多任务训练并行化；移除后，模型回退到直接联邦微调范式，通信量激增且收敛缓慢，验证了 FPO 对大规模部署的关键支撑作用。

### 3. 效率对比：训练时间与通信开销（Figure 7）

在 GeoLife 数据集上，FedTDP 的运行时间仅为其他 LLM 方法（FM4DP、MELD、TableGPT）的 **1/11.3 ~ 1/14.2**，通信数据量减少了 **1.4 ~ 1.8 倍**。这得益于 FPO 的设计：客户端仅传输轻量中间表示与梯度，避免直接暴露原始轨迹；服务端在安全聚合后批量执行 LLM 前向/反向，大幅降低冗余通信。

### 4. 泛化能力：可见任务数量削减（Figure 6）

通过逐步减少训练中可见任务的数量（从 7 类减至 1 类），FedTDP 仍能保持较强的泛化性能。即使仅以 1 ~ 2 个任务作为指引，在未见过任务上的测试指标下降幅度远小于基线方法。TKE 定义**统一的任务指令范式 (Task, Data, Information, Format)** 使得模型能够跨任务迁移知识，同时双向蒸馏机制支持 SLM 与 LLM 持续对齐，从而缓解了对大规模标注的依赖。

### 5. 基座模型与参数敏感性

- **服务端 LLM 选择**：Llama 系列在大多数 TDP 任务上取得最优性能（Figure 12），GPT3 在部分任务上有竞争力，而 Qwen 在测试任务上的跨度更大。
- **客户端 SLM 选择**：GPT3‑Small 综合表现最佳，其后是 T5‑Small 和 GPT2‑Small。
- **训练层比例 m**（LoRA 稀疏微调中每轮选择的层数占比）：随着 m 增加，性能缓慢上升并趋于饱和；m 过大则增加训练开销（Figure 13）。因此，在实践中可通过网格搜索平衡效率与精度。

上述结果表明，FedTDP 通过协同设计隐私编码器、知识增强器和联邦并行优化，成功解决了垂直联邦场景下多任务统一轨迹数据准备的关键瓶颈。**其性能优势可归因于三点因果链路**：(1) TKE 注入轨迹时空先验使 LLM / SLM 突破通用模型的语义盲区；(2) TPA 在零噪声安全聚合下保持了嵌入的时空相关性；(3) FPO 的分解‑并行架构将通信与计算开销控制在可行范围内，使大模型联邦训练从工程上变为现实。

> ⚠ **注意**：当前实验未明确报告具体的失败案例或系统性的失败模式。消融中移除 TPA 带来的性能轻微回升说明隐私保护与效用的权衡存在优化空间，但文中未对极端情况（如高度稀疏轨迹或超大规模客户端）进行敏感分析，该点需要后续补充验证。

## 定位与知识库关联

### 1 在轨迹数据准备方法谱系中的位置

FedTDP的核心定位在于填补 **垂直联邦场景下统一轨迹数据准备** 的方法空白。现有的轨迹数据准备工作可以从两个维度理解：一是任务范围（单任务 vs. 多任务），二是隐私保护机制（中心化 vs. 去中心化）。

**相对于单任务TDP基线（ATROM、Kamel、GraphMM、AttnTUL、Estimator、S3、LightTR）：**
这些方法针对特定任务（异常检测、轨迹补全、地图匹配等）进行专门设计，在各自任务上表现良好，但缺乏跨任务泛化能力。实验表明（Table 2），FedTDP在few-shot/zero-shot设置下，整体性能超过单任务TDP方法至少18.38%。在GeoLife异常检测任务上，F1从S-TDP的60.36提升至81.20；在轨迹补全任务上，准确率从73.87提升至87.45。这一性能跨越的关键在于 **TKE模块通过轨迹感知提示、离站调优、稀疏微调和双向知识蒸馏，将通用的LLM/SLM转化为具有轨迹领域知识的统一推理器**（§4.2），而非依赖任务专用架构。

**相对于基于LLM的表格数据处理方法（FM4DP、MELD、TableGPT）：**
这些方法将LLM应用于通用表格数据清洗但缺乏时空语义理解。FedTDP在整体性能上超过该类方法至少32.26%（Table 2）。差距的根源在于TKE引入的轨迹知识增强机制——通用LLM本身缺乏对轨迹序列中时空依赖关系、移动模式、路网约束的理解，而TKE通过轨迹提示工程（定义`(Task, Data, Information, Format)`范式）和双向知识蒸馏，使模型获得TDP特定的语义理解能力。

**相对于基于LLM的时空分析方法（PromptGAT、UniST、UrbanGPT）：**
这些工作将LLM用于时空预测，但面向集中式数据，未考虑隐私限制。FedTDP的区别在于两个层面：（a）**隐私保护机制**——通过TPA轻量级编码器-解码器配合秘密共享安全聚合（Eq.1-2），在不解码原始轨迹的情况下完成联邦训练，Appendix C.2提供了基于互信息的形式化隐私保证；（b）**任务统一**——不限于单一分析任务，而是覆盖十种轨迹数据准备任务（Table 4）。

### 2 机制创新的因果定位

FedTDP对方法谱系的贡献可通过三个“改变插槽”（changed slots）理解：

**插槽1：隐私保护策略。** 基线方法依赖差分隐私加噪（导致效用下降）或同态加密（计算开销高）。FedTDP的TPA模块通过将三维时空点映射到高维嵌入空间并配合秘密共享聚合，在避免加噪的同时实现隐私保护（§4.1，置信度0.9）。但消融实验揭示了一个关键权衡：去除TPA后部分任务性能反而提升（Fig. 5），因为高维嵌入替代了原始三维坐标，说明TPA在隐私和效用之间存在固有的信息损失。

**插槽2：LLM适配策略。** 基线方法要么忽略LLM的轨迹知识缺失，要么采用全参数微调。FedTDP的TKE通过四步注入轨迹知识（轨迹提示→离站调优→LoRA稀疏微调→双向知识蒸馏），在保持LLM通用能力的同时获得任务特异性。消融实验显示移除TKE导致性能下降至少27.52%（Fig. 5，置信度0.95），证明这是基准性能的核心驱动力。

**插槽3：联邦训练效率。** 直接联邦微调LLM导致通信开销大。FPO通过分割学习、交替优化和并行训练，将训练运行时间降低约11.3-14.2倍，通信数据量减少1.4-1.8倍（Fig. 7）。去除FPO则训练时间和通信开销增加近4倍（Fig. 5消融实验）。

### 3 适用边界与核心局限

尽管FedTDP在统一框架上表现出色，其适用边界需要在以下几个维度明确：

**（a）任务覆盖范围的边界。** FedTDP支持的十种任务集中在数据准备层面（降噪、补全、简化、匹配等），尚未扩展到更高级的轨迹挖掘任务（聚类、模式发现、预测）。附录中提到的开放问题（part_008）明确指出：如何将框架扩展为语义解释器以支持下级任务（如聚类、预测）仍是未解决的方向。

**（b）隐私-效用权衡的内生限制。** 消融实验明确揭示：TPA模块在保护隐私的同时，用高维嵌入替代原始三维坐标，导致部分任务性能低于无隐私保护的变体（§5.2 Ablation Study，置信度0.9）。这一权衡在FedTDP框架内部无法根本消除——隐私保护的程度与任务性能构成一对基本矛盾。当前的形式化隐私保证（Appendix C.2）基于互信息界，但未在实验中系统地测试不同隐私预算下的性能退化曲线。

**（c）复杂路网场景的轨迹补全局限。** 从Fig. 7的消融数据来看，地图匹配（MM）和轨迹-用户链接（TUL）任务的F1整体低于异常检测（AD）和轨迹补全（TI）。虽然论文未专门讨论这一现象的原因（limitations字段为空），但可能反映了LLM在结构化路网约束下的推理能力仍然不足。

**（d）模型基座选择的依赖性。** 附录中模型基础研究表明Llama在服务端LLM表现最优而GPT3-Small在客户端SLM表现最优（Fig. 12，置信度0.9）。FedTDP的整体性能部分取决于底座模型的选择，而不同模型架构对轨迹知识的吸收效率可能存在差异，论文未提供跨模型架构的系统比较。

**（e）多任务联合训练的梯度冲突。** 多任务联合损失定义为简单求和 $\mathcal{L} = \mathcal{L}_{T1} + \mathcal{L}_{T2} + \dots + \mathcal{L}_{T10}$（§C.5），未引入任务权重或梯度调节机制。当任务间存在冲突时（如简化要求丢弃点而补全要求恢复点），这种等权加和可能导致次优解。

**（f）实验环境的生态效度。** 所有实验基于六个公开数据集（GeoLife、Porto、T-Drive等），这些数据集的轨迹密度、采样率和噪声模式与实际部署环境可能存在差异。公平性注释中提到，所有基线方法扩展了差分隐私机制以保证公平比较——但这是对基线的人工修饰，未必反映实际部署中各方法的原生隐私保护能力。

### 4 开放问题与演进方向

从FedTDP的当前形式出发，存在三条清晰的演进路径：

**（a）可解释性缺口。** part_008明确提出的开放问题指出：FedTDP目前无法解释为何某个点被标记为异常，或某段轨迹的补全推理过程。对于需要信任和公平性保证的应用场景（如执法领域的轨迹取证），缺乏解释能力构成实用化的关键瓶颈。

**（b）向高级任务语义扩展。** 当前框架定位为TDP（数据准备），尚未与下游轨迹挖掘任务形成闭环。如果能将TDP的输出语义与聚类、预测、模式发现的输入需求对齐，FedTDP可从数据准备工具进化为完整的轨迹智能管道。

**（c）架构深度与通信效率的进一步优化方向。** 虽然FPO已将通信量降低至基线方法的0.56-0.71倍（Fig. 7数据），但分割学习本身引入的通信轮次与模型层数的线性关系仍未根本打破。如何结合异步聚合或梯度压缩进一步解耦这一关系，是效率优化的理论问题。

**（d）未见任务（zero-shot）泛化的理论理解。** Fig. 6显示，随着可见任务数量减少，虽整体泛化能力有所下降，但FedTDP仍保持一定性能——这背后的机制是TKE注入的轨迹先验知识在起作用。然而，零样本泛化的边界（哪些任务类型可通过指令理解而被泛化，哪些必须通过微调）目前仅依赖经验观察，缺乏理论刻画。

**（e）隐私与效用的形式化边界。** 虽然Appendix C.2提供了基于互信息的上界分析，但这一分析与实验中观察到的性能退化之间缺乏直接联系。若能建立隐私预算与任务性能退化之间的量化关系（如$\epsilon$变化对应的F1变化函数），将为实际部署中的隐私参数选择提供科学依据。
