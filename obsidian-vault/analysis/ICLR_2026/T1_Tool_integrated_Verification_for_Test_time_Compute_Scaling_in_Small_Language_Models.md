## 概要

本文提出 **Tool-integrated Verification (T1)**，一种面向小语言模型（sLM）测试时计算扩展的两阶段验证框架。核心思路是将外部工具（如代码解释器、知识检索器）集成到验证流程中，先通过工具验证器（ToolV）过滤候选解，再使用奖励模型（RM）进行评分。该方法有效缓解了sLM因参数容量有限而在记忆密集型验证步骤（如数值计算、事实核查）上的性能瓶颈。实验表明，在MATH500和GSM8K基准上，T1显著提升了sLM的测试时扩展性能，其中Llama-3.2 1B模型在MATH基准上超越了更大的Llama-3.1 8B模型。

**核心瓶颈**：小语言模型（sLM）在验证任务中受限于有限的参数容量，无法记忆所有所需的计算事实和知识，导致在数值计算和事实核查等记忆密集型验证步骤上表现不佳。如Figure 1所示，当计算复杂度（N个三位数的加减运算）增加时，1B模型的验证准确率显著下降，而3B模型保持稳定。

**因果旋钮**：通过集成外部工具（如代码解释器和知识检索器）来卸载记忆密集型步骤，从而减少sLM的验证负担。

**核心洞察**：将外部工具集成到验证流程中，可以显著降低小语言模型在验证时的记忆需求，使其在测试时计算扩展中达到与更大模型相当的性能，而无需增加模型参数。

**决定性证据**：
- sLMs fail to verify even simple calculations, particularly as the complexity of calculations N increases. (置信度: 0.95)
- code generation and execution substantially improves sLM's verification accuracy, narrowing the gap with larger models even as N increases. (置信度: 0.95)
- Tool-integrated Verification (T1), a two-stage framework in which external tools first verify candidate solutions and sLMs then verify the filtered solutions. (置信度: 0.95)
- a Llama-3.2 1B model under test-time scaling outperforms the significantly larger Llama-3.1 8B model. (置信度: 0.9)

## 核心方法与创新机理

T1的核心创新在于将验证流程从单阶段（仅使用奖励模型）改造为两阶段（工具过滤 + 奖励模型评分），具体变更如下：

| 变更槽位 | 基线值 | 提出值 | 证据锚点 | 置信度 |
|---------|--------|--------|---------|-------|
| 验证流程 | 单阶段：仅使用奖励模型（PRM或GenRM）进行验证和评分 | 两阶段：先使用基于工具的验证器（ToolV）过滤候选解，再使用奖励模型进行评分 | Tool-integrated Verification (T1), a two-stage framework in which external tools first verify candidate solutions and sLMs then verify the filtered solutions. | 0.95 |
| 验证器能力来源 | 完全依赖模型参数记忆的计算事实和知识 | 通过外部工具（代码解释器、知识检索器）卸载记忆密集型步骤，减少对模型参数容量的依赖 | offloading memorization-heavy steps, such as numerical calculations and fack-checking, to external tools, T1 enables sLMs to achieve verification accuracy comparable to much larger models without increasing parameters. | 0.95 |
| 验证器训练方式 | 使用标准监督学习或强化学习训练验证器 | 使用多LoRA知识蒸馏，分别训练工具验证器和奖励模型验证器 | we employ knowledge distillation (Hinton et al., 2015; Kim & Rush, 2016) from LLMs. Specifically, we fine-tune sLM using tool-based and RM-based verifications generated by a larger teacher model θ_T. To efficiently manage multiple distinct tasks during the distillation process, we adopt a multi-LoRA (Hu et al., 2022) approach, assigning separate LoRA adapters, Δθ_tool, and Δθ_reward, for each verifier. | 0.95 |

![[assets/figures/papers/iclr26_0001_tBkLWfmugI_T1_Tool-integrated_Verification_for_Test-time_Co/figures/001_Figure_1.jpg]]

T1框架包含三个模块，如Figure 2所示：

1. **Generator**：小语言模型（sLM）生成候选解，可能因计算错误而产生不正确解。
2. **Tool-based Verifier (ToolV)**：sLM基于其推理生成可执行代码；代码输出用于验证解的正确性。对于数学推理，使用代码解释器进行数值检查；对于知识密集型任务，使用基于Wikipedia摘要的检索器进行事实检查。
3. **RM-based Verifier**：奖励模型（GenRM / PRM）照常评估解，但其判决仅在解通过工具辅助过滤器后才对最终决策有贡献。

### 5.1 验证策略

**Best-of-N策略**：从N个采样候选中选择验证器得分最高的解：
$$\operatorname * { a r g m a x } _ { \pmb { y } \in \{ { y } _ { 1 } , . . . , { y } _ { N } \} } r ( { \pmb x } , { \pmb y } ) , \quad \mathrm { s . t . } \quad { \pmb { y } } _ { i } \sim \pi ( { \pmb y } \mid { \pmb x } , { \pmb I } _ { p } ; \theta )$$

**生成式验证器得分**：验证得分是经过思维链推理后，最终token为'Yes'的概率：
$$r ( { \pmb x } , { \pmb y } ) = \pi ( z _ { T } = ^ { * } \mathrm { Y e s } ^ { , } \mid { \pmb x } , { \pmb y } , I _ { v } , z _ { 1 : T - 1 } ; \theta )$$

### 5.2 T1两阶段验证

**T1最终选择**：选择最大化工具二进制过滤器与验证器得分乘积的解：
$$\boldsymbol { y } ^ { * } = \underset { \boldsymbol { y } \in \{ y _ { 1 } , \dots , y _ { N } \} } { \arg \operatorname* { m a x } } f ( \boldsymbol { x } , \boldsymbol { y } ; \mathcal { T } , \boldsymbol { \theta } ) \times \boldsymbol { r } ( \boldsymbol { x } , \boldsymbol { y } ; \boldsymbol { \theta } )$$

**基于工具的验证函数**：生成工具调用查询，执行工具，并提取二进制验证结果：
$$f ( \pmb { x } , \pmb { y } ; \mathcal { T } , \theta ) = c _ { 2 } \sim \pi \left( c \mid \mathcal { T } ( c _ { 1 } ) , \pmb { x } , \pmb { y } , \pmb { I } _ { f } ; \theta \right) , \quad \mathrm { w h e r e } \quad c _ { 1 } \sim \pi ( c \mid \pmb { x } , \pmb { y } , \pmb { I } _ { c } ; \theta )$$

### 5.3 验证器蒸馏

使用多LoRA方法，分别训练工具验证器和奖励模型验证器：

**ToolV蒸馏损失**：
$$\mathcal { L } _ { \mathrm { t o o l } } ( \Delta \theta _ { \mathrm { t o o l } } ) = - \mathbb { E } _ { x \sim \mathcal { X } _ { \mathrm { t r a i n } } , ~ y \sim \pi ( \cdot | x , I _ { p } ; \theta ) , ~ c \sim \pi ( \cdot | t , x , y , I ; \theta _ { T } ) } \log \pi ( c | t , x , y , I ; \theta + \Delta \theta _ { \mathrm { t o o l } } )$$

**RM验证器蒸馏损失**：
$$\mathcal { L } _ { \mathrm { r e w a r d } } \big ( \Delta \theta _ { \mathrm { r e w a r d } } \big ) = - \mathbb { E } _ { x \sim \mathcal { X } _ { \mathrm { r e i n } } , ~ y \sim \pi ( \cdot \mid x , I _ { p } ; \theta ) , z \sim \pi ( \cdot \mid x , y , I _ { r } ; \theta _ { T } ) } \log \pi ( z \mid x , y , I _ { r } ; \theta + \Delta \theta _ { \mathrm { r e w a r d } } )$$

### 5.4 理论分析

**无工具的记忆化下界（引理5.1）**：在没有工具的情况下，任何ε-接近最优的学习算法必须记忆Ω(M³)的信息量：
$$I ( X ; \theta | { \bf \bar { \Delta } } P ) = \bar { \Omega ( } M ^ { 3 } )$$

**有工具的记忆化下界（定理5.2）**：在有工具的情况下，任何ε-接近最优的学习算法所需记忆的信息量接近于0：
$$I \left( \dot { X } ; \theta \vert P \right) \ \stackrel { \sim } { = } \ \stackrel { \sim } { 0 }$$

### 6.2 消融与分析

- **两阶段设计的必要性**：ToolV单独使用即可超越PRM和GenRM，但两阶段设计（ToolV + PRM/GenRM）在所有设置下均达到最高准确率。
- **数据效率**：ToolV在仅使用10%蒸馏数据时仍能保持有竞争力的性能，展示了其数据效率。
- **工具集成的独特性**：简单增加一个无工具集成的额外验证阶段无法带来ToolV所观察到的增益。
- **问题类型分析**：ToolV在代数、数论、计数与概率问题上效果最显著，在几何问题上效果下降。
- **难度级别分析**：ToolV在难度级别2-4上持续改进，在级别5上略有下降。

## 定位与知识库关联

T1方法位于以下研究脉络的交汇点：

1. **测试时计算扩展**：基于Snell et al. (2024)的Best-of-N框架，通过增加推理计算量来提升模型性能。
2. **验证器方法**：结合了过程奖励模型（PRM, Lightman et al., 2024）和生成式奖励模型（GenRM, Zhang et al., 2024）两种验证范式。
3. **工具集成语言模型**：继承了PAL (Gao et al., 2023)等将计算委托给代码解释器的思路，但首次将其系统性地集成到验证流程中。
4. **知识蒸馏**：使用多LoRA方法（Hu et al., 2022）从大教师模型蒸馏验证能力到小模型。

与现有方法Themis (Li et al., 2024)相比，T1在Llama-3.2-1B-Instruct上表现更优（Figure 9）。T1的理论贡献在于证明了工具集成可以显著降低sLM的记忆需求（从Ω(M³)到≈0），为小模型在测试时扩展中超越大模型提供了理论依据。
