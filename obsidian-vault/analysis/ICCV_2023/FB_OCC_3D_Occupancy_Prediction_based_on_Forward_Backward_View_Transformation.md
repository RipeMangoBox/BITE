## 概要

**FB-OCC** 是 CVPR 2023 端到端自动驾驶研讨会中提出的单目 3D 占用预测方法，在 Occ3D-nuScenes 挑战赛中以 **54.19% mIoU** 排名第一。该方法直面一个核心瓶颈：大规模视觉模型在有限 3D 标注数据上严重过拟合，且现有单一种类的视图变换——前向投影（LSS 范式）或后向投影（BEVFormer 范式）——难以同时高效构建密集几何表示并捕捉全局语义。

FB-OCC 的核心洞察在于将两类视图变换串联为因果闭环：**前向视图变换（F-VTM）** 基于深度分布将图像特征投影为稀疏但几何准确的初始 3D 体素，随后将其压缩为富含语义先验的 BEV 查询；**后向视图变换（B-VTM）** 以这些查询（而非随机初始化）与图像特征进行深度感知的交叉注意力，从稀疏表示中恢复密集几何信息。这一“先前后向”联合视图变换构成了方法的关键因果旋钮。

为缓解大模型在小规模 3D 数据上的过拟合，FB-OCC 引入大规模预训练策略：先在 Objects365（200 万张 2D 检测图像）上预训练骨干网络，再在 nuScenes 上进行深度估计与 2D 语义分割的联合预训练，其中 2D 语义标签由 SAM 自动生成。配合距离感知焦点损失、Dice 损失、几何/语义亲和力损失、Lovász-Softmax 损失等多重监督信号，以及 16 帧历史时间信息融合，FB-OCC 在验证集上展现了从 67.8M 参数（mIoU 42.06）到 1.2B 参数（mIoU 52.79）的持续规模化收益。

**方法定位**：FB-OCC 属于单目相机输入的密集 3D 占用预测方法，其联合视图变换架构区别于仅前向投影的 **MonoScene**（Cao et al., CVPR 2022）、仅后向投影的 **BEVFormer**（Li et al., ECCV 2022）以及挑战赛基线 **CTF-Occ**（Tian et al., arXiv 2023）。通过大规模骨干网络（InternImage-H，1.2B 参数）和高分辨率输入（960×1760），该方法将占用预测的性能边界大幅推高，但需注意测试集成绩为 7 模型集成结果，且训练需 32 块 A100 GPU，复现成本极高。



三维占用预测（3D Occupancy Prediction）旨在将自动驾驶场景的周围环境表示为稠密的体素网格，并为每个体素赋予语义类别标签。与仅预测少数前景类别的3D目标检测不同，占用预测要求模型对空间中所有占据区域进行完整语义重建，这对下游规划与决策至关重要。然而，该任务面临两个根本性瓶颈。

**瓶颈一：大规模视觉模型在有限3D数据上过拟合严重。** 近年来，视觉骨干网络（如InternImage-H）的参数规模已扩展至十亿级别，在2D视觉任务上展现出强大的表示能力。但3D占用预测的标注数据极为稀缺——以Occ3D-nuScenes数据集为例，其标注体素范围仅为$[-40\text{m}, -40\text{m}, -1\text{m}, 40\text{m}, 40\text{m}, 5.4\text{m}]$，体素分辨率$0.4\text{m}$，远不足以支撑大模型从零训练。直接将大模型应用于有限3D数据会导致严重过拟合，无法发挥其表示潜力。

**瓶颈二：单一种类的视图变换难以同时高效构建密集几何表示并捕捉全局语义。** 现有方法在将多相机2D图像特征变换到3D空间时，通常仅采用前向投影（Forward Projection）或后向投影（Backward Projection）之一。前向投影（如Lift-Splat-Shoot, LSS）通过预测每个像素的深度分布将2D特征“抬升”到3D空间，能够高效生成密集的初始体素表示，但其深度预测精度受限于单目深度估计的固有歧义性，导致几何结构不够精确。后向投影（如BEVFormer中的深度感知交叉注意力）以BEV空间中的查询向量为锚点，从图像特征中采样相关信息，能够更好地捕捉全局语义上下文，但查询向量通常为随机初始化，缺乏几何先验，导致收敛缓慢且稀疏区域的表示质量不佳。**MonoScene**（Cao et al., CVPR 2022）作为单目3D语义场景补全的早期工作，仅依赖前向投影，几何精度受限；**BEVDet**（Huang et al., arXiv 2021）和**BEVFormer**（Li et al., ECCV 2022）虽在BEV感知上取得进展，但应用于稠密占用预测时，单一投影方式难以兼顾密集几何重建与语义理解。

针对上述瓶颈，FB-OCC的核心动机是：能否设计一种联合视图变换机制，使前向投影的几何先验与后向投影的语义建模能力互补，同时通过大规模2D预训练缓解3D数据不足的问题？具体而言，FB-OCC提出**前向-后向联合视图变换**：先通过前向投影生成稀疏但几何准确的初始3D体素，将其压缩为富含语义先验的BEV查询，再以此查询指导深度感知的后向投影，从稀疏表示中恢复密集几何信息。此外，FB-OCC通过在Objects365（200万2D检测图像）上的大规模预训练，以及在nuScenes上的深度估计与2D语义分割联合预训练（2D语义标签由SAM自动生成），有效缓解了大模型在有限3D数据上的过拟合问题。该方法最终在Occ3D-nuScenes测试集上达到54.19% mIoU，排名挑战赛第一。



## 核心方法与创新机理

FB-OCC 的核心创新在于**解决大规模视觉模型在有限3D数据上过拟合严重**这一瓶颈，通过**前向-后向联合视图变换**和**大规模预训练**两个因果旋钮，使大模型在3D占用预测任务上发挥优势。

### 前向-后向联合视图变换（F-VTM + B-VTM）

传统的视图变换方法采用单一范式：前向投影（如LSS）能高效构建密集几何表示，但缺乏全局语义理解；后向投影（如BEVFormer）能捕捉全局语义，但随机初始化的查询难以高效恢复密集几何。FB-OCC 将两者耦合为一个互补流程：

1. **F-VTM（前向视图变换）**：基于LSS从多相机图像特征生成初始3D体素表示，并使用BEVDepth的深度监督来提升深度预测精度。
2. **体素压缩为BEV查询**：将获得的3D体素表示压缩为BEV特征图，使其携带**丰富的几何先验和语义先验**。
3. **B-VTM（后向视图变换）**：以压缩后的BEV特征作为查询（而非随机初始化），与图像特征进行**深度感知的交叉注意力**，利用深度分布实现更精确的投影关系，从而从稀疏的初始表示中恢复密集几何信息。

这一设计的核心洞察在于：前向投影提供稀疏但几何准确的初始体素，后向投影利用这些富含先验的查询进行深度显式注意力，实现从稀疏到密集的几何恢复。消融实验表明，添加深度监督后（Version A→B），模型性能获得显著提升（Table 1）。

### 深度-语义联合预训练

FB-OCC 采用两阶段预训练策略缓解3D数据稀缺导致的过拟合：

1. **2D检测预训练**：在Object365数据集（200万张2D检测图像）上预训练图像骨干网络。
2. **深度-语义联合预训练**：在nuScenes上同时预测深度估计和2D语义分割标签。其中2D语义标签由SAM自动生成（结合框提示与LiDAR点提示）。消融实验中，Version F 引入该预训练后性能再次显著提升（Table 1）。

### 多损失函数联合优化

FB-OCC 集成了丰富的损失函数体系，从多个维度约束占用预测：

- 距离感知焦点损失 $L_{fl}$：对不同距离体素施加差异化权重
- Dice损失 $L_{dl}$：直接优化区域重叠
- 几何亲和力损失 $L_{scal}^{geo}$ 与语义亲和力损失 $L_{scal}^{sem}$：源自MonoScene，约束场景几何与语义一致性
- Lovász-Softmax损失 $L_{ls}$：源自OpenOccupancy，优化IoU指标
- 深度监督损失 $L_{d}$ 与2D语义损失 $L_{s}$：用于联合预训练阶段

消融实验中，Version G 添加Dice损失并使用3D变换对齐不同时间步的体素特征后，性能再度提升（Table 1）。

### 模型规模扩展

FB-OCC 验证了模型规模与性能的正向关系：从67.8M参数的Version H（mIoU 42.06）扩展到1.2B参数的Version K（mIoU 52.79），性能持续提升（Table 2）。大模型配合InternImage-H骨干网络和960×1760高分辨率输入，充分发挥了规模优势，最终在Occ3D-nuScenes测试集上以54.19% mIoU（7模型集成）排名第一。

### 与基线方法的关键差异

| 创新维度 | 基线方法 | FB-OCC |
|---------|---------|--------|
| 视图变换 | 仅前向投影（LSS）或仅后向投影（BEVFormer） | 前向后向联合：前向生成稀疏体素→压缩为BEV查询→后向深度感知注意力 |
| 预训练 | 仅ImageNet或无预训练 | Object365 2D检测预训练 + 深度-语义联合预训练（SAM自动标注） |
| 损失函数 | 仅交叉熵或焦点损失 | 距离感知焦点损失 + Dice损失 + 几何/语义亲和力损失 + Lovász-Softmax损失 + 深度监督损失 + 2D语义损失 |

FB-OCC 的整体架构围绕 **前向-后向联合视图变换** 这一核心设计展开，旨在解决单一种类视图变换难以同时高效构建密集几何表示与捕捉全局语义的瓶颈。其 pipeline 由四个主要模块串联构成：**Image Backbone → F-VTM（前向视图变换）→ B-VTM（后向视图变换）→ Voxel Encoder + Occupancy Head**，如 Figure 1 所示。

### 输入与特征提取

多相机图像首先经过大规模图像骨干网络提取多尺度特征。FB-OCC 的最终版本（Version K）采用 **InternImage-H** 作为骨干，参数量达 12 亿，输入分辨率可扩展至 960×1760（Table 2）。骨干网络的学习率设为主学习率的 1/10，以稳定大规模预训练权重的微调过程。

### 前向视图变换（F-VTM）

F-VTM 遵循 **Lift-Splat-Shoot（LSS）** 范式，从图像特征中预测逐像素的深度分布，将 2D 特征“提升”为 3D 体素表示。此过程生成的是**稀疏但几何相对准确**的初始体素，为后续精化提供几何先验。为获得准确的深度监督信号，FB-OCC 借鉴 BEVDepth 的做法，利用 LiDAR 点云生成深度真值来监督深度预测。

### 后向视图变换（B-VTM）

B-VTM 的核心创新在于**将 F-VTM 生成的 3D 体素压缩为 BEV 特征图，作为后向投影的查询（queries）**，而非使用随机初始化或可学习参数。这些 BEV 查询携带了来自前向投影的强语义先验，随后与图像特征进行**深度感知的交叉注意力**（Depth-Aware backward projection，源自 BEVFormer）。通过显式利用深度分布，B-VTM 能够从稀疏的初始表示中恢复密集的几何信息，实现“稀疏到密集”的表示增强。

### 占用预测头

F-VTM 的体素特征与 B-VTM 优化后的 BEV 特征在 Voxel Encoder 中融合，最终由 Occupancy Head 预测每个体素的语义占用类别（Figure 2）。预测范围为 $[-40\text{m}, -40\text{m}, -1\text{m}, 40\text{m}, 40\text{m}, 5.4\text{m}]$，体素分辨率为 0.4m，共覆盖 18 个语义类别。

### 信息流总结

整个 pipeline 的信息流可概括为：**多相机图像 → 骨干特征 → 深度分布引导的前向投影（稀疏 3D 体素）→ BEV 压缩（富含语义先验的查询）→ 深度感知的后向交叉注意力（密集 BEV 优化）→ 体素-BEV 融合 → 语义占用预测**。这一设计使前向投影的几何准确性与后向投影的语义丰富性形成互补，是 FB-OCC 取得领先性能的结构性基础。



### 3.1 整体架构概览

FB-OCC 的整体架构由四个核心模块串联构成，如 Figure 1 所示：

1. **Image Backbone**：以 InternImage-H 等大规模骨干网络提取多相机图像特征。
2. **F-VTM (Forward View Transformation Module)**：基于前向投影（LSS）从图像特征生成初始的稀疏 3D 体素表示，并压缩为富含语义先验的 BEV 特征图。
3. **B-VTM (Backward View Transformation Module)**：将压缩后的 BEV 特征作为查询，与图像特征进行深度感知的交叉注意力（深度感知后向投影），优化 BEV 表示。
4. **Voxel Encoder + Occupancy Head**：融合优化后的 BEV 特征与体素特征，预测每个体素的语义占用。

### 3.2 前向视图变换模块 (F-VTM)

F-VTM 遵循 **Lift-Splat-Shoot (LSS)** 范式。其核心机制为：

- **深度估计与投影**：对每个图像像素预测一个深度分布，根据该分布将图像特征“提升”（Lift）到 3D 空间中，生成初始的稀疏 3D 体素表示。
- **深度监督**：采用 **BEVDepth** 方法，利用 LiDAR 点云生成精确的深度真值，对深度预测过程进行监督。
- **BEV 压缩**：将获得的 3D 体素表示沿高度维度压缩为扁平的 BEV 特征图，从而融入更强的语义先验，为后续的后向投影提供高质量的查询初始化。

### 3.3 后向视图变换模块 (B-VTM)

B-VTM 基于 **BEVFormer** 的深度感知后向投影机制，但其关键改进在于**使用 F-VTM 压缩后的 BEV 特征作为查询**，而非随机初始化：

- **查询来源**：BEV 空间中的查询由前向投影的 BEV 压缩特征提供，携带了初步的几何与语义信息。
- **深度感知交叉注意力**：每个 BEV 查询利用深度分布信息与多相机图像特征进行交叉注意力，实现从稀疏表示中恢复密集几何信息。
- **融合输出**：优化后的 BEV 特征与原始体素特征融合，得到最终的体素表示，送入占用预测头。

### 3.4 占用预测头 (Occupancy Head)

如 Figure 2 所示，占用预测头接收融合后的体素特征，通过卷积或 Transformer 结构进一步编码，最终输出每个体素在所有类别上的语义占用概率。

### 3.5 损失函数体系

FB-OCC 采用多损失联合优化，总损失函数形式为：

$$L_{total} = L_{fl} + \lambda_1 L_{dl} + \lambda_2 (L_{scal}^{geo} + L_{scal}^{sem}) + \lambda_3 L_{ls} + \lambda_4 L_{d} + \lambda_5 L_{s}$$

各损失项含义如下：

| 符号 | 含义 | 来源/说明 |
|------|------|-----------|
| $L_{fl}$ | 距离感知焦点损失 (Distance-aware Focal Loss) | 对远距离体素赋予更高权重，缓解类别不平衡与远距离退化 |
| $L_{dl}$ | Dice 损失 | 直接优化预测与真值的重叠度，补充交叉熵类损失 |
| $L_{scal}^{geo}$ | 几何亲和力损失 (Geometry Affinity Loss) | 源自 **MonoScene** (Cao et al., CVPR 2022)，约束相邻体素的几何一致性 |
| $L_{scal}^{sem}$ | 语义亲和力损失 (Semantic Affinity Loss) | 源自 **MonoScene**，约束相邻体素的语义一致性 |
| $L_{ls}$ | Lovász-Softmax 损失 | 源自 **OpenOccupancy**，直接优化 mIoU 指标 |
| $L_{d}$ | 深度监督损失 | 对 F-VTM 中的深度预测进行监督 |
| $L_{s}$ | 2D 语义分割损失 | 用于联合深度-语义预训练阶段 |

### 3.6 评价指标公式

主要评价指标为 **平均交并比 (mIoU)**，计算方式如下：

$$mIoU = \frac{1}{C} \sum_{c=1}^{C} \frac{TP_c}{TP_c + FP_c + FN_c}$$

其中 $C$ 为类别总数（Occ3D-nuScenes 上为 18 类），$TP_c$、$FP_c$、$FN_c$ 分别为第 $c$ 类的真正例、假正例、假负例数量。

### 3.7 联合深度-语义预训练

如 Figure 3 所示，预训练阶段在 nuScenes 数据上同时预测深度图和 2D 语义分割标签：

- **深度监督**：利用 LiDAR 点云生成深度真值，训练模型从图像中预测稠密深度。
- **语义监督**：2D 语义标签由 **SAM (Segment Anything Model)** 通过框提示与 LiDAR 点提示自动标注生成。
- **联合优化**：通过 $L_d$ 和 $L_s$ 共同优化，使骨干网络同时学习几何结构与语义信息，缓解大规模模型在有限 3D 数据上的过拟合问题。



## 实验与关键发现

### 核心性能与挑战赛结果

FB-OCC在Occ3D-nuScenes数据集上取得了显著领先的3D占用预测性能。在测试集上，7模型集成方案达到**54.19% mIoU**，在挑战赛赛道中排名第一，相较基线CTF-Occ（28.53%）提升超过25个百分点。在验证集上，单模型Version K（1.2B参数）达到**52.79 mIoU**，远超BEVFormer基线（26.88）。

这一性能跃升的核心驱动力来自三个方面：前向-后向联合视图变换机制、大规模2D检测数据与深度-语义联合预训练、以及模型规模的持续扩展。然而需注意，测试集最优成绩依赖计算密集的7模型集成与测试时增强（TTA），实际单模型推理成本与实时性之间存在显著张力。

### 消融实验：从基线到高性能的逐级验证

Table 1系统追踪了FB-OCC从基础版本到高性能版本的逐级改进路径，每一步均带来可衡量的性能增益：

| 版本 | 关键改进 | 机制分析 |
|------|---------|---------|
| **Version A** | 基础前向投影（LSS）+ 后向投影（BEVFormer） | 联合视图变换的基线框架 |
| **Version B** | 添加深度监督（遵循BEVDepth） | 利用LiDAR点云生成精确深度真值，监督前向投影中的深度预测，提升几何精度 |
| **Version C** | 训练时忽略相机不可见体素 | 减少无效监督信号，聚焦可观测区域的优化 |
| **Version E** | 引入16帧历史时间信息 | 时序融合显著增强对遮挡和动态场景的建模能力 |
| **Version F** | 联合深度-语义预训练 | 在深度估计任务上叠加2D语义分割监督，使预训练阶段同时学习几何与语义表征 |
| **Version G** | 添加Dice损失 + 3D变换对齐时序体素特征 | 损失函数优化与更精确的时序特征对齐共同提升预测质量 |
| **Version H** | 测试时增强（图像/3D翻转 + 时序TTA） | Version G的基础上通过TTA进一步榨取性能，达到42.06 mIoU |

消融实验揭示的关键因果链为：**深度监督 → 几何精度提升 → 时序信息融合 → 语义-几何联合预训练 → 损失函数精细化**，每一步均在前一步基础上叠加收益，而非相互替代。

### 模型规模扩展分析

Table 2展示了FB-OCC在不同模型规模下的性能变化，验证了大规模视觉模型在3D占用预测任务上的扩展潜力：

- **Version H**（67.8M参数）：42.06 mIoU
- **Version I**（130.8M参数）：48.90 mIoU（+6.84）
- **Version J**（428.8M参数）：50.47 mIoU（+1.57）
- **Version K**（1200.0M参数，InternImage-H骨干）：52.79 mIoU（+2.32）

从67.8M到1.2B参数，mIoU累积提升10.73个点，表明模型容量持续带来收益。但边际收益递减（从Version I到J仅+1.57，J到K仅+2.32），暗示单纯扩展模型规模已接近当前框架的性能上限。Version K采用InternImage-H作为图像骨干，输入分辨率提升至960×1760，体素分辨率保持0.4m，这些配置共同推高了计算成本——训练需32块NVIDIA A100 GPU。

### 预训练策略的关键作用

联合深度-语义预训练（Figure 3）是FB-OCC区别于先前工作的核心设计之一。该策略分两阶段：

1. **大规模2D检测预训练**：在Object365数据集（200万张2D检测图像）上预训练图像骨干，为模型注入丰富的视觉语义先验。
2. **深度-语义联合预训练**：在nuScenes上同时预测深度图和2D语义分割标签，其中语义标签由SAM（Segment Anything Model）基于框提示和LiDAR点提示自动生成。

Version F的实验结果表明，联合预训练相较仅深度预训练带来明确性能提升。这一设计的深层逻辑在于：深度估计提供几何约束，语义分割提供类别先验，两者联合优化使模型在有限3D标注数据上也能学习到鲁棒的几何-语义联合表征，从而缓解大规模模型在小规模3D数据集上的过拟合问题。

### 失败模式与局限性

尽管FB-OCC取得了领先性能，分析揭示出若干关键局限：

1. **远距离体素性能下降**：文中未提供距离分层的IoU分析，但从占用预测任务的一般特性推断，远距离区域因点云稀疏和投影分辨率不足，体素预测质量显著降低。该问题在纯视觉方案中尤为突出。
2. **预训练标签噪声**：2D语义标签由SAM自动生成，存在类别不平衡和标注噪声，可能限制模型在稀有类别上的性能上限。
3. **计算密集的推理流程**：测试时增强（TTA）需执行8次推理（图像翻转+3D翻转+时序TTA），7模型集成进一步放大计算量，难以满足实时自动驾驶部署需求。
4. **传感器模态单一**：FB-OCC仅使用相机输入，未与LiDAR方案对比，无法评估多传感器融合场景下的相对优势。在极端光照、恶劣天气或严重遮挡场景下的鲁棒性亦未验证。

## 定位与知识库关联

### 技术路线溯源

FB-OCC 的视图变换设计融合了单目 3D 感知的两条主流路线：**前向投影（forward projection）** 和 **后向投影（backward projection）**。

- **前向投影分支**：继承自 **LSS**（Philion & Fidler, ECCV 2020）的 Lift-Splat-Shoot 范式，将图像特征沿深度分布“提升”为 3D 体素。FB-OCC 在 F-VTM 中采用这一机制，并引入 **BEVDepth**（Li et al., AAAI 2023）的点云深度监督，以获得更准确的深度分布估计。这使前向投影生成的初始体素具备稀疏但几何准确的特性。
- **后向投影分支**：借鉴 **BEVFormer**（Li et al., ECCV 2022）的交叉注意力机制，以 BEV 空间中的查询与图像特征进行交互。FB-OCC 的关键创新在于：**不使用随机初始化的 BEV 查询，而是将前向投影生成的 3D 体素压缩为富含语义先验的 BEV 特征图，作为后向投影的查询**。这使得 B-VTM 的交叉注意力能够在已有几何结构的基础上进行深度感知的特征聚合，而非从零开始构建空间表示。

与现有基线的关系：
- **MonoScene**（Cao et al., CVPR 2022）：单目 3D 语义场景补全的开创性工作，FB-OCC 继承了其几何亲和力损失 $L_{scal}^{geo}$ 和语义亲和力损失 $L_{scal}^{sem}$，但将其从单目补全扩展到多相机占用预测。
- **BEVDet**（Huang et al., arXiv 2021）：纯前向投影的 BEV 检测方法，FB-OCC 在 F-VTM 中沿用了类似的 LSS 投影逻辑，但通过后续的 B-VTM 弥补了前向投影在全局语义建模上的不足。
- **CTF-Occ**（Tian et al., arXiv 2023）：Occ3D 挑战赛基线，FB-OCC 在相同基准上以显著优势超越（mIoU 54.19% vs 28.53%），但需注意前者为单模型结果，后者为 7 模型集成。
- **OpenOccupancy**（Wang et al., NeurIPS 2023）：FB-OCC 引入了其 Lovász-Softmax 损失 $L_{ls}$ 以优化 mIoU 指标。

### 核心方法差异

| 维度 | 主流基线做法 | FB-OCC 做法 |
|------|-------------|------------|
| 视图变换 | 单一前向投影（LSS/BEVDet）或单一后向投影（BEVFormer） | 前向→后向联合：前向生成稀疏体素并压缩为 BEV 查询，后向以深度感知交叉注意力精炼 |
| BEV 查询初始化 | 随机初始化或零初始化 | 前向投影体素压缩，携带几何与语义先验 |
| 预训练策略 | ImageNet 分类预训练 | Object365 2D 检测预训练 + nuScenes 深度估计与 2D 语义分割联合预训练 |
| 2D 语义标签 | 人工标注或无需 | SAM 自动标注（框提示 + LiDAR 点提示） |
| 损失函数 | 交叉熵/焦点损失 | 距离感知焦点损失 + Dice 损失 + 几何/语义亲和力损失 + Lovász-Softmax 损失 + 深度监督损失 + 2D 语义损失 |
| 模型规模 | ResNet-50 / VoVNet-99（≤100M 参数）| InternImage-H（1.2B 参数），输入分辨率 960×1760 |
| 时序建模 | 少量历史帧或无 | 16 帧历史时间信息，3D 变换对齐不同时间步的体素特征 |

### 适用边界与局限

**适用场景**：
- 纯视觉多相机输入的 3D 语义占用预测，适用于自动驾驶场景理解。
- 大规模模型 + 大规模预训练的策略在数据受限的 3D 感知任务上有效缓解过拟合。

**关键局限**：
1. **计算成本极高**：训练需 32 块 A100 GPU，测试时使用 TTA（图像/3D 翻转 + 时序 TTA，相当于 8 次推理）和 7 模型集成，单模型 1.2B 参数的推理延迟难以满足实时部署需求。
2. **数据依赖重**：预训练依赖 Objects365（200 万 2D 检测图像）和 SAM 自动标注的 2D 语义标签，SAM 标注存在噪声和类别不平衡，可能限制模型性能上限。
3. **远距离性能退化**：文中未提供距离分层的 IoU 分析，但体素分辨率 0.4m 且感知范围达 40m，远距离体素因稀疏性和遮挡问题性能下降明显（需人工验证具体衰减幅度）。
4. **仅支持相机输入**：未与 LiDAR 方案对比，无法体现多传感器融合的相对优势；在极端光照、遮挡或恶劣天气下的鲁棒性未经验证。
5. **集成策略不可复现**：测试集 54.19% mIoU 为 7 模型集成结果，集成权重通过 NNI 搜索确定，单模型最优为 52.79（Version K），集成增益约 1.4 个百分点，但推理成本成倍增加。

### 开放问题

1. **联合深度-语义预训练的机制理解**：语义分割任务如何更有效地辅助深度估计？是提供了场景级上下文约束，还是通过共享特征表示隐式正则化深度预测？目前缺乏消融实验分离这两种效应。
2. **长期时序融合的效率**：16 帧历史信息带来显著增益（Version E），但当前采用 3D 变换对齐不同时间步的体素特征，计算和存储开销随帧数线性增长。是否存在更高效的时序压缩或选择性记忆机制？
3. **占用预测的不确定性校准**：当前输出为确定性语义标签，未建模预测置信度。在下游规划任务中，不确定性估计对于安全决策至关重要——例如，远距离或遮挡区域的低置信度预测应触发保守策略。
4. **大规模预训练的边际收益**：模型从 67.8M 扩展到 1.2B 参数，mIoU 从 42.06 提升至 52.79（+10.73），但参数量增长约 17.7 倍。在资源受限场景下，是否存在更高效的缩放策略或知识蒸馏方案？
