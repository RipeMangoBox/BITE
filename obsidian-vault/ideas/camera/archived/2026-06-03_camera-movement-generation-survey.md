# Camera Movement Generation 系统调研
> [!abstract] 结论先行
> Camera movement generation 并不是空白方向，但它长期被拆散在自动摄影、novel view synthesis、camera-controlled video generation、video re-rendering 这些社区里。真正“生成相机运动本身”的工作在 2024 之后才明显增多，代表线是 E.T./DIRECTOR、Director3D、ChatCam、GenDoP/DataDoP、CT-1、ShotVerse。  
> 严格的 `sketch/freehand 2D path -> 6-DoF camera movement` 现代生成论文很少；目前更常见的是“用户给 3D camera path/poses”或“在重建的 3D scene 里拖拽相机轨迹”，例如 RealCam-I2V。Tora、DragNUWA、DragAnything 这类 2D trajectory 控制更偏 object/background motion，不应直接等同为 camera extrinsics generation。

## 1. 任务边界与分类

这里把 camera movement generation 定义为“生成、估计、规划或控制相机位姿/运镜轨迹”，输出可以是 6-DoF extrinsics / intrinsics / camera pose sequence / 轨迹参数，也可以是受相机条件控制的生成视频。人体动作生成只作为类比，不纳入主表。

一个重要分界：  

- “camera control”常表示用户已经给出了相机轨迹，模型负责执行。  
- “camera movement generation”更强，要求模型从文本、场景、角色、草图或导演意图里生成轨迹。  
- “sketch2camera movement”如果只画 object trajectory，不等于 camera extrinsics；必须看输出是否是 camera pose/path。

| Camera-on-rails                                         | 2015      | 3D constraints -> constrained camera path                    | 自动生成受约束摄影路径，[[analysis/ICCV_2025/GenDoP_Auto_regressive_Camera_Trajectory_Generation_as_a_Director_of_Photography.md\|GenDoP]] reference 中出现 |

## 6. Sketch / draw-to-camera 专项结论

### 6.1 严格 sketch-to-camera 很少

严格定义：用户画 2D freehand/sketch/path，系统输出 3D camera extrinsics 或 camera path。按这个定义，现代 diffusion video generation 里成熟论文很少。


| 工作                                                                                                                               | 年份         | 输入                                                          | 输出                                    | 结论                                                                                         |
| -------------------------------------------------------------------------------------------------------------------------------- | ---------- | ----------------------------------------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------ |
| Path Drawing for 3D Walkthrough                                                                                                  | 1998       | 2D hand-drawn stroke                                        | 3D walkthrough camera path            | 老 HCI 线，是真 sketch/path-to-camera                                                           |
| Sketch-Based Navigation in 3D Virtual Environments                                                                               | 2008       | 2D curve/point/sketch gesture                               | camera navigation animation/keyframes | 城市场景中把 sketch 语义映射为 camera navigation                                                      |
| [[analysis/arxiv_2025/RealCam_I2V_Real_World_Image_to_Video_Generation_with_Interactive_Complex_Camera_Control.md\|RealCam-I2V]] | 2025/ICCV  | image + 在 reconstructed 3D scene 中拖拽/draw camera trajectory | camera-controlled I2V video           | 最接近现代“draw-to-camera movement”的生成模型；注意它是在 3D scene 里拖拽，不是纯 2D sketch 到 6-DoF               |
| [Freehand Sketches to Multi-View Scene Generation](https://arxiv.org/abs/2604.14302)                                             | 2026/arXiv | single freehand sketch + caption                            | multi-view images                     | 是 sketch-to-multiview，不是 continuous camera path；可借鉴 camera-aware adapter 和 SfM supervision |


[[analysis/arxiv_2025/RealCam_I2V_Real_World_Image_to_Video_Generation_with_Interactive_Complex_Camera_Control.md\|RealCam-I2V]] 的摘要明确说 inference 提供交互界面，用户可以在 3D scene 中通过 dragging 精确绘制 camera trajectories；这是当前最值得跟的 sketch/draw-to-camera 入口：[project](https://zgctroy.github.io/RealCam-I2V/), [paper](https://arxiv.org/abs/2502.10059), [CVF](https://openaccess.thecvf.com/content/ICCV2025/papers/Li_RealCam-I2V_Real-World_Image-to-Video_Generation_with_Interactive_Complex_Camera_Control_ICCV_2025_paper.pdf)。

### 6.2 这些不是严格 sketch-to-camera


| 工作                                                                                                                                                                                                                                                    | 为什么容易混淆                              | 更准确的定位                                                                |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ | --------------------------------------------------------------------- |
| [CamDirector](https://arxiv.org/abs/2603.02256)                                                                                                                                                                                                       | 输入 arbitrary 2D trajectory           | trajectory-to-video / object or motion control，不一定是 camera extrinsics |
| [paper](https://arxiv.org/abs/2306.02018)                                                                                                                                                                                                             | 输入 2D trajectory                     | fine-grained object/background motion control，不输出 3D camera path      |
| [[analysis/ECCV_2024/DragAnything_Motion_Control_for_Anything_using_Entity_Representation.md\|DragAnything]]                                                                                                                                          | 用户画线控制 entity/background             | object/background dragging，不是 camera pose generation                  |
| [[analysis/CVPR_2025/Motion_Prompting_Controlling_Video_Generation_with_Motion_Trajectories.md\|Motion Prompting]]                                                                                                                                    | motion trajectories 作为 video control | 可表达相机/物体运动，但核心是 motion prompt 控制视频                                    |
| [[analysis/SIGGRAPH_ASIA_2025/CamCloneMaster_Enabling_Reference_based_Camera_Control_for_Video_Generation.md\|CamCloneMaster]] sketch encoder + [[analysis/ICLR_2025/CameraCtrl_Enabling_Camera_Control_for_Text_to_Video_Generation.md\|CameraCtrl]] | sketch map + camera trajectory 可组合   | sketch 控内容，相机仍是另一路 pose/path 条件                                       |


研究空位很明显：把“导演在屏幕上画一个曲线/箭头/镜头路径草图”直接翻译成 physically plausible 6-DoF camera trajectory，并能在开放域 I2V/T2V 里稳定执行，目前仍没有像 HumanML3D/text-to-motion 那样成熟的数据集和标准任务。

## 10. 研究 gap 与可切入方向

### Gap A：真正的 sketch2camera movement 还缺数据和标准任务

现状：  

- 早期 HCI 有 2D path drawing -> 3D walkthrough，但不是现代生成模型。  
- [project](https://research.nvidia.com/labs/toronto-ai/GEN3C/)-I2V 解决了“在 3D scene 中拖拽相机路径”，但不是纯 2D sketch 到 6-DoF camera。  
- [FaceCam](https://arxiv.org/abs/2603.05506) / [paper](https://arxiv.org/abs/2402.03162) / [[analysis/ECCV_2024/DragAnything_Motion_Control_for_Anything_using_Entity_Representation.md\|DragAnything]] 的 2D trajectory 更偏 object/background motion，不输出 camera extrinsics。

可做题：  

1. 构建 `SketchCam` 数据：screen-space stroke / arrow / storyboard cue + first-frame RGBD + desired 6-DoF path + rendered video。
2. 设计 2D stroke 到 3D path 的显式中间表示：anchor point、look-at target、depth plane、motion type、speed profile、focal length schedule。
3. 把 [paper](https://arxiv.org/abs/2503.10592)-I2V 的 3D drag interface 降维成 2D sketch interface，并通过 MLLM/geometry module 自动 disambiguate depth/look-at。

### Gap B：文本到轨迹与视频执行之间仍断裂

E.T./GenDoP/[ReCapture](https://arxiv.org/abs/2411.05003) 生成 camera trajectory，CameraCtrl/GEN3C/TrajectoryCrafter 执行 camera trajectory，但两者之间的坐标系、尺度、intrinsics、scene constraints 不统一。

可做题：  

- `Planner -> Verifier -> Controller`：文本生成轨迹后，先用 scene geometry / depth / collision / framing verifier 修正，再交给 CameraCtrl/GEN3C/TrajectoryCrafter 执行。  
- 评估不仅看视频质量，也看轨迹可执行性：collision、subject visibility、composition rule satisfaction、depth-aware parallax plausibility。

### Gap C：camera 与 object/human dynamics 仍难解耦

[[analysis/CVPR_2025/AC3D_Analyzing_and_Improving_3D_Camera_Control_in_Video_Diffusion_Transformers.md\|AC3D]] 指出 RealEstate10K 静态偏置会把 camera motion 和 scene staticness 绑定。[[analysis/CVPR_2025/Motion_Prompting_Controlling_Video_Generation_with_Motion_Trajectories.md\|Motion Prompting]]/RealCOD-25K 开始补 camera + object 3D trajectories，但方向很新。

可做题：  

- 动态对象 + 相机运动联合控制数据集，要求每帧 camera pose、object 3D trajectory、2D tracks、caption。  
- 模型上采用 factorized latent：global camera motion latent、object dynamics latent、appearance latent 分开约束。  
- 评估上拆出 camera error、object 3D trajectory error、parallax consistency、occlusion consistency。

### Gap D：directorial language 不只是 “pan left / zoom in”

很多 camera control 工作只支持基本 motion type 或 explicit pose。真正导演语言包含“先推近建立压迫感，再绕到角色背后揭示空间关系”等叙事意图。

可做题：  

- 用 DataDoP / ShotVerse-Bench / [[analysis/ECCV_2024/E_T_the_Exceptional_Trajectories_Text_to_camera_trajectory_generation_with_character_awareness.md\|E.T.]] 对齐 directorial text、构图变化、subject saliency、camera pose。  
- 学习 semantic shot primitives：establishing shot、tracking shot、reveal、dolly zoom、orbit、push-in、pull-back。  
- 建立 directorial reward：text-trajectory alignment + composition + aesthetic + story beat satisfaction。

### Gap E：缺少跨模型可复用的 camera trajectory representation

[[analysis/SIGGRAPH_2024/MotionCtrl_A_Unified_and_Flexible_Motion_Controller_for_Video_Generation.md\|MotionCtrl]] 用 RT，[[analysis/ICLR_2025/CameraCtrl_Enabling_Camera_Control_for_Text_to_Video_Generation.md\|CameraCtrl]] 用 Plücker，I2VControl 用 dense 2D point trajectories，AC3D/[Unified Camera Positional Encoding](https://arxiv.org/abs/2512.07237) 又讨论相机 positional encoding。Representation 不统一导致模型难以互操作。

可做题：  

- 统一表示：SE(3) pose + intrinsics + dense ray/point correspondence + semantic anchors。  
- 做 representation ablation：sparse pose vs Plücker vs raymap vs dense point trajectory vs learned camera tokens。  
- 目标是同一 planner 输出可以驱动 [[analysis/ICLR_2025/CameraCtrl_Enabling_Camera_Control_for_Text_to_Video_Generation.md\|CameraCtrl]]、[[analysis/CVPR_2025/GEN3C_3D_Informed_World_Consistent_Video_Generation_with_Precise_Camera_Control.md\|GEN3C]]、[[analysis/arxiv_2025/TrajectoryCrafter_Redirecting_Camera_Trajectory_for_Monocular_Videos_via_Diffusion_Models.md\|TrajectoryCrafter]]、[paper](https://arxiv.org/abs/2412.07760)。

## 11. 最小可执行调研路线

1. 精读并复现表征接口：[[analysis/SIGGRAPH_2024/MotionCtrl_A_Unified_and_Flexible_Motion_Controller_for_Video_Generation.md\|MotionCtrl]]、[[analysis/ICLR_2025/CameraCtrl_Enabling_Camera_Control_for_Text_to_Video_Generation.md\|CameraCtrl]]、[[analysis/ICLR_2025/I2VControl_Camera_Precise_Video_Camera_Control_with_Adjustable_Motion_Strength.md\|I2VControl-Camera]]、[[analysis/CVPR_2025/AC3D_Analyzing_and_Improving_3D_Camera_Control_in_Video_Diffusion_Transformers.md\|AC3D]]。
2. 精读轨迹生成数据/评估：[[analysis/ECCV_2024/E_T_the_Exceptional_Trajectories_Text_to_camera_trajectory_generation_with_character_awareness.md\|E.T./DIRECTOR]]、[[analysis/ICCV_2025/GenDoP_Auto_regressive_Camera_Trajectory_Generation_as_a_Director_of_Photography.md\|GenDoP/DataDoP]]、[CameraCtrl II](https://arxiv.org/abs/2503.10592)。
3. 精读 sketch/交互入口：Path Drawing、Sketch-Based Navigation、[paper](https://arxiv.org/abs/2506.03140)-I2V、Geometrically Consistent Multi-View from Freehand Sketches。
4. 选一个 controller baseline：[[analysis/ICLR_2025/CameraCtrl_Enabling_Camera_Control_for_Text_to_Video_Generation.md\|CameraCtrl]] 或 [[analysis/CVPR_2025/GEN3C_3D_Informed_World_Consistent_Video_Generation_with_Precise_Camera_Control.md\|GEN3C]]；选一个 planner baseline：[[analysis/ICCV_2025/GenDoP_Auto_regressive_Camera_Trajectory_Generation_as_a_Director_of_Photography.md\|GenDoP]] 或 [OmniCam](https://arxiv.org/abs/2504.02312)；中间加一个 sketch/text-to-camera adapter。
5. 做小型 benchmark：20-50 个 first-frame RGBD scenes，每个 scene 给 5 类 sketch/directorial prompts，评估 trajectory plausibility、camera following、video consistency。
