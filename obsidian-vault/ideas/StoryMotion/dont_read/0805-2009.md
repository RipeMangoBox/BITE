总体判断是：**v2 的主方向合理，已经比 v1 和 v2-pre 可靠得多，但当前状态仍不宜写成 `implementation_complete_pending_calibration`。** 更准确的状态应是：

```yaml
status: v2_geometry_code_complete_pending_rule_budget_and_language_calibration
```

原因不是代码质量不足，而是目前仍有两个结构性问题没有闭合：第一，H0/H1 的候选事件能否从同一份阈值无关 signal artifact 精确重放；第二，最多 3 个 event 的 fact packet 是否足以覆盖真实轨迹，而不是把显著运动静默省略。两者没有关闭前，不应恢复全量 Qwen，也不应启动 Stage2 canonical-text 训练。

整体上最值得保留的部分有四个。C1REL 消除 world gauge、相邻 body-local 增量负责 primitive 解释、rotation log 取代 Euler 标签、LLM 只做 surface realization，这条几何链是清楚的；完整 atomic graph 与 bounded language packet分离也是正确的；first-20K 暴露结构问题后停止任务、保留 immutable artifact，而不是在原版本里打补丁，这个版本纪律是可靠的；raw caption 只保留 provenance，不回流 Qwen，也避免了原始 motion-tag→LLM 弱标签链被重新注入。Pulp 官方只说明 Camera caption 来自 motion tagging 后交给 LLM，并未提供独立几何真值；TriMotion 的公开代码则确实采用首帧相对轨迹、固定 (0.02,\mathrm m/0.3^\circ) 阈值、ratio 5 和 Qwen short/long language realization。因此你现在做全训练集 rate calibration、body-local primitive 和长序列事件归并，是合理的 Pulp-specific 扩展，但还不能直接继承 TriMotion 的正确性。([arXiv][1])

**目前最优先要修的是 H0/H1 artifact 路径的矛盾。** 文档的 P2 说从 signal shards 分别运行 H0 和 H1，这是正确的；但 9.3 又说 `event_plan_v2.py` 只读取 immutable v2-pre event records，而这些 records 是由 provisional H1 得到的。H0 与 H1 使用不同 (T_{\rm exit})，会改变 interval 边界、短 gap 穿越、事件拆分和合并，因此不能从 H1 event records 精确恢复 H0。除非 v2-pre record 保存了全部逐 step 六轴 signal，否则这条实现并没有真正支持 H0/H1 calibration。

最终应冻结为：

[
\text{immutable six-axis step signals}
\rightarrow
\begin{cases}
G^{H0}\
G^{H1}
\end{cases}
\rightarrow
\text{calibration selects one graph}.
]

`event_plan_v2.py` 必须读取 per-step signal shards，而不是读取 H1 event graph；H1 的 100K event-plan只能作为 throughput 和历史语言实验 provenance。这个问题修复前，“v2 实现完成”不成立。

第二个高风险点是 `max_caption_events=3`。v2-pre 的 100K 统计平均每条约有 8.42 个 axis event、6.51 个 required event。虽然 v2 已经修改 required 定义和 selection，但这个数量级至少说明：**不能预设 top-3 一定足够。** 如果轨迹存在 5 个显著事件，而 caption只写 3 个，parser 可以达到 100% packet recall，却仍然会给 Stage2 制造未写入文本的强 target variation。这个问题不能由“完整 graph 仍保留”自动解决，因为模型训练读的是 bounded caption，而不是完整 graph。

建议为每个 event 定义一个跨轴无量纲分数：

[
s_e=
\max\left(
\frac{\operatorname{median}*{t\in e}|r_t|}
{S^{\mathrm{rate}}*{a(e)}},
\frac{|A_e^{\mathrm{net}}|}
{S^{\mathrm{amp}}_{a(e)}}
\right),
]

其中 amplitude 分支只有在

[
\kappa_e\ge \kappa_{\min}
]

时有效。然后记录：

[
\operatorname{Coverage}_3
=========================

\frac{\sum_{e\in E_{\mathrm{selected}}}s_e}
{\sum_{e\in E_{\mathrm{salient}}}s_e+\epsilon}.
]

我建议直接预注册：

```text
all_direct_reversals_selected = true
caption_salience_coverage >= 0.90
selected_event_count <= 3
```

未通过时标记：

```text
canonical_status = caption_budget_exceeded
```

而不是仍然生成三条 partial canonical short。此类样本可以保留完整 graph 和 deterministic audit text，但暂不进入 canonical Camera-text Stage2 训练。若 uniform calibration 中超过约 20% 的样本触发 budget exceeded，再整体比较 `max_events=3` 与 `max_events=4`，或者恢复一个最小 macro summary；不能逐样本扩容。当前 `must_preserve` 字段也尚未有可复现定义，建议在定义完成前删除或改名为 `structurally_required`，并明确它只包括 primary 与必须表达的直接方向反转，不能靠人工直觉赋值。

第三个必须冻结的是 **static 与 weak motion 的语义分离**。当前至少需要三个状态：

[
\begin{aligned}
\texttt{strict_static}:&
\quad E_{\mathrm{present}}=\varnothing,\
\texttt{weak_motion_only}:&
\quad E_{\mathrm{present}}\neq\varnothing,\
E_{\mathrm{salient}}=\varnothing,\
\texttt{captioned_motion}:&
\quad E_{\mathrm{salient}}\neq\varnothing.
\end{aligned}
]

只有第一种可以生成 “The camera remains stationary.”。第二种不能因为没有 event进入 packet 就变成 static，建议固定为 deterministic 的 “The camera remains mostly steady, with only subtle movement.”，同时不赋予任何 directional control label。若你不希望引入 `mostly steady` 语义，就把 weak-only 样本排除出 directional text training，但不能错误写成 stationary。

第四个问题是当前 relation ontology 对嵌套事件还不够。`overlap / reverses / then` 加“每个后续 event 只连接前一个 event”，无法精确表达：

```text
dolly in: 0–60
pan right: 10–20
pan left: 35–45
```

线性边可能得到 `dolly overlaps pan-right`、`pan-right then pan-left`，但丢失 pan-left 也发生在持续 dolly 期间。Qwen又不接收 interval，因此无法恢复这条事实。解决方案不需要重新引入复杂 graph，只需增加一个最小关系，或让 deterministic planner直接读取 interval：

```text
then
overlap
during / while_primary_continues
reverses
```

推荐 Qwen 接收确定性的 sentence plan，而不是只有 event list 和简化 relation：

```json
{
  "clauses": [
    "The camera dollies in throughout the shot.",
    "It pans right and later pans left while the dolly-in continues."
  ],
  "event_ids": ["e0", "e1", "e2"]
}
```

Qwen仍然只做同义改写。`reverses` 也需要严格定义：只有同轴反向 event在短 gap 内直接衔接时才叫 reversal；若中间长期静止或插入其他阶段，只写 `then moves in the opposite direction`，不要泛化成直接反转。

待敲定项建议收敛为下表：

FOV 是当前合同里另一个容易被低估的问题。Pulp 的 Camera14 不只有 extrinsics，它明确包含相对 Camera–Human distance和水平、垂直 FOV。([arXiv][1]) 因此，仅依据 raw caption是否包含 `zoom` 来 quarantine 不够：raw text本身可能漏标 zoom。你需要从 intrinsics计算例如

[
z_t=\frac{\Delta \log \sqrt{f_{x,t}f_{y,t}}}{\Delta t},
]

并检测是否存在显著 FOV 变化。对于显著 zoom 但 v2 只生成 extrinsics6 caption 的样本，应至少保存：

```text
camera_attribute_scope = extrinsics6_partial
unsupported_geometry_attributes = [zoom]
canonical_stage2_eligible = false
```

或者在 Stage2 中明确 mask FOV-related supervision。否则某条 canonical text写 “camera remains stationary”，但 Camera14 target中存在明显 zoom，仍会形成 text–target 语义缺口。你可以暂不实现 zoom ontology，但几何 quarantine 必须在 P7 前完成。

Calibration 512 的规模总体可用，但当前协议还需要三个强化。首先，192 条 threshold boundary 最好明确为 12 个 signed primitive各 16 条，并覆盖 enter、exit、duration和 amplitude-rescue边界；否则 roll 或某个负方向可能几乎没有样本。其次，calibration 与 sealed 必须按 parent source video 和 near-duplicate cluster分组隔离，不能只有 sample ID不重复。第三，人工审核需要更独立：calibration 第一轮可以显示候选 interval以便定规则，但 sealed第一遍应先隐藏 H0/H1 标签、event色块和 canonical text，让审核者仅根据真实轨迹渲染、Camera frustum／静态网格和六轴曲线判断 primitive与方向；第二遍再显示模型标签。否则所谓人工正确率会受到候选规则的锚定。

12 条纯轴 synthetic tests也不应全部由同一套 pose构造和解析代码闭环。至少增加独立的 projection sanity test：例如 pan-right 时 Camera optical axis应向右转，而固定 world point在图像中应向左移动；truck-right 时 Camera center应沿其当前 local (+x) 移动。否则同一个符号错误可能同时存在于 synthetic generator和parser中，仍然“全部通过”。此外，如果你最终要在论文中写 coordinate-gauge defect，不仅要证明 C1REL 对随机 SE(3) 左乘不变，还要报告：

[
\text{raw direction}
\times
\text{canonical direction}
\times
\text{coordinate-construction branch}
]

的 confusion matrix；如果无法恢复 preprocessing branch，最多声称存在系统性 directional inconsistency，不能把根因唯一归为 gauge construction。

现有 sealed gate还缺少一个关键指标。`caption-packet event-instance recall=100%`只证明文本忠实于自己的 fact packet，不能证明 fact packet没有漏掉真实运动。sealed 应增加人工 event-level指标：

[
\text{salient-event precision},\qquad
\text{salient-event recall},\qquad
\text{direction accuracy}\mid\text{matched event}.
]

建议的最低合同是：在 `canonical_status=accepted` 子集上，salient-event precision 的 95% 置信下界不低于 95%，recall 下界不低于 90%，relation accuracy下界不低于90%，训练文本可直接使用率下界不低于90%。同时单独报告 canonical coverage／abstention rate；不能通过大量 abstain换取高 precision而不披露。若某一 primitive无法达标，不要在 sealed之后调该轴阈值，可以将该 primitive降为 unsupported，并重新发布更窄的 ontology。

Qwen 的定位建议再收紧一点。真正的 canonical 对象应是：

```text
camera_motion_events
caption_fact_packet
camera_text_canonical_template
```

而三条 Qwen输出更准确地叫：

```text
camera_text_enriched_shorts[3]
```

它们不是三份独立 canonical truth，而是同一个 canonical fact packet的三种语言 realization。这样后续 Stage2 可以明确分离：

[
\text{recaption correction}
\quad\text{vs.}\quad
\text{same-fact paraphrase enrichment}.
]

不建议冻结“最小词汇差异”硬门槛。三条描述同一事实，本来就应该高度相似；强迫它们变得不相似最容易诱发新增速度、阶段或风格事实。只需要归一化后不完全相同，并对近重复做去重；若最终只剩一到两条合法表达，就按实际 unique 数量采样。

CLIP/T5 也不应成为 P7 的 blocker。TriMotion 的跨模态能力来自专门训练的 video–pose–text shared motion space，而不是因为一个普通冻结 T5 或 CLIP天然理解相机左右、反转和时间关系。([arXiv][2]) 因此你可以在 calibration 上测 paired direction-flip AUC、unplanned-event detection和 paraphrase duplicate detection；若某个 encoder的方向翻转 AUC不足，例如低于 0.8，直接删除它的 direction-margin阈值，只保留日志。闭集 parser和人工 sealed audit才是事实 gate。

\end{aligned}}
]

其中 (T_0\rightarrow T_1) 证明 correction，(T_1\rightarrow T_2) 才证明 enrichment。若担心 deterministic 与 Qwen自然语言风格混杂，可以先做一个短预算 screen选择 `deterministic one-short` 或 `Qwen one-short` 作为 (T_1)，正式长训不必再扩成四臂。

调整 event 数量设定：
整体上，Event‑T2M 的参考进一步说明：你当前“step → 轴级 interval → bounded fact packet”的方向是对的，但 **`max_caption_events=3` 仍然冻结得过早**。更稳妥的修订不是让 Qwen 处理更多 step，而是在轴级事件和文本事件之间增加一层很薄的“共时几何事件归并”，并由 Pulp 全训练集分布决定文本事件上限。Event‑T2M 可以支持“同时发生、属于同一时间阶段的动作应作为一个 event”这一原则，但不能支持 Pulp 采用 3、4 或 11 中的任何具体上限。Event‑T2M 将 event 定义为能够映射到连续运动片段的最小、自洽语义单元，其 prompt 还明确规定同一时刻同时进行的一组动作构成一个 event；论文的人评也表明这种 event-aware 分法优于按动词机械拆分。([arXiv][1])

**1. (E_{\mathrm{present}}) 和 (E_{\mathrm{salient}}) 分别是什么？**

这两个符号是我在上一轮分析中引入的概念集合，并不是你当前 schema 已经冻结的字段。你的 schema 现在是“所有 event 都保存，再为每个 event 写 `salient` 和 `must_preserve` 布尔值”。建议正式把语义写成：

[
E_{\mathrm{present}}
====================

\left{
e:
e\text{ 通过 H0/H1 hysteresis、持续时间与gap规则形成合法interval}
\right},
]

[
E_{\mathrm{salient}}
====================

\left{
e\in E_{\mathrm{present}}:
e\text{ 通过segment-level caption salience规则}
\right}.
]

也就是说：

* (E_{\mathrm{present}}) 是**几何上可以确认存在的运动事件**。它可能很弱，不一定值得写进文本。
* (E_{\mathrm{salient}}) 是 (E_{\mathrm{present}}) 的子集，是**强到足以成为 Camera caption 事实的事件**。
* 最终写入文本的集合还应再记作 (E_{\mathrm{text}})，它是经过跨轴归并和文本预算处理后的集合。

应明确满足：

[
E_{\mathrm{text}}
\subseteq
E_{\mathrm{salient}}
\subseteq
E_{\mathrm{present}}.
]

三种状态也要分开：

[
E_{\mathrm{present}}=\varnothing
\Rightarrow
\texttt{strict_static},
]

[
E_{\mathrm{present}}\neq\varnothing,\quad
E_{\mathrm{salient}}=\varnothing
\Rightarrow
\texttt{weak_motion_only},
]

[
E_{\mathrm{salient}}\neq\varnothing
\Rightarrow
\texttt{captionable_motion}.
]

第二种不能被描述成完全 static。它可以使用 “the camera remains mostly steady with subtle movement”，或者直接从方向控制文本训练中 abstain。否则一个确有微弱运动的 target 会被错误配成 “the camera remains stationary”。

为了兼容后面 Event‑T2M 启发的事件归并，我建议进一步把术语改为：

[
E_{\mathrm{axis}}^{\mathrm{present}}
\rightarrow
G_{\mathrm{geom}}
\rightarrow
G_{\mathrm{salient}}
\rightarrow
G_{\mathrm{text}}.
]

其中 (E_{\mathrm{axis}}^{\mathrm{present}}) 是轴级 atomic intervals；(G_{\mathrm{geom}}) 是跨轴共时归并后的 Camera 几何事件；(G_{\mathrm{salient}}) 是值得写入文本的几何事件；(G_{\mathrm{text}}) 是最终 fact packet。这样不会把“一个 dolly + pan 的复合摄影阶段”误算成两个完全独立的文本事件。

**2. H0 和 H1 指什么？**

H0、H1 不是两种事件类别，而是两套待人工 calibration 选择的 hysteresis 公式。它们共享同一个事件进入阈值：

[
T_{\mathrm{enter},a}=U_a,
]

但退出阈值不同：

[
\text{H0}:
\quad
T_{\mathrm{exit},a}
===================

\sqrt{L_aU_a},
]

[
\text{H1}:
\quad
T_{\mathrm{exit},a}
===================

0.5U_a.
]

由于通常 (L_a\ll U_a)，所以一般有：

[
\sqrt{L_aU_a}<0.5U_a.
]

因此：

* **H0 的退出阈值更低，hysteresis 更宽。** 一个事件启动后，即使速度下降到比较弱的区域，也会继续保持 active。优点是减少错误切段；风险是把真实停顿或弱漂移桥接进一个过长事件。
* **H1 的退出阈值更高，事件结束得更早。** 优点是更容易保留真实静止 gap；风险是把一个持续但有速度波动的动作切成多个碎片。

你现在的 provisional 100K H1 产生了约 8.42 个 axis events/样本，这至少提示 H1 可能存在较强碎片化，但不能仅凭这个统计选择 H0，因为 H0 也可能产生错误长事件。人工 calibration 应比较：

[
\text{false split},\quad
\text{false merge},\quad
\text{interval boundary error},\quad
K_{\mathrm{axis}}\text{ 随序列长度的膨胀}.
]

另一个必须修正的实现边界是：H0 和 H1 都应从同一份逐 step 六轴 signal shards 重建。不能从已经由 H1 生成的 event records 反推 H0，因为不同退出阈值会改变事件边界、短 gap、拆分与合并结果。

**3. deterministic planner 是什么？它与线性边策略有什么区别？为什么不让 Qwen 直接处理 interval？**

这里的 deterministic planner 不是神经网络，也不是新训练模块。它是一个**纯规则的 sentence-plan builder**：读取被选事件的 primitive、direction、start/end interval，确定哪些事实应该组成一句话、谁是持续主运动、谁发生在谁期间、谁先后发生、谁构成直接反转，再输出结构化 clause plan。

例如有三个事件：

[
e_0=\text{dolly in},\quad I_0=[0,60],
]

[
e_1=\text{pan right},\quad I_1=[10,20],
]

[
e_2=\text{pan left},\quad I_2=[35,45].
]

你当前的线性边策略按开始时间排序，每个后续 event 只连接前一个 event，可能得到：

```text
e0 overlap e1
e1 then e2
```

这只能说明 pan-left 晚于 pan-right，却丢失了一个重要事实：**e2 也发生在持续的 dolly-in 期间**。

interval-aware deterministic planner 可以直接生成：

```json
{
  "clauses": [
    {
      "event_ids": ["e0"],
      "fact": "the camera dollies in throughout the shot"
    },
    {
      "event_ids": ["e1", "e2"],
      "fact": "it pans right and later pans left while the dolly-in continues"
    }
  ]
}
```

Qwen只需要把这两条事实自然化，而不用自己理解数值区间。

推荐的最小关系集合是：

```text
then
overlap
during
reverses
```

其中：

* `during`：短事件大部分或全部位于一个长事件内部；
* `overlap`：两者部分重叠，但不存在明显包含关系；
* `then`：前一个结束后，后一个才开始；
* `reverses`：同轴、反方向且时间上直接或近直接衔接。

当前“最多3个 event、最多2条线性边”在嵌套场景中不够。若最终文本预算为 (K\le6)，对被选事件临时计算完整 pairwise interval relation 最多也只有：

[
\binom{6}{2}=15
]

对关系，计算成本和存储成本都不是问题。没有必要为了避免完整 atomic graph 的 (O(N^2)) 膨胀，连 bounded packet 中的必要关系也强制压成链。完整 atomic graph仍然只存 interval；只有 selected packet在 planner 中即时计算关系即可。

不推荐 Qwen 直接读取 interval，主要不是因为它“绝对不能理解数字”，而是因为这会让 Qwen同时承担四个不该由它承担的职责：

1. 判断 interval 是包含、重叠还是先后；
2. 识别哪个长事件持续贯穿其他事件；
3. 决定哪些事件值得保留；
4. 把数值时间关系转换成 “throughout / while / then / later” 等语义。

这会重新破坏当前最重要的原则：**LLM 不决定几何真值。** Event‑T2M 的 LLM 操作对象是自然语言句子，而不是六轴数值 interval；即使在自然语言事件分解上，论文人工复核的正确率也是 93.3%，不是可以视为确定性几何标注的 100%。([arXiv][1])

因此 Qwen 可以接收 deterministic clause plan，例如：

```json
{
  "required_clauses": [
    "The camera dollies in throughout the shot.",
    "A right pan is followed by a left pan while the dolly-in continues."
  ]
}
```

而不直接接收：

```json
{
  "e0": [0, 60],
  "e1": [10, 20],
  "e2": [35, 45]
}
```

后者可以作为非 canonical 诊断实验，但不适合作为正式标注链。

**4. 目前方案还涉及 step 吗？长序列是否已经得到妥善处理？**

仍然涉及 step，而且应当保留。当前每条轨迹在 stride 4 后最多有 63 个 pose、62 个相邻 step。每个 step 都提供六轴 rate，H0/H1 的 `2 enter / 2 exit / 1 gap` 也都是以 step 为单位。

正确的层级是：

[
\text{step-level signal}
\rightarrow
\text{axis interval}
\rightarrow
\text{geometry event}
\rightarrow
\text{text event}.
]

step 不应被发送给 Qwen，但也不能被删除，因为它仍负责：

* 事件的起止位置；
* 短 gap 合并；
* 方向反转；
* 持续时间；
* net/path amplitude；
* sign consistency；
* 长序列中的事件边界审计。

当前方案对长序列的处理只能说 **几何层基本妥善，语言层尚未闭合**。

几何层没有裁剪 62 steps，完整 atomic event graph 也不截断，所以不会因为序列长而直接丢轨迹事实。这一部分合理。

但语言层固定 top‑3 还没有证明足够。v2-pre 的 100K 统计中，平均每条有 8.42 个 axis events、6.51 个 required events。虽然后续的 salience、同轴合并和跨轴归并会降低数量，但在得到新分布之前，不能假设 3 个文本事件足以覆盖大多数样本。

因此需要正式统计四个数量：

[
K_{\mathrm{axis}}
=================

\text{同轴归并后的atomic axis event数},
]

[
K_{\mathrm{geom}}
=================

\text{跨轴共时归并后的完整Camera geometry event数},
]

[
K_{\mathrm{salient}}
====================

\text{值得进入caption的geometry event数},
]

[
K_{\mathrm{text}}
=================

\text{实际写入short的event数}.
]

同时按 `N_step` 分桶报告：

[
K_{\mathrm{axis}},\quad
K_{\mathrm{geom}},\quad
K_{\mathrm{salient}},\quad
\text{overflow rate}.
]

例如至少分：

```text
1–20 steps
21–40 steps
41–50 steps
51–62 steps
```

若长序列的 (K_{\mathrm{axis}}) 随 step 数近似线性增长，但 (K_{\mathrm{geom}}) 和 (K_{\mathrm{salient}}) 没有对应增长，说明主要是 detector碎片化；若三者都增长，则确实存在复杂 Camera sequence，不能靠 top‑3 静默压缩。

跨轴归并也不能把任意 overlap都合成一个 event。推荐：

* start/end 都接近、持续时间也相近的多轴动作，归为一个 compound geometry event，例如 `dolly-in + pan-right`；
* 短 pan嵌套在长 dolly中，不合并，保留为 `during`；
* 不把 `truck + pan` 自动命名成 orbit，不把某种 Camera组合自动命名成 follow，因为 orbit/follow需要目标或 Human 语义，超出 Paper A 的 extrinsics6 范围。

所以长序列是否真正解决，要等 (K_{\mathrm{geom}}) 和 (K_{\mathrm{salient}}) 的全训练集直方图出来之后再判断。现在只能说“没有在 step 层截断”，不能说“文本层已经完整覆盖”。

**5. Event‑T2M 参考建议哪些应采纳，哪些需要修正？**

你给出的代码判断基本正确。我核对了官方仓库当前公开实现：`encode_decomposed_with_padding` 的默认和实际调用上限都是 `max_len=11`，训练和采样都显式传入 11；代码分配长度为 11 的 tensor 后直接执行 `[:L] = embedding[:L]`，没有截断逻辑。若 (L>11)，按这段实现会发生 shape 不匹配，而不是优雅截断。数据预处理则把 LLM 输出的所有 decomposed lines全部加入列表，没有过滤 `event_count > 11` 的规则。

论文层面只把 HumanML3D-E 分成至少2、至少3、至少4个事件的难度子集；这表示“4及以上是高复杂度评测区间”，不是最大事件数。论文还展示了一个包含7个事件的定性样本，因此论文显然没有把4定义为 event上限；与此同时，论文和正文没有解释代码中11的来源。([arXiv][1])

所以 Event‑T2M 对 Pulp 最有价值的启发有三个：

第一，**事件应该按时序语义单元归并，而不是按 primitive 数量机械计数。** 同一阶段同时发生的动作可以组成一个 compound event。这一点可以用于把 camera 的共时 dolly + pan合为一个 geometry event。Event‑T2M 的 event-aware prompt明确把同一时刻同步执行的一组动作作为单一 event，并且其人评显示 event-aware segmentation 与人工划分接近、优于 verb-aware划分。([arXiv][1])

第二，**必须区分 geometry event容量和 text event容量。** 这与你给出的：

[
K_{\mathrm{axis}}
\rightarrow
K_{\mathrm{geom}}
\rightarrow
K_{\mathrm{text}}
]

完全一致。我建议再补一个 (K_{\mathrm{salient}})，得到：

[
K_{\mathrm{axis}}
\rightarrow
K_{\mathrm{geom}}
\rightarrow
K_{\mathrm{salient}}
\rightarrow
K_{\mathrm{text}}.
]

第三，**具体上限不能继承 Event‑T2M。** `4` 是其评测复杂度门槛，`11` 是未经论文解释的实现容量，都不是 Pulp caption预算的依据。

你给出的 97% 和 98% gate思路可以保留，但公式需要调整。文本上限应主要依据 (K_{\mathrm{salient}})，而不是完整 (K_{\mathrm{geom}})，因为 present但不显著的微调本来就不需要进入 short caption。建议比较：

[
K_{\mathrm{text,max}}\in{3,4,5,6},
]

选择满足下列条件的最小值：

[
\Pr
\left(
K_{\mathrm{salient}}
\le
K_{\mathrm{text,max}}
\right)
\ge0.97.
]

对于被接受为 canonical 的样本，应要求：

[
E_{\mathrm{text}}
=================

E_{\mathrm{salient}},
]

即 **所有 salient geometry events 都被文本覆盖**，而不是 top‑(K) 后静默遗漏。直接方向反转也必须完整保留。

你提出的显著度覆盖率：

[
C_i(K)
======

\frac{
\sum_{e\in E_{\mathrm{text}}}S(e)
}{
\sum_{e\in E_{\mathrm{salient}}}S(e)+\epsilon
}
]

仍然有用，但更适合作为 overflow诊断，而不是允许 canonical样本遗漏事实的主要通行证。单纯要求全局总和达到98%，可能掩盖少数复杂样本后半段事件被全部漏掉。建议报告：

[
\Pr(C_i(K)=1),
\qquad
\Pr(C_i(K)\ge0.98),
]

并按长度、compound、reversal strata分层。

超过上限的样本不要只保留前 (K) 个，也不要按 top‑(K) 仍写成 canonical。处理顺序应是：

1. 同轴、同方向、短 gap interval合并；
2. 跨轴、近共时且边界接近的动作合为 compound geometry event；
3. 保留 nested关系，不错误合并；
4. 若 (K_{\mathrm{salient}}>K_{\mathrm{text,max}})，标记：

```text
caption_budget_status = overflow_abstain
canonical_stage2_eligible = false
```

完整 geometry graph继续保留。若 overflow不超过约3%，162,760条数据中隔离这部分复杂尾部通常比强行写成不完整短文本更可靠；若 overflow明显超过3%，再从4、5、6中提高预算，或者检查 H0/H1 与跨轴归并是否过度碎片化，而不是直接采用11。

基于这些结论，当前 v2 最推荐的主链应改为：

[
\boxed{
\begin{aligned}
&\text{strict-stride six-axis steps}\
\rightarrow;&
\text{H0/H1 axis-wise present intervals}\
\rightarrow;&
\text{same-axis temporal merging}\
\rightarrow;&
\text{cross-axis co-temporal geometry grouping}\
\rightarrow;&
\text{segment salience}\
\rightarrow;&
\text{calibrated }K_{\mathrm{text,max}}\in{3,4,5,6}\
\rightarrow;&
\text{interval-aware deterministic clause plan}\
\rightarrow;&
\text{Qwen three-short surface realization}\
\rightarrow;&
\text{count/relation reparse and fallback}.
\end{aligned}
}
]

对应 schema 建议新增：

```text
camera_motion_axis_events_full
camera_motion_geometry_events
axis_event_count
geometry_event_count
salient_geometry_event_count
caption_event_count
caption_budget_status
caption_salience_coverage
```

并把当前固定字段：

```text
max_caption_events = 3
```

改成：

```text
max_caption_events_candidate = [3, 4, 5, 6]
max_caption_events = pending_full_train_geometry_event_calibration
```

最终判断是：**Event‑T2M 支持你引入“时序 Camera 几何事件”这一中间层，也支持反对按六轴 primitive机械计数；但它不支持把上限直接改成4或11。当前 top‑3 应退回候选，先得到 (K_{\mathrm{axis}})、(K_{\mathrm{geom}})、(K_{\mathrm{salient}}) 的全训练集分布。** 在此之前，长序列只是在数值层未被截断，尚不能认为已经在文本层得到妥善处理。
