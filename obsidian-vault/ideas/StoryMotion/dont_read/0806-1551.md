结论很明确：**这次 8.2% 的结果不能主要归因于 Qwen3-4B-Instruct 的能力上限，主因是 authoritative fact packet、prompt 语法合同和 parser/gate 三层处理不当；但它也暴露出一个真实的模型边界——让 4B 模型在一次自由生成中同时产出三条不同、语法自然、逐实例保真、逐关系保真的文本，尤其包含 4–6 个动作和多条 `during/overlap` 时，不具备可生产使用的可靠性。**

附件只覆盖从已完成 40K provisional population 中分层抽取的 1K smoke，并没有包含 sealed human review，也没有覆盖未来 60K。因此下面的判断适用于这 1K 的语言链与其上游 fact packet，不能直接外推为完整 162,760 条数据的最终质量。

**首先，8.2% 把多个问题压成了一个数字，严重低估了“单句生成能力”，也无法单独衡量模型上限。** 我重新拆解 1K records 后得到：

* 3000 条候选短句中，1272 条通过当前 fact reparser，单句通过率是 **42.4%**；
* 337 个样本三句全失败，236 个有一句通过，245 个有两句通过，182 个三句的 fact gate 都通过；
* 这 182 个样本中，又有 92 个因为三句重复、8 个因为额外的 subject gate 被拒绝，最后才剩 82 个，即 **8.2%**；
* 换言之，至少有一条候选通过当前 fact gate 的样本其实是 **663/1000=66.3%**，而不是 8.2%。

但这不意味着真实可用率有 66.3%，因为当前 parser 同时存在 false accept 和 false reject。它只是说明：**8.2% 更多反映“三句必须同时正确、必须不同、必须通过额外语法门”的组合成功率，而不是 Qwen 单次理解 Camera fact 的能力。**

更有解释力的是位置和风格分解。第一、第二、第三条输出的单句通过率分别为 **49.9%、50.2%、27.1%**。三种 style 已经按 sample ID 轮换，所以第三条明显变差不能归因于某一种固定风格，而是一次生成三个精确改写时出现了明显的后位退化、跨候选干扰或约束疲劳。按实际 style 统计，`direct_finite` 为 50.0%，`cinematic_nominal` 为 45.2%，`compact_mixed` 只有 32.0%。因此 `compact_mixed` 本身就在增加失败，而单次 triplet generation 又进一步放大了它。

**最严重的根因实际上发生在 Qwen 之前：当前 relation graph 不是严格的时间关系图。** 1K fact packets 中共有 1692 条关系边：

* `during`：902 条；
* `overlap`：599 条；
* `then`：191 条；
* `reverses`：0 条。

所有关系边都只连接 event list 中相邻的两个事件，且每个 (K)-fact 样本固定有 (K-1) 条边。这说明它本质上是一个**线性链**，不是从完整 interval graph 中提取的必要关系。

更关键的是，全部 902 条 `during` 都来自“两个 excursion 属于同一个 `camera_motion_phase`”，而不是来自严格的 interval containment。用 record 中的真实 `start_step/end_step` 复核后：

[
\begin{array}{l|r|r}
\text{实际区间关系} & \text{数量} & \text{占 during 比例}\
\hline
\text{source 包含 target} & 481 & 53.3%\
\text{区间完全相同} & 247 & 27.4%\
\text{target 包含 source} & 97 & 10.8%\
\text{仅部分重叠} & 48 & 5.3%\
\text{source 已结束后 target 才开始} & 29 & 3.2%
\end{array}
]

因此当前 `during` 实际表达的是 `same_phase`，不是一个方向明确的自然语言关系。Qwen 不可能稳定保持一个尚未被严格定义的关系。具体例子是 `2016_ZMZxDJb5V8o_00010_001_a`：truck-left 和 pan-right 都覆盖完整 `[0,13]`，却被标成 `truck left during pan right`。更合理的关系应是 `coextensive/simultaneous`。`2017_JOzVMqp3vMc_00005_000_a` 的六个动作全部属于同一个 phase，于是被展开为五条连续的 `during`；但最后的 tilt-up `[3,5]` 与 tilt-down `[6,11]` 实际是前后关系，不是 during。

`then` 也有 6/191 条实际是 source interval 包含 target，例如 `2014_vKsWNzKjVEk_00000_000_a` 的 tilt-down `[2,20]` 与 pan-right `[6,11]` 被标成 `then`。这进一步说明关系是从 phase/线性排序的启发式产生，而非直接由 interval 语义确定。

与此同时，parser 根本没有区分 `during` 与 `overlap`。二者都只检查同一个 `OVERLAP_PATTERN`，即文本中有没有 `while/during/overlap/simultaneously` 等词。它既不检查 containment 方向，也不验证 relation type。因此当前所谓“精确保留 identical relation graph”在实现上并不成立：输入关系自身含混，输出 gate 又把两类关系视为同一种。

**第二层根因是 v2p5 prompt 内部存在直接冲突。** `cinematic_nominal` 要求使用 noun phrase，但系统又要求每条 caption 必须以 `The camera` 开始，却没有给 noun phrase 配套的 carrier grammar，例如 `performs/makes/executes`。结果模型自然生成：

* `2011_ifjmJHoUzc8_00020_000_a`：`The camera a counterclockwise roll.`
* 多个 dolly-in 样本：`The camera a dolly in.`
* `2015_9RfC79nFT3U_00004_002_a`：`A pan to the left occurs.`

这不是复杂推理失败，而是 prompt 要求“以 The camera 开头”与“直接使用 noun phrase”之间没有闭合语法。

`compact_mixed` 更危险，因为它允许 finite 与 nominal 自由混合，却仍要求每个 event 恰好出现一次。模型经常先列动作，再为了说明 relation 用 noun phrase复述一次，导致重复。例如 `2015_-CKzCdneg04_00011_000_a` 中，每个动作先以 finite form 出现，随后又以 noun form 出现，parser 正确地判成 `unplanned_event_instance`。这不是模型没看到动作，而是“action list + separate relation list”的输入结构诱导它二次陈述动作。

Dolly 还暴露了非常典型的 morphology failure。虽然 allowed form 明确给出 `dollies in/out`，模型大量生成 `dollys in/out`。在单事实样本中，dolly-in 的单句通过率只有 **12.7%**，而 tilt-down、tilt-up、truck-left 分别约为 92.6%、88.6%、93.8%。这说明把 action inflection交给模型是不必要且高风险的；`dollies` 应当是不可修改的确定性字符串。

**第三层是 parser/gate 本身既过严又不完整。** 最多的失败原因是 1025 次 `overlap_marker_missing`，但其中相当一部分是 marker placement 的 false reject，而不是关系确实丢失。例如：

* `2016_ZMZxDJb5V8o_00010_001_a`：`The camera trucks left. The camera pans right during that action.`
  自然语言已经表达了同时关系，但 `during` 位于第二个动作 mention 之后，不在两个 mention 的字符区间内，因此被拒绝。
* `2011_S2fxN2JZ81A_00009_000_a`：`The camera pedestals up and tilts down overlapping.`
  `overlapping` 位于第二个动作之后，同样被判缺失。
* `The camera dollies out while it pans right, trucks left, rolls clockwise...`
  一个 `while` 可以自然地支配后续并列动作，但当前 gate 要求每条相邻边之间都单独出现 marker，于是会把自然协调句判错。

反过来，gate 也会 false accept。`COMPLETE_CAMERA_SENTENCE_PATTERN` 只检查整段文字是否以 `The camera` 开头、以标点结束，所以 `The camera a dolly in.` 能通过 fact reparse。`MISSING_SUBJECT_AFTER_WHILE` 只检查 `while pans/trucks/...`，无法识别 `then pedestals up`、noun fragment 或第二句无主体。Prompt 又说只能使用 `allowed_surface_forms`，但 parser 实际接受了更宽的 regex，例如 accepted case `2014_E9yuGEux_OI_00027_001_a` 中的 `The camera's pedestal moves down.` 并不属于提供的两个 allowed forms。也就是说，这个“closed world”合同并没有被 gate 真正执行。

还有一个未被这次 smoke 测到的缺口：虽然代码和 handoff 都声称支持 `reverses`，但 1K 中一条 `reverses` 都没有。像 `2017_uwkMYWXtFu0_00014_000_a` 的 counterclockwise roll → clockwise roll 仍被标为普通 `then`。因此本次实验无法证明 reversal realization 或 parser 已经正确。

**Qwen3-4B 确实存在能力边界，但当前实验不能把它干净量出来。** 在同一 1K 上，v2p4 给模型三条完整 deterministic drafts，triplet acceptance 为约 49.3%；v2p5 去掉 scaffolding 后降到 8.2%。单事实的 v2p4 单句 fact pass 是 100%，v2p5 只有 66.9%。这足以证明 scaffolding 与 prompt 设计是主要变量。

但随着事实数增加，v2p5 的单句通过率仍从 1 fact 的 66.9% 降到 4–6 facts的约 25%–28%；`none/then/during/overlap` 条件下分别约为 66.9%、54.5%、34.9%、21.1%。因此，让 4B 模型自由完成多事件、多关系、三版本、exact-count、exact-order、exact-relation 的联合任务，确实超过了它的可靠工作区间。更准确的结论是：

[
\boxed{
\text{Qwen3-4B 可以做受保护的表面改写，不能承担 Camera fact planning 与自由结构实现。}
}
]

运行环境本身没有明显的模型加载错误。Qwen3-4B-Instruct-2507 是非思考版，官方示例使用相同的 chat-template 调用方式；官方要求 Transformers 至少为 4.51.0，本次使用 4.51.3，因而没有证据表明这是版本或 thinking-mode 配置错误。官方推荐一般生成使用 sampling，而本次采用 greedy；greedy 可能加重重复，但不能解释 relation truth 含混、nominal grammar 冲突和 parser scope错误。([GitHub][1])

输入长度也不是问题：本次 input 只有约 374–675 tokens。只有 12 个输出达到 160-token 上限，11 个 JSON parse failure基本都来自这些截断样本。把 `max_new_tokens` 提高到 256 可以修复约 1% 的格式失败，但无法改变主体结论。

接下来的正确路线不是马上换更大的 Qwen，也不是直接实现 handoff 中的 placeholder v2p6。**必须先修 authoritative fact packet，否则 placeholder 只会更可靠地复述含混关系。**

第一步应取消当前相邻 event chain，直接以 phase hierarchy 和 interval 为语言事实。建议冻结下面的结构：

```json
{
  "phases": [
    {
      "phase_id": "p0",
      "spine_event_id": "x0",
      "members": [
        {"event_id": "x0", "role": "primary"},
        {"event_id": "x1", "role": "co_primary", "relation_to_spine": "coextensive"},
        {"event_id": "x2", "role": "modifier", "relation_to_spine": "during"}
      ]
    }
  ],
  "phase_order": [
    {"source": "p0", "target": "p1", "type": "then"}
  ],
  "event_transitions": [
    {"source": "x3", "target": "x4", "type": "reverses"}
  ]
}
```

关系必须直接由 interval 决定，而不是由 `same phase` 决定：

[
\begin{aligned}
\texttt{coextensive}:&
\quad |s_i-s_j|\le\delta_s,\ |e_i-e_j|\le\delta_e,\
\texttt{during(child,parent)}:&
\quad s_p\le s_c,\ e_c\le e_p,\ \text{且非近似同长},\
\texttt{partial_overlap}:&
\quad I_i\cap I_j\neq\varnothing,\ \text{且互不包含},\
\texttt{then}:&
\quad e_i<s_j,\
\texttt{reverses}:&
\quad \text{同轴、反方向且gap不超过冻结门槛}.
\end{aligned}
]

`same_phase` 可以继续作为组织信息，但不能直接翻译成 `during`。完整 packet 也不应强制为 (K-1) 条相邻边；长 dolly 包含两个不相邻 pan 时，需要 phase spine 与 modifier关系，而不是线性链。

第二步应把 **canonical correction** 与 **Qwen enrichment** 完全分开。真正的 canonical text应由确定性 grammar生成：

```text
camera_text_canonical_template
```

Qwen输出只能叫：

```text
camera_text_enriched_shorts
```

对于 12 个 directed primitives 和少数关系，完全可以建立一个小型、人工审计过的 template grammar。例如：

```text
single:
The camera {V0}.
The camera performs {N0}.
The camera makes {N0}.

coextensive:
The camera {V0} while it {V1}.
The camera {V0} and simultaneously {V1}.

during:
While the camera {VPARENT}, it {VCHILD}.
During {NPARENT}, the camera {VCHILD}.

then:
The camera {V0}, then it {V1}.

reverses:
The camera {V0}, then reverses and {V1}.
```

所有 `dollies/trucks/pans/...` 的词形都由程序写入，模型没有机会生成 `dollys`。只要 template grammar经过自检，T1 的 canonical one-short 就不需要 Qwen，Paper A 的 Camera text correction也不会被 enrichment 阻塞。

第三步若仍然希望保留 Qwen，最安全的角色不是生成 caption，而是**选择或改写带不可变 placeholder 的语法模板**。例如程序先给出：

```text
The camera [[A0]] while it [[A1]], then it [[A2]].
```

Qwen只允许返回包含相同 placeholder、相同顺序和相同 relation slots的模板：

```json
[
  "The camera [[A0]] while it [[A1]], then it [[A2]].",
  "While the camera [[A0]], it also [[A1]]; afterward, it [[A2]].",
  "The camera [[A0]] together with [[A1]], before it [[A2]]."
]
```

在验证 placeholder multiset、顺序和 relation template ID 后，再由程序把 `[[A0]]` 替换为固定的 `trucks right`。更保守且更推荐的方案是让 Qwen只返回三个已枚举的 `template_id`，甚至直接按 sample hash从模板库中确定性选择三个，不再逐样本调用 LLM。

当前三种 style slot应删除。特别是：

* 删除 `compact_mixed`；
* nominal form只能由确定性 carrier verb模板产生；
* 不再要求模型在一个 pass 中自由实现三种不同句法；
* 若仍需模型生成，可一条 caption一次调用，或一次只选择三个 template IDs。

第四步要把 parser从“自然语言理解器”降级为“模板合同验证器”。在 placeholder替换前，hard gate只检查：

```text
placeholder multiset exact
placeholder occurrence = 1
template relation IDs exact
placeholder order compatible
no unknown placeholder
```

替换后再做有限 grammar sanity check。当前基于 mention 字符位置、marker是否出现在两 mention之间的 regex不应再承担 relation truth gate，只能作为诊断。`during`、`overlap` 和 `coextensive` 必须分别验证，不能共享一个 pattern。

建议用同一批 1K sample IDs做以下分层实验，而不是立即跑剩余 60K：

[
\begin{array}{ll}
A:& \text{当前 packet + 当前 v2p5，用作历史失败基线};\
B:& \text{修正后的 phase/interval packet + deterministic canonical};\
C:& \text{修正 packet + immutable-placeholder Qwen3-4B};\
D:& \text{可选：同一 C prompt + 更大模型}.
\end{array}
]

B 必须满足 deterministic fact/relation self-check 100%。C 在扩量前建议至少满足：

* JSON/template parse ≥99.5%；
* placeholder multiset与relation template一致率在被选输出上为100%；
* Qwen candidate whole-triplet接受率至少80%，否则它相对于 deterministic template没有足够增值；
* 每个 fact-count strata分别报告，6-fact不能被总体平均掩盖；
* 512 人工审核中，语法可直接训练通过率至少95%；
* hallucinated Camera primitive、方向和未支持属性为0；
* 三条中至少两条归一化后不同的样本比例单独报告，但不能为了多样性牺牲事实。

只有在 packet、template和gate全部修正后，Qwen3-4B 仍在 placeholder保持或语法实现上显著落后于更大模型，才能把剩余失败归因于模型容量。当前证据只能支持：

[
\boxed{
\text{主因：relation/grammar/gate 处理不当}
}
]

[
\boxed{
\text{次因：4B 不适合自由完成三条复杂 exact rewrite}
}
]

因此当前最优裁决是：继续禁止 canonical write 和剩余 60K；先重构 relation truth与 deterministic canonical grammar；Paper A 先以 `raw → deterministic canonical one-short` 完成 correction，三条 Qwen enrichment降级为可独立失败的 T2，而不是让 Qwen是否成功决定整个 Camera text contribution。
