整体思路是合理的，而且已经从“照搬 TriMotion 阈值”升级成了一个真正针对 Pulp 分布的、可审计的 geometry-grounded recaptioning pipeline。尤其正确的决策包括：只在 162,760 条训练数据上统计阈值、同时检查 step-balanced 与 sample-balanced 稳定性、把旧 512 条结果全部降级为 noncanonical、保留 raw text 但不把它当真值、先冻结规则再调用 LLM，以及放弃固定 21 poses、20 steps 和人为四阶段压缩。TriMotion 的论文和固定 commit `5b203a8` 确实使用 81 帧中 stride 4 得到 21 个 pose、首帧相对 RDF、Euler `xyz`、固定 `0.02 m / 0.3°` 和 ratio 5，并逐 step 输出时间序列；其官方流程没有“四阶段压缩”，最后为每条轨迹生成一条 short 和一条 long caption。([arXiv][1])

不过，现在还不能直接生成 canonical text。当前还差的不是简单补几个超参数，而是要把“数值运动存在”“连续运动事件”“值得写进 caption 的运动”分成三个层级。你目前的 K3 是 **step-level rate distribution**，而 caption 是 **segment-level semantic decision**。如果直接让 K3 upper 决定 present、raw-text anchor 决定 salient，会漏掉持续低速但累计明显的运动，也会把很短的高频尖峰错误写进 caption。

建议最终冻结成以下语义：

[
\text{OFF}
\rightarrow
\text{PRESENT}
\rightarrow
\text{CAPTION_SALIENT},
]

其中 `OFF/PRESENT` 由六轴 rate、hysteresis 和持续时间决定；`CAPTION_SALIENT` 再由 segment 的持续时间、累计幅度、单调性和典型速度决定。中间的 weak 区间不删除样本，也不强行赋文本标签，只保存在 event graph 中并设置 `caption_mask=0`。

你目前的 K3 结果支持这种三层设计。step-balanced 与 sample-balanced 的两个分界非常接近，说明阈值不是明显由长序列重复 step 主导，这是好信号。但 raw-text translation anchor 大约是 K3 upper 的 2.3–4.6 倍，恰好说明“运动已存在”和“用户会在 caption 中提及”不是同一阈值。另一方面，Pulp 论文明确说明其 Camera caption 是先进行 motion tagging，再交给 LLM 生成，所以 native tag 和 raw text 本质上来自同一条弱标注链，不能作为相互独立的真值。([arXiv][2])

Primitive 坐标基建议按下面的方式一次性冻结。存储和跨模态对齐仍采用 C1REL：

[
\widetilde T_t=T_1^{-1}T_t,
]

但六轴 primitive 不要直接对 C1REL 的平移坐标做前后差分，而应从相邻 Camera frame 的 body-local transform 提取：

[
\Delta T_t
==========

# \widetilde T_t^{-1}\widetilde T_{t+1}

# T_t^{-1}T_{t+1}

\begin{bmatrix}
\Delta R_t & \Delta p_t\
0 & 1
\end{bmatrix}.
]

然后定义：

[
v_t=\frac{\Delta p_t}{\Delta t},
\qquad
\omega_t=
\frac{\operatorname{Log}(\Delta R_t)^\vee}{\Delta t},
\qquad
\Delta t=\frac{4}{25}=0.16\text{ s}.
]

这意味着：C1REL 负责消除任意 world coordinate gauge，body-local RDF increment 负责解释“Camera 此刻向自身右侧 truck、沿自身视轴 dolly、绕自身轴 pan/tilt/roll”。两者并不冲突，因为 body-local increment 可以直接从 C1REL 计算。相比直接在首帧坐标轴中计算 translation difference，这种定义在 Camera 已经发生较大 pan 之后仍保持 primitive 语义正确。例如 Camera 先旋转 90°、再沿当前视轴前进，body-local 仍会标为 dolly，而首帧轴差分可能把它标成 truck。

Rotation 不建议继续沿用 Euler `xyz + unwrap` 作为权威标签。TriMotion 的固定实现确实如此，但这会受到 Euler order、gimbal coupling 和多轴旋转分解的影响。([arXiv][1]) 更稳妥的合同是直接使用相邻旋转的 Lie algebra rotation vector：

[
\omega_t
========

\operatorname{Log}(R_t^\top R_{t+1})^\vee/\Delta t.
]

在 RDF 右手系下，最终通过六个纯轴 synthetic unit tests冻结符号：

[
+\omega_x=\text{Tilt Up},\qquad
+\omega_y=\text{Pan Right},\qquad
+\omega_z=\text{Roll CW}.
]

Euler 角可以留在 Gradio 中帮助人看曲线，但不再生成 canonical primitive，也不再需要 unwrap 合同。若单个 0.16 秒 step 的相对旋转接近或超过 (180^\circ)，更合理的处理是标记 geometry anomaly，而不是试图 unwrap。

Hysteresis 建议先使用以下候选，而不是直接冻结 K3 lower/upper 为一对：

[
T_{\rm noise}=T_{\rm K3,lower},
\qquad
T_{\rm enter}=T_{\rm K3,upper},
]

[
T_{\rm exit}^{(0)}
==================

\sqrt{T_{\rm K3,lower}T_{\rm K3,upper}}.
]

对应的首轮 (T_{\rm exit}^{(0)}) 大致为：truck (0.00327) m/s、pedestal (0.00188) m/s、dolly (0.00543) m/s、tilt (0.172^\circ/s)、pan (0.237^\circ/s)、roll (0.192^\circ/s)。这些数值只能作为 calibration sweep 中心，不应直接宣布为最终 rule。进入事件要求至少连续两个 step 超过 `T_enter`；退出要求至少连续两个 step 低于 `T_exit`。位于 noise floor 与 enter 之间的 step 可维持已有事件，但不能独立启动事件。

之所以不建议直接取 `T_off=K3 lower`，是因为这会让一个已启动的 truck 事件在速度下降到 (10^{-3}) m/s 量级后仍长时间保持 active，容易把“明显移动—停顿—再次移动”错误合并为一个长事件。合理的 `T_exit` 应明显低于 `T_enter`，但不能贴近数值噪声。

Caption salience 不应只由 raw-text rate anchor决定。建议一个 event 满足下面任一条件才进入 canonical caption：

[
\operatorname{median}*{t\in e}|v*{a,t}|
\ge T_{{\rm salient},a}
\quad\land\quad
D_e\ge0.48\text{ s},
]

或者对于持续低速运动：

[
D_e\ge0.8\text{ s},
\qquad
A_e^{\rm net}\ge A_{{\rm salient},a},
\qquad
\rho_e=
\frac{|A_e^{\rm net}|}
{\sum_{t\in e}|v_{a,t}|\Delta t}
\ge0.8.
]

这里 (A_e^{\rm net}) 是有符号累计位移，(\rho_e) 是单调性。持续向一个方向缓慢移动时 (\rho_e) 接近 1；左右抖动或来回漂移时，路径长度很大但净位移很小，(\rho_e) 会下降。`T_salient` 可以围绕 raw-text anchor 做 (0.75/1.0/1.25) 倍 sweep，但最终应由人工确认的 segment 标签选择，而不是由 raw text 自己决定。rotation 当前没有可靠 raw/native anchor，因此 tilt、pan、roll 的 salience 必须单独人工校准，不能套用 translation 的比例。

Dominance 建议从 detector 中删除。每个 axis 先独立形成 event：

```text
primitive
direction
start_step / end_step
median_rate / peak_rate
net_amplitude / path_amplitude
duration
present_confidence
salient_confidence
```

之后再根据 interval overlap 构建关系。可以先冻结：

[
r_{ij}
======

\frac{|I_i\cap I_j|}
{\min(|I_i|,|I_j|)}.
]

当 (r_{ij}\ge0.6) 时标为 simultaneous；当 (r_{ij}\le0.2) 时标为 sequential；中间为 partial-overlap，long caption 可以写成“先开始 A，随后 B 加入，同时继续 A”。这样不会把所有关系强行压成 `while` 或 `then`。同一 primitive、同一方向、间隔不超过一个 step 时合并；相反方向绝不合并，而是生成 `reversal` edge。你风险池中的 5,784 条反转或多阶段文本正适合专门校准这一部分，而不是一律当错误。

FOV 建议在 v1 前明确决策，而不是默认删除。由于你已经有逐帧 intrinsics，先统计：

[
f_t=\sqrt{f_{x,t}f_{y,t}},
\qquad
z_t=\frac{d\log f_t}{dt}.
]

若 (f_x,f_y) 变化方向一致、principal point 与 aspect ratio 正常，并且有效变化样本具有足够规模，则：

[
z_t>0 \Rightarrow \text{Zoom In},
\qquad
z_t<0 \Rightarrow \text{Zoom Out}.
]

使用 log focal length 能避免不同初始焦距下同样百分比 zoom 的尺度差异。Dolly 继续由 extrinsic 的 local (z) translation定义，两者可以形成 dolly-zoom compound。若 intrinsics 大部分恒定或变化噪声不可靠，就不纳入 canonical v1，并把所有 raw zoom caption 标记为 `raw_attribute_unsupported`。`orbit` 不应进入 Paper A 的 camera-native ontology，因为 orbit 需要一个明确的旋转中心或目标主体；仅凭 Camera 自身 extrinsics通常不能唯一判断它是在围绕谁运动。Paper A只做 camera-native 无歧义化，而 Human-relative orientation、shot scale、look-at 和 event ownership继续归 DIRECT，这与两篇拆分边界一致。

Event graph 应成为最终数据真值，short 和 long 都只是 graph 的语言化结果。推荐 schema 至少包含：

```json
{
  "events": [
    {
      "event_id": "e0",
      "primitive": "dolly",
      "direction": "in",
      "start_step": 8,
      "end_step": 19,
      "duration_s": 1.92,
      "median_rate": 0.061,
      "net_amplitude": 0.118,
      "salient": true
    }
  ],
  "relations": [
    {
      "source": "e0",
      "target": "e1",
      "type": "partial_overlap"
    }
  ]
}
```

short caption 可以只保留所有 primary salient events，并省略 weak secondary component；long caption必须覆盖全部 salient event、方向、顺序、并行关系和反转。不要继续把“exactly 3–5 sentences”当硬合同，因为 Pulp 的 event 数量和序列长度可变；更稳妥的是动态 2–6 句或固定 token 上限。TriMotion 的 3–5 句要求是为其固定 21-keyframe symbolic input设计的，不能直接证明适合最长 62 step 的 Pulp 序列。([GitHub][3])

还建议先生成一个完全确定性的 template caption，再让 Qwen做自然语言 surface realization。例如：

```text
Deterministic:
The camera first dollies in. It then pans right while continuing to move forward.

Qwen surface:
The camera initially moves forward, then gradually begins panning to the right while maintaining the inward motion.
```

raw Pulp caption绝不能作为 Qwen 输入，否则会把 prompt contamination、错误 left/right 和 primitive 混用重新注入 canonical text。Qwen输出后必须重新解析，并检查：

[
\text{primitive set},
\quad
\text{direction},
\quad
\text{temporal order},
\quad
\text{simultaneous/sequential relation}.
]

建议让 Qwen 同时返回 `caption` 和隐藏的 `mentioned_event_ids`，然后用确定性 parser做独立核验。reparse 不通过时回退 deterministic template，而不是继续采样直到“看起来正确”。当前 parser 对 `pull-outs/push-ins` 的遗漏必须在任何 raw-text anchor 重算或错误统计前修复，并建立封闭词表单元测试；否则 parser failure会被错误归因于原 caption。

Mechanical QC 的定义是正确的，但应另建一层 `geometric-semantic QC`，不要混用名称。至少增加以下 metamorphic tests：

[
\operatorname{Graph}(T)
=======================

\operatorname{Graph}(GT)
]

对任意全局刚体变换 (G) 必须成立；时间反转后 event 顺序和方向必须按规则翻转；六个纯轴 synthetic trajectory 必须逐项得到正确标签；由 body-local increments重新积分回 trajectory 后应在数值容差内恢复原 C1REL；第一帧 C1REL 必须为 identity。这样可以直接验证这次修复真正消除了原来的 world coordinate branch，而不仅仅是换了一组经验阈值。

严格 stride 4 可以保留，因为 rate normalization已经统一了单位，并且最长仅 62 steps，适合 event graph处理。但在冻结前建议只做一次 stride 2 / stride 4 sensitivity，不需要重开完整阈值搜索。对一组 uniform + high-frequency 样本比较 high-confidence salient event 的 primitive、direction 和顺序；若一致率达到预注册门槛，例如 95%，就冻结 stride 4。若短事件系统性消失，则应在 stride 2 上检测、再压缩 event graph，而不是继续降低 stride 4 的 rate threshold。

人工审核建议分成 calibration 和 sealed audit。一个可执行规模是：约 1,200 条 calibration，覆盖六轴、正反方向、K3 lower附近、(T_{\rm exit})附近、K3 upper附近、raw anchor附近、短/长时长、compound、reversal 和最长序列；另保留约 1,000 条 sealed audit，其中一半 uniform random、一半 risk-stratified。首轮审核隐藏 raw text，只根据 Camera trajectory、局部坐标轴、六轴 rate curve 和候选 event interval判断；第二轮再显示 raw/canonical text做冲突分类，避免 raw text造成 anchoring bias。至少 20% 双人复核，并分别报告 primitive precision、direction precision、interval boundary agreement、simultaneous/sequential accuracy，而不是只给一句“caption acceptable”。

Gradio 中最重要的不是“数值距离分组”本身，而是同时显示：三维 Camera trail与每个关键帧 RDF axes、六轴 rate curves、`T_noise/T_exit/T_enter/T_salient`水平线、event interval色块、累计幅度和单调性、deterministic text、Qwen short/long、raw text及冲突原因。边界样本必须按“离阈值的归一化距离”采样：

[
\delta_{a,t}
============

\frac{|r_{a,t}|-T_a}{T_a},
]

而不是只采绝对速度相近的样本，因为六个轴的量纲和尺度不同。

最终建议把 pipeline 稍微修改为：

[
\boxed{
\text{C1REL normalization}
\rightarrow
\text{body-local RDF increments}
\rightarrow
\text{six-axis normalized rates}
\rightarrow
\text{hysteretic interval detection}
\rightarrow
\text{segment salience and cumulative rescue}
\rightarrow
\text{variable-length event graph}
\rightarrow
\text{deterministic canonical text}
\rightarrow
\text{Qwen short/long realization}
\rightarrow
\text{independent reparse + metamorphic QC}
}
]

在规则冻结前，真正的 hard blockers只剩五个：body-local sign unit tests、rotation-log实现、(T_{\rm exit})与segment salience的人工 calibration、FOV/zoom纳入决策、event graph/reparse合同。它们完成后即可生成 canonical text；不需要再重读 162,760 条原轨迹，也不需要扩大到新的聚类算法。Paper A 最终可以合理声称的不是“提出通用 Camera captioner”，而是：发现 Pulp 的 coordinate-gauge 与弱标签问题，建立适配长轨迹和多阶段运动的 geometry-grounded recaptioning contract，并通过 raw/canonical matched training证明修正改善 Camera text control。

这个方向合理，但建议不要把它实现成“对 62 个 step 的标签做简单相邻去重”，而应改成 **轴级事件合并 + 重叠关系压缩 + 语言层宏事件摘要**。核心原则是：完整六轴信号和事件边界永远保留，压缩只发生在送给 Qwen 的结构化表示上，不能为了减少 token 改动 stride 或丢失几何监督。

TriMotion 的原始条件较简单：81 帧经 stride 4 后只有 21 个 pose、20 个相邻 motion step，再将它们组织为 symbolic phases后生成一条 short 和一条 detailed description。Pulp 最长达到 62 step，因此不能假设同样的逐 step symbolic list仍能被 4B Qwen稳定完整复述。([arXiv][1])

你提出的“相同动作片段做时间块合并”应作为第一层压缩，但更准确地说，应在 **每个轴完成 hysteresis event detection 后合并 interval**，而不是直接合并六轴联合 step 标签。推荐表示分成三层：

[
\text{62-step six-axis signal}
\rightarrow
\text{axis-wise event graph}
\rightarrow
\text{caption macro graph}.
]

第一层始终保留，用于数值审计；第二层是 canonical 几何真值；第三层才是 Qwen 输入。这样即使语言描述有意省略了弱运动，仍能知道省略了什么，而不是数据本身被不可逆压缩。

具体来说，同一轴上的两个片段只有同时满足以下条件才合并：primitive 相同、方向相同、中间没有可信的反向运动、间隔不超过预注册的短 gap，并且合并后的累计运动没有被来回抖动抵消。初始可以设为 gap 不超过 1 step，即 (0.16) 秒；是否放宽到 2 step 再由人工边界样本校准。以下情况不能直接合并：

* `pan right → pan left`：必须保留 reversal；
* `dolly in → 明确静止 → dolly in`：保留为两次 burst，或在语言层标为 repeated motion；
* `truck right → truck right，但中间速度发生持续的数量级跳变`：可以保留一个父事件，但记录 speed regime change；
* 短暂跌入 (T_{\rm off}) 以下但整体方向和累计位移稳定：允许 gap bridging。

最重要的改进是：**同一主运动被其他轴动作临时叠加时，不要切成多个联合状态块。** 例如：

```text
step 0–15: Dolly In
step 16–28: Dolly In + Pan Right
step 29–61: Dolly In
```

不应压缩成三个平级 phase，而应表示为：

```json
{
  "events": [
    {"id": "e0", "motion": "dolly_in", "interval": [0, 61]},
    {"id": "e1", "motion": "pan_right", "interval": [16, 28]}
  ],
  "relations": [
    {"type": "during", "child": "e1", "parent": "e0"}
  ]
}
```

于是语言计划只需写：

> The camera dollies in throughout the shot, briefly adding a rightward pan around the middle.

这类 **长时间主运动 + 临时修饰运动** 的层级化表示，通常比对六轴联合状态做 run-length encoding压缩得更充分，也更符合自然语言组织方式。

在此基础上，还建议加入以下几类压缩。

第一类是 **速度轮廓压缩**。同一个 primitive 不必因为每几步速度略有变化而切段。每个事件只保存：

[
{\text{median rate},\text{peak rate},\text{net amplitude},
\text{duration},\text{speed profile}},
]

其中 `speed profile` 归纳为 `steady / accelerating / decelerating / pulse / variable`。例如连续 25 step 的 dolly-in 从弱到强，应压成一个 `dolly_in, accelerating` 事件，而不是十几个不同 magnitude 的 step。可以对事件内部 rate curve做最多一至两个 change point 的分段线性近似；只有变化持续至少 2 step、且明显不能由一个稳健趋势解释时，才增加新的 speed phase。

第二类是 **重复与往返宏事件**。非连续的相同动作不能伪装成一个连续 interval，但可以在 caption graph 中形成父节点：

```text
Pan Right → Stationary → Pan Right
```

压缩为：

```json
{
  "macro": "repeated_motion",
  "primitive": "pan_right",
  "children": ["e2", "e5"],
  "count": 2
}
```

而：

```text
Pan Right → Pan Left → Pan Right
```

可以形成 `alternating_pan` 或 `reversal_sequence`。long caption 写清顺序，short caption可以写成“the camera alternates its horizontal rotation”。所有子事件仍保留，因此不是丢失方向信息。

第三类是 **时间关系宏化**。建议 event graph 至少支持：

[
\texttt{before},\quad
\texttt{during},\quad
\texttt{overlap},\quad
\texttt{continues_through},\quad
\texttt{reverses},\quad
\texttt{repeats}.
]

例如三个 atomic block：

```text
Dolly In
Dolly In + Pan Right
Pan Right
```

可以被归纳为“dolly-in 先开始，随后 pan-right 加入；dolly结束后 pan继续”，而不是把每个 block 原样交给 Qwen。这类关系最好由确定性代码产生，不能让 Qwen自己从 62 行数值中推断。

第四类是 **salience 分层，而不是固定 top-K 删除**。建议维护三种状态：

```text
present_but_weak
caption_salient
must_preserve
```

其中 `must_preserve` 至少包括方向反转、首个和最后一个显著运动、主要 primitive 切换，以及独特但短暂的强运动。完整 event graph保留全部 `present` 事件；long caption覆盖全部 `caption_salient + must_preserve`；short caption只覆盖主导运动和最重要的转折。这样可以允许 short 是有意的摘要，同时 long 仍有明确的保真合同。Paper A 当前应保持 Camera-native caption 与后续 DIRECT 的 Human-centric program分离。

第五类是 **两级 deterministic planning**。不要把压缩后的 graph直接交给 Qwen并让它自由决定写什么，而应先由程序生成 sentence plan：

```json
{
  "overall": "persistent dolly in",
  "sentences": [
    {
      "event_ids": ["e0"],
      "content": "camera dollies in from start to end",
      "required": true
    },
    {
      "event_ids": ["e1", "e2"],
      "content": "pan right begins midway, then reverses left",
      "required": true
    }
  ]
}
```

Qwen只负责把这些 sentence plans改写成自然语言。输出时要求额外返回：

```json
{
  "caption": "...",
  "covered_event_ids": ["e0", "e1", "e2"]
}
```

随后独立 parser重新检查 primitive、方向、顺序和 event coverage。Qwen漏掉 required event时直接回退到 deterministic template，不要反复采样直到“看起来合理”。这会把 LLM 从“信息选择器”降级为“表面语言实现器”，显著降低长序列遗漏风险。

第六类是 **只对极端长 macro graph使用分块生成**。先统计压缩后每条样本的 `N_axis_event` 和 `N_macro_event` 分布，不应预先假设所有 62-step 序列都复杂；很多长轨迹可能只是一个持续 dolly 加一个 pan。若压缩后 p99 仍超过例如 8 个 macro nodes，可以在以下自然边界切块：

* 持续静止区间；
* 明确方向反转；
* 主导 primitive 更换；
* 长时间事件结束；
* early/middle/late 的自然段落边界。

每个 chunk包含大约 3–6 个 macro event，由 Qwen分别生成一句或两句，然后按确定性时间顺序拼接。不要再用第二次 LLM 对这些句子做全局总结，否则仍可能发生遗漏。short caption则直接由全局 macro summary生成，不依赖 long caption再次压缩。

因此推荐的最终路线是：

[
\boxed{
\begin{aligned}
&\text{strict-stride six-axis rates}\
\rightarrow;&\text{per-axis hysteretic intervals}\
\rightarrow;&\text{same-axis run merging}\
\rightarrow;&\text{speed-profile simplification}\
\rightarrow;&\text{overlap / nesting / reversal graph}\
\rightarrow;&\text{repetition and transition macro events}\
\rightarrow;&\text{deterministic short/long sentence plans}\
\rightarrow;&\text{Qwen surface realization}\
\rightarrow;&\text{event-ID coverage + reparse QC}.
\end{aligned}
}
]

最优先实现的并不是复杂的通用 change-point clustering，而是三个简单且高收益的压缩规则：

1. 同轴、同方向、短 gap 的 interval 合并；
2. 长主运动与短 secondary motion 的 parent–child nesting；
3. 重复、反转和速度趋势的 macro pattern。

实现后先在 162,760 条数据上统计：

[
N_{\rm step},\quad
N_{\rm axis\ event},\quad
N_{\rm macro},\quad
N_{\rm required}.
]

只有看到压缩后的 p95/p99 macro 数量，才决定是否需要 chunking和具体的单次 Qwen 输入上限。评估也不要只看最终 caption 可读性，应同时报告：

[
\text{required-event recall},
\quad
\text{direction accuracy},
\quad
\text{temporal-relation accuracy},
\quad
\text{hallucinated-event rate},
]

以及

[
\text{compression ratio}
========================

\frac{N_{\rm raw\ step}}{N_{\rm macro}}.
]

一句话概括：**可以合并 step，但权威操作应是“事件归并”，不是“标签去重”；进一步通过嵌套、重复和速度轮廓把事件压成自然语言宏结构，让 Qwen只负责说出来，而不负责决定保留什么。**
