### 1.2 本轮不可改变的边界

- Operational mainline 在新 promotion decision 前仍是 v9 Pulp-only、non-causal Stage1 加
  C0-LAT Camera `105K`，Human teacher 冻结于 `105K`。
- 新 C0 派生 run 默认使用 no-source 实现；不得重新引入 historical `source_id`。
- StoryMotion Stage1／Stage2 始终断言 `is_causal=false`；不恢复 joint-parallel 或 evolving-H。
- 一个 checkpoint、decoder、cache、normalizer、ordered IDs、sampler 与 evaluator 组成一个完整
  evidence row；不得跨 endpoint 摘取单列最优。
- 混合系统比较必须显式写 native／adapted、Human condition、representation、decoder、训练 exposure、
  sampler 与 runtime；同 cohort 不等于单变量因果对照。
- 组合式 editing、Rect、HumanML3D、ViGen utility 与 DIRECT 队列不在本轮长训范围。

## 3. P0-A：Stage1 Phase C 因果审计与训练

### C1｜代码审计／合同

当前实现已可静态确认：Phase C 的 `total=human_total+camera_total`，Human encoder／decoder
均可训练且 Human 参数组使用 `0.1×` LR；`camera_total` 可通过 Camera conditioner 回传到
Human encoder，但不会到 Human decoder。本轮不只复述该事实，而是回答两个分开的因果问题：

1. `G`：Camera loss 是否必须更新 Human encoder？
2. `U`：Phase C 是否必须继续用 Human loss 更新 Human branch？

预声明三个 treatment：

| arm | Camera→Human gradient `G` | Phase-C Human update `U` | 解释 |
| --- | --- | --- | --- |
| A0 current control | on | on | 现有 v9 Phase C；仅在 exact Phase-B parent 与代码/hash 可核验时复用 |
| A1 detach-camera | off | on | Camera path 使用 detached Human context；Human loss仍更新 Human encoder／decoder |
| A2 freeze-human | off | off | Phase C 完整冻结 Human encoder／decoder，只更新 interaction／Camera modules |

实现验收：

- 对 `camera_total` 单独反传：A0 的 Human-encoder grad 非零；A1/A2 为 exact zero；三臂
  Human-decoder grad 都为 zero。
- 对 `human_total` 单独反传：A1 的 Human encoder／decoder grad 非零；A2 不在 optimizer 且参数
  hash 从 Phase-B parent 到 endpoint 完全不变。
- 三臂从同一个 immutable Phase-B checkpoint 分叉。若 A0 无法证明同 parent、同 order、同代码边界，
  则 A0 必须作为新 run 在 4090 上重跑；不得拿不匹配的历史 endpoint 伪装 control。
- 新合同显式记录 `camera_loss_reaches_human` 与 `phase_c_human_update`，并增加 optimizer-membership、
  per-loss gradient、checkpoint reload 测试。

### T1｜Phase C 两个新 arm 长训

| --- | --- | --- | --- |

| 4090 GPU1 | `sm_stage1_phasec_g0_u0_seed17_4090g1_20260812` | A2，同一 Phase-B parent、同 exposure | C1 全部测试与 contract preflight 通过 |

GPU utilization 与 memory。若 Phase-B parent 缺失或 hash 不一致，先停止并建立新的 matched A0/A1/A2
执行，不从不明 checkpoint 继续。

### I1｜Stage1 formal 与 downstream gate

## 5. P0-C：公平的 Human→Camera 组合基线

### C3｜先做接口与公平性矩阵

独立双 EncDec 已完成，但它同时改变 representation、decoder、normalizer/cache、参数量和 runtime，不能单独
回答“为什么不直接组合 off-the-shelf Human 与 Camera 模型”。本轮先审计可组合接口，再执行兼容 pair：

- Human candidates：v9 frozen Human、MoMask-Pulp、MotionLab-MFT；独立-H只作已有 native-chain reference。
- Camera candidates：C0-LAT、Director-C／E.T.、CCD-Pulp；独立-C只作已有 native-chain reference。
- 每个 Camera candidate 必须明确接收 full motion、pelvis/root trajectory、StoryMotion latent 还是 native latent，
  是否真正消费 Camera text，以及生成 Human 是否需 decode→coordinate conversion→re-encode。
- 每个 pair 记录 native／adapted、训练数据、checkpoint、Human condition、coordinate convention、encoder／decoder、
  sampler steps、exposure、是否重新训练。接口不兼容的 cell 标记 `not comparable`，不靠静默 zero-pad 或错位 latent
  凑齐矩阵。

当前只读接口审计得到以下执行边界：

| candidate | native output／condition | 接 C0-LAT 的合法路径 | zero-retrain status |
| --- | --- | --- | --- |
| v9 frozen Human | Human text→v9 H128 | 直接输入 C0-LAT | canonical；无需adapter |
| MoMask-Pulp | native RVQ→Pulp-H199 | native decode→Pulp normalization／mask→exact v9 $E_h$→H128 | zero-retrain pure4,053 formal闭合；system-level |
| MotionLab-MFT | v7.14 H128→v7.14 $D_h$→Pulp-H199 | v7.14 decode→Pulp bridge→exact v9 $E_h$→H128 | zero-retrain pure4,053 formal闭合；同为128D不代表latent兼容 |
| independent-H | independent H128→independent $D_H$→Human199 | branch denorm/decode→Pulp bridge→exact v9 $E_h$→H128 | adapter-only理论可行；未审计 |
| C0-LAT | v9 H128＋Camera text→v9 C64→Pulp-C14／framing | canonical v9 owner内直接运行 | canonical；无需adapter |
| Director-C／E.T. | GT pelvis＋Camera text→native 9D C2W | 只作native standalone；C2W→metric bridge | 可重评native输出；不能替换C0 C64 |
| CCD-Pulp | v7.14 H latent＋Camera text→v7.14 Camera latent→Pulp-C14 | 只作native standalone；owning decoder→metric bridge | 可重评native输出；不能直接拼接C0 |
| independent-C | independent H128＋Camera text→independent C64→absolute C2W14 | 只作independent native chain；absolute→official Camera14 evaluator bridge | native chain可复用；不能直接替换C0 C64 |

因此 Tier A 的第一合法扩展路径是外部 Human 输出经各自 owning decoder 回到 Pulp-H199，再通过 exact v9
normalization、valid mask 与 $E_h$ 进入 C0-LAT。每个 candidate 都必须新建 run contract 并验证 decoder、
normalizer、sample identity 与重编码误差；Director-C、CCD-Pulp、independent-C 保留各自 native representation、
decoder与Camera text接口，只能作为system-boundary输出进入统一evaluator。当前代码没有覆盖这些外部baseline的
统一API，不得把历史artifact audit写成已实现的组合runner。

### I3｜两层组合实验

1. **Tier A：零重训组合推理。** 对通过接口审计的 Human×Camera pair 做 Generated-H→Camera pure 4,053；
   Human 输出只生成一次并复用。Direct-H 沿用各自正式结果，Observed-H Camera 沿用各 Camera baseline 的正式结果。
2. **Tier B：最小 matched adaptation。** 只有当一个关键 Camera baseline 需要薄 adapter 才能接收生成 Human 时，
   冻结 Human 与 Camera 主体，仅训练预声明 adapter；不得把全模型重训后仍称 off-the-shelf composition。

> [!success] 2026-08-13 I3 Tier-A formal closure
> 5090 SSD上完成MotionLab→C0与MoMask→C0两条zero-retrain pair：external Human只生成／byte-exact
> replay一次，经owning decoder→Pulp H199→exact v9 $E_h$接同一C0-LAT；各自pure4,053 formal、
> 相对canonical C0的10k paired comparison与8视频完整decode均通过。两条pair均可执行，但
> Generated-H Camera semantic、caption、projective framing与Human semantic／geometry大幅回退；较低
> Camera ADE/FDE/rotation只作dataset-target deviation。故simple-composition gate关闭为system-level
> negative trade-off，不构成单变量architecture superiority。接口已兼容，Tier-B adapter既非必要也未授权。
> 正式数字与identity只见
> [[ideas/StoryMotion/StoryMotion-valid-metric-ledger#Audited detail — §3.31 Tier-A zero-retrain Human→C0-LAT composition baselines]]。

公平比较按以下层级解释：

| 层级 | 可回答的问题 | 不可回答的问题 |
| --- | --- | --- |
| same Human + same Camera + only interface treatment | 接口／conditioning 的局部因果影响 | 跨模型总体优越性 |
| same cohort, native systems | 系统级 feasibility 与 trade-off | representation 或 decoder 的单变量贡献 |
| off-the-shelf pair | 实际可组合性、OOD robustness | matched training-budget superiority |

该矩阵是 Q5／Q30／Q32 的核心证据。若简单组合与 StoryMotion 等价，方法 claim 必须在结果后转向系统／评测贡献；
若 StoryMotion 在预注册 Camera semantic、framing、naturalness 上一致且非微小地胜出，才支持 relation-aware
factorization 的必要性叙述。

## 6. P1：H-steps × C-steps、资源画像与指标解释

- 所有 cell 使用同一 pure 4,053 IDs、seed 与 base noise，并保留完整 metric，即使某指标不适合作主指标。

| field group | required fields | rule |
| --- | --- | --- |

| provenance | `contract_sha256`、`checkpoint_sha256`、`source_artifact_sha256`、`renderer_sha256` | 任一hash缺失则不能进入blind-ready |
| media | `view`、`asset_path`、`asset_sha256`、`codec`、`fps`、`frame_count`、`duration_seconds` | 必须single asset；concat只作summary |
| blinding | `anonymous_system_id`、`presentation_order`、`blinding_seed` | 评分manifest不得暴露run名或metric rank |
| state | `status`、`eligibility`、`reason_code` | 资产状态与实验资格分开；`status`只用`ready/missing/invalid/superseded`，`eligibility`只用`formal_candidate/diagnostic_only/excluded` |

冻结顺序为：先冻结 eligible endpoint 与 ordered IDs → 再冻结 per-sample ranking metric／failure threshold／
random seed → 生成 sample selection 与 hash → 最后才允许作者看片。`best/worst` 只用于透明的极值与失败分析，
不得用于 checkpoint、CFG scale 或主表 promotion；`random` 使用固定seed在完整eligible ID集合上无放回抽样；
failure strata 只按看片前冻结的动作、长度、root velocity、Camera primitive、rotation、out-of-screen规则进入，
同一样本可有多个failure tag但只能有一个canonical cell identity。现有
[[StoryMotion/StoryMotion_Gradio_Render]] 的single-asset、显式`missing`与archived-exclusion规则继续复用。
正式 comparative panel 的所有 arm 共用同一批 sample IDs；`best/worst`只能由一条预注册 reference run
和一个 metric recipe选样，不能按模型分别选最好结果。排序固定为
`SHA256(selection_seed || sample_id)`，平局以sample ID打破，并按source／near-duplicate cluster去重。
盲评顺序固定为`SHA256(blind_seed || panel_id || sample_id || arm_id)`；run名、路径、metric/rank与
`blind_key.json`不得进入展示目录。现有fixed-8、Top-5与旧screen都只作显式diagnostic cohort，不能混入U1的
formal random样本。
