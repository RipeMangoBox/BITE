# HY-Motion的若干不足，从点到面找问题

> [!abstract] **Quick Links & TL;DR**
> - **主结论**：HY-Motion 已经把“动作大模型”这条路跑通了，但它当前更像一个**强单段生成器**，而不是一个**强结构化控制器**。一旦任务进入复杂 duration、多阶段组合、细粒度部位控制、事件级奖励和全局物理一致性场景，它的短板会系统性暴露。
> - **我最关心的五个根因**：`duration/rewrite 接口压扁原始意图`、`细粒度时间/部位监督不足`、`长时程全局规划缺位`、`控制接口弱结构化`、`reward 覆盖不够完整`。
> - **实习生视角的判断**：下一阶段不应该只做“更大模型”或“再加一点 RL”，而应该补一个 **structured planning + structured supervision + structured reward** 的中间层。

## 先给总判断

- [[paperAnalysis/Motion_Generation/Tencent_HY/2025_HY_Motion_1_0_Scaling_Flow_Matching_Text_to_Motion|HY-Motion 1.0]] 解决的是“连续 flow-matching 动作模型能否 scale 到大模型并在开放动作类目上跑赢现有开源方法”。
- 它没有真正解决的是“复杂用户意图如何在生成过程中被保真地分解、调度、约束和验收”。
- 所以它今天的优势非常明确：
  - 语义覆盖更广；
  - 基础动作质量更高；
  - 单段开放文本生成更强。
- 它今天的短板也很明确：
  - 复杂动作是“生成出来了”，但未必“按结构完成了”；
  - duration 和 prompt rewrite 解决了用户接口噪声，却没有解决结构化控制；
  - RL 对齐解决了局部伪影和 pass rate，却没有真正覆盖事件完整性、长程轨迹和风格保真。

## 根因树

### 1. duration prediction 和 rewrite 不是小补丁，而是接口级信息瓶颈

你原始笔记里的这几条，我认为是同一个系统问题：

- 动作完成是前提，否则 duration 模块容易 reward hack，只学会“在规定时长内停掉”。
- rewrite LLM 的训练目标只看“语义一致性 + 时长合理性”，不看风格/重点/约束保真。
- 生成主干只吃 rewritten prompt，原始 prompt 被丢弃，信息瓶颈在接口层就产生了。

这意味着 HY-Motion 现在其实在做一件很激进的事：**先用 LLM 把真实用户需求压缩成单段、结构化、可执行的文本，再让 DiT 生成动作。** 一旦这个压缩过程丢信息，后面的 1B DiT 再强也只能忠实地生成“压缩后的目标”。

**KB 里最像的同类问题与解法**：

| 问题                      | 对应论文                                                                                                                                                                             | 他们的解法           | 对 HY-Motion 的可迁移性 |                                                   |                                                                                       |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- | ----------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 复杂指令在单轮生成里被压扁           | [[paperAnalysis/Motion_Generation/ICLR_2026/2026_Motion_R1_Enhancing_Motion_Generation_Decomposed_CoT_RL_Binding                                        | Motion-R1]]     | Motion-R1         | 先显式输出 `<think>/<output>` 结构化动作分解，再生成 motion       | 很值得借鉴，但不建议把 HY-Motion 直接改成离散 token LLM；更适合做成 **planner sidecar** 或 latent plan tokens |
| 单轮生成缺少自检回路              | [[paperAnalysis/Motion_Generation/arXiv_2025/2025_IRG_MotionLLM_Interleaving_Motion_Generation_Assessment_and_Refinement_for_Text_to_Motion_Generation  | IRG-MotionLLM]] | IRG-MotionLLM     | 生成-评估-修正交错推理，边做边改                                 | 适合拿来做 **candidate reranking / self-refinement**，不一定要全量在线多轮 rollout                    |
| 句向量过度偏向动作名，忽略 specifics | [[paperAnalysis/Motion_Generation/NeurIPS_2023/2023_GraphMotion_Act_As_You_Wish_Fine_grained_Control_of_Motion_Diffusion_Model_with_Hierarchical_Semant | GraphMotion]]   | GraphMotion       | 把文本拆成 hierarchical semantic graph，单独保留方向、部位、方式等细节 | 对大模型更合理的迁移方式是 **graph/plan supervision**，而不是照搬小 backbone                              |

**我的判断**：

- HY-Motion 下一步不该只是“把 rewrite LLM 训得更聪明”，而应该让 rewrite 从“单段改写器”升级成“结构化计划器”。
- 最关键的不是生成一个更漂亮的 rewritten prompt，而是保留一个可传递给生成主干的 **事件级中间表示**：
  - 原始用户意图；
  - 分解后的子动作序列；
  - duration 分配；
  - 局部重点和禁止项。

### 2. 数据问题已经不是“量不够”，而是“监督粒度不对”

HY-Motion 论文已经非常强调数据规模和数据清洗，这件事做得对。但它的下一个瓶颈不再是“数据少”，而是：

- caption 仍然偏单段、整体；
- 细粒度时序和 body-part 描述不足；
- “同一个语义，不同时长/节奏/执行风格”的 supervision 还不够显式。

这正对应你原 note 里的这些问题：

- 相同 text 如何在不同 duration 下训练；
- augment 应该改帧率、插空白还是学 tempo；
- backward 语义 grounding 不足，模型容易回落到高频模式。

**KB 中最直接的对照解法**：

| 问题                        | 对应论文                                                                                                                                                                                                  | 他们的解法        | 对 HY-Motion 的可迁移性                                  |                                                         |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------ | -------------------------------------------------- | ------------------------------------------------------- |
| 文本太粗，无法告诉模型“何时、哪个部位、做了什么” | [[paperAnalysis/Motion_Generation/ICCV_2025/2025_FineMotion_A_Dataset_and_Benchmark_with_both_Spatial_and_Temporal_Annotation_for_Fine_grained_Motion_Generation_and_Editing | FineMotion]] | 自动构建 0.5s 片段级 body-part 描述，双文本条件（粗粒度 + 细粒度）联合训练    | 非常值得迁移。对 HY-Motion 不一定要全量重标，而是先做 **failure slice 精细标注** |
| 大规模 web 数据有噪声，不能简单全吃      | [[paperAnalysis/Motion_Generation/ICLR_2025/2025_PedGen_Learning_to_Generate_Diverse_Pedestrian_Movements_from_Web_Videos_with_Noisy_Labels                                  | PedGen]]     | reconstruction-based 异常过滤 + mask embedding 吃部分可靠标签 | 可借鉴到 HY-Motion 的视频估计数据，尤其适合处理部分时序可信、部分时序不可信的样本          |
| 大规模高质量控制数据才是上限            | [[paperAnalysis/Motion_Generation/arXiv_2026/2026_Kimodo_Scaling_Controllable_Human_Motion_Generation                                                                        | Kimodo]]     | 用更大规模、更高质量、带细粒度约束的动作数据支撑 controllable generation   | 提醒我们：大模型最终还是被数据定义上限，结构化标注不能缺位                           |

**我的判断**：

- 对 1B 级动作模型来说，数据粒度错误比 loss 设计错误更伤。
- 如果只继续扩 3000h 粗 caption 数据，HY-Motion 大概率会继续提升 coverage，但不会自然长出“复杂动作细节保真”和“时间结构控制”。
- 更有效的路径是：
  - 在 400h 高质集上补 **timeline / body-part / event-level** 标注；
  - 做相同语义、不同 duration 的对比 supervision；
  - 把 duration 视为 phase/tempo 变量，而不是只视为一个 scalar。

### 3. 局部时间建模很强，但全局规划仍然是薄弱环节

HY-Motion 的 121-frame 窄带注意力很适合学局部动力学稳定性，但它天然不是一个显式的长时程 planner。这就会导致：

- 空翻、转体、连贯多阶段动作，局部看都对，但全局轨迹不一定对；
- duration 满足了，但动作完成度不一定满足；
- 多阶段语义之间的过渡容易依赖 implicit prior，而不是 explicit planning。

这和你写的这几条是同一根因：

- 全局上下文建模有限；
- 模型无法同时满足“正确动作类别 + 指定时长”时，会先保 duration；
- 合理空翻轨迹不是窗口内局部动力学能自己推出的。

**KB 里最相关的方案**：

| 问题 | 对应论文 | 他们的解法 | 对 HY-Motion 的可迁移性 |
|---|---|---|---|
| 多段动作边界生硬，长程语义和局部平滑冲突 | [[paperAnalysis/Motion_Generation/CVPR_2024/2024_FlowMDM_Seamless_Human_Motion_Composition_with_Blended_Positional_Encodings|FlowMDM]] | 早期用绝对位置编码建立全局结构，后期切换到相对编码保证局部平滑 | 对 HY-Motion 很有启发，尤其适合做 **多事件时序生成** 的位置编码调度 |
| 长序列组合时缺少跨段通信 | [[paperAnalysis/Motion_Generation/ICLR_2024/2024_PriorMDM_Human_Motion_Diffusion_as_a_Generative_Prior|PriorMDM]] | 握手区约束 + 第二次局部精修，显式做段间耦合 | 适合做 inference-time composer，但如果只靠后处理，天花板有限 |
| 长序列过渡的根因在 phase 不连续 | [[paperAnalysis/Motion_Generation/NeurIPS_2025/2025_TransPhase_Deep_Compositional_Phase_Diffusion_for_Long_Motion_Sequence_Generation|TransPhase]] | 在相位潜空间里做跨段联合去噪，让相邻段共享节律 | 很适合迁移成 HY-Motion 的 **tempo/phase plan head** |
| 复杂动作应该先有粗结构再补细节 | [[paperAnalysis/Motion_Generation/TPAMI_2024/2024_GUESS_GradUally_Enriching_SyntheSis_for_Text_Driven_Human_Motion_Generation|GUESS]] | coarse-to-fine skeleton generation | 对大模型更适合做 **global plan → local refinement** 的蒸馏，而不是照搬多级小模型 |

**我的判断**：

- HY-Motion 的问题不在于“窗口太小”，而在于缺少一个明确的 **global action plan / root plan / phase plan**。
- 所以最合理的演进方向不是简单把局部窗口变大，而是补一个上层结构：
  - 先规划 duration 分配、关键阶段和 root/phase 轮廓；
  - 再让 HY-Motion DiT 做高保真细化。

### 4. 现在的控制接口太弱结构化，导致复杂约束只能靠 prompt 硬塞

HY-Motion 现在最强的是“文本驱动单段生成”，最弱的是“带结构约束的 controllable generation”。这在实习生视角下会直接变成产品和研究问题：

- 你很难稳定地指定某个 body part、某个时间段、某个关键姿态；
- 你很难强行让模型 obey 一个 root path 或 sparse key pose；
- 你也很难让 duration 成为强控制，而不伤害语义保真。

**KB 里更成熟的 controllability 思路**：

| 问题 | 对应论文 | 他们的解法 | 对 HY-Motion 的可迁移性 |
|---|---|---|---|
| 复杂约束类型无法统一 | [[paperAnalysis/Motion_Generation/arXiv_2026/2026_Kimodo_Scaling_Controllable_Human_Motion_Generation|Kimodo]] | root/body 两阶段去噪 + 直接约束注入，统一支持 keyframe、sparse joints、2D path 等控制 | 非常适合作为 HY-Motion 的未来控制接口方向，且比很多小模型 trick 更接近“大模型系统升级” |
| 稀疏控制和动作质量互相拉扯 | [[paperAnalysis/Motion_Generation/ICCV_2025/2025_SFControl_Motion_Synthesis_with_Sparse_and_Flexible_Keyjoint_Control|SFControl]] | 先做关键关节轨迹，再补全全身运动，解耦 controllability 和 naturalness | 思路很强，但更适合作为 **外部控制 adapter**，不是直接替换 HY-Motion backbone |
| 多部位同时受约束时，全身协调性容易崩 | [[paperAnalysis/Motion_Generation/ECCV_2024/2024_ParCo_Part_Coordinating_Text_to_Motion_Synthesis|ParCo]] | 分部位生成 + 协调模块通信 | 可借鉴其“分工 + 协调”思想，但离散多生成器路线对大模型未必最优 |
| 文本细节无法稳定落到 body part/time span | [[paperAnalysis/Motion_Generation/NeurIPS_2023/2023_GraphMotion_Act_As_You_Wish_Fine_grained_Control_of_Motion_Diffusion_Model_with_Hierarchical_Semant|GraphMotion]] | 把 text-control 变成图结构传播，而不是全压成一个 embedding | 很值得和 HY-Motion 的大文本条件结合 |

**我的判断**：

- HY-Motion 未来如果想变成真正的动作基础模型，不能只有 `text + duration -> motion`。
- 更合理的接口应该变成：
  - `user prompt`;
  - `structured plan`;
  - `optional constraints`。
- 也就是把 foundation model 当 prior，用 planner / controller / constraint adapter 去组织它，而不是逼它从单个 prompt 里学会所有控制逻辑。

### 5. RL 已经在起作用，但 reward 覆盖还不够“结构化”

HY-Motion 的 DPO + Flow-GRPO 已经说明一件事：**监督学习的目标和真实用户想要的目标并不一致**。这点非常重要。但它现在的 reward 还偏“底线型”：

- 语义 reward 关注 aligned 不 aligned；
- 物理 reward 关注脚滑、root drift；
- 缺少对子动作完整性、事件顺序、风格保真、全局轨迹物理一致性的评价。

这也正好对应你写的：

- reward 覆盖不足；
- 物理 reward 更像 local artifact penalty；
- 没有覆盖全局轨迹物理一致性和复杂意图 preservation。

**KB 中最对口的几篇**：

| 问题 | 对应论文 | 他们的解法 | 对 HY-Motion 的可迁移性 |
|---|---|---|---|
| 子动作遗漏、顺序错误、频率错误无法被普通 reward 抓住 | [[paperAnalysis/Motion_Generation/CVPR_2025/2025_AToM_Aligning_Text_to_Motion_Model_Event_Level_GPT4Vision_Reward|AToM]] | 把 reward 分解为完整性、时序、频率三类事件级信号 | 非常值得借鉴，尤其适合补齐 HY-Motion 的事件级评测与对齐 |
| 复杂指令需要“先想再做”，而不是只做最终对齐 | [[paperAnalysis/Motion_Generation/ICLR_2026/2026_Motion_R1_Enhancing_Motion_Generation_Decomposed_CoT_RL_Binding|Motion-R1]] | 用结构化计划和语义/动作双路奖励绑定最终结果 | 适合作为生成前 planning 或训练中 auxiliary targets |
| 更强的对齐来自生成-评估-修正闭环 | [[paperAnalysis/Motion_Generation/arXiv_2025/2025_IRG_MotionLLM_Interleaving_Motion_Generation_Assessment_and_Refinement_for_Text_to_Motion_Generation|IRG-MotionLLM]] | 让模型显式输出 assessment/refinement，而不是只优化终值 | 对大模型尤其有意义，因为 compute 可以换更强校正能力 |
| 只跟踪轨迹会导致不自然，需要 style reward | [[paperAnalysis/Motion_Generation/ECCV_2024/2024_MHC_Generating_Physically_Realistic_and_Directable_Human_Motions_from_Multi_Modal_Inputs|MHC]] | tracking reward + style discriminator + CCC 能力训练 | 提醒我们：reward 不能只有 obey，还得有自然性和恢复性 |

**我的判断**：

- HY-Motion 的下一代 reward 不应该只问“像不像”和“滑不滑”，还应该问：
  - 子动作有没有都做完；
  - 顺序对不对；
  - 重复次数对不对；
  - 风格/约束有没有被 rewrite 冲掉；
  - 全局轨迹是不是合理。
- 但这些 reward 不适合直接全部做成昂贵的在线 RL。更现实的办法是：
  - 先用 GPT-4V/VLM 评估器、事件分解器离线造高质量偏好数据；
  - 再蒸馏成更便宜的 reward heads 或 reranker。

## 把你原始问题并回到更大的结构里

### 1. duration prediction 问题

- **表面问题**：模型要同时支持自动预测合理时长，以及在用户指定时长下合理完成动作。
- **深层根因**：HY-Motion 把 duration 当成了单段接口变量，但很多动作的 duration 本质上取决于内部 phase 结构，而不是一个独立 scalar。
- **更合理的解法方向**：
  - 用 [[paperAnalysis/Motion_Generation/NeurIPS_2025/2025_TransPhase_Deep_Compositional_Phase_Diffusion_for_Long_Motion_Sequence_Generation|TransPhase]] 式 phase 表示，或 [[paperAnalysis/Motion_Generation/CVPR_2024/2024_FlowMDM_Seamless_Human_Motion_Composition_with_Blended_Positional_Encodings|FlowMDM]] 式多段 `(text, duration)` 规划；
  - 把 duration 从“结果要求”改成“结构性计划”的一部分。

### 2. rewrite 训练目标偏差

- **表面问题**：reward 只看语义一致性和时长合理性，没有 style/constraint preservation。
- **深层根因**：rewrite 被定义成“规范化文本”，不是“结构化保真计划”。
- **更合理的解法方向**：
  - 加入 [[paperAnalysis/Motion_Generation/CVPR_2025/2025_AToM_Aligning_Text_to_Motion_Model_Event_Level_GPT4Vision_Reward|AToM]] 式事件级对齐目标；
  - 加入 [[paperAnalysis/Motion_Generation/ICLR_2026/2026_Motion_R1_Enhancing_Motion_Generation_Decomposed_CoT_RL_Binding|Motion-R1]] / [[paperAnalysis/Motion_Generation/arXiv_2025/2025_IRG_MotionLLM_Interleaving_Motion_Generation_Assessment_and_Refinement_for_Text_to_Motion_Generation|IRG-MotionLLM]] 式 planning/refinement 中间态。

### 3. 数据分布不平衡

- **表面问题**：高频动作和高频 caption 模式会吸走模型的概率质量。
- **深层根因**：3000h 数据负责 coverage，但 400h 高质数据仍然缺少足够的细粒度、长尾、结构化对齐信号。
- **更合理的解法方向**：
  - 用 [[paperAnalysis/Motion_Generation/ICCV_2025/2025_FineMotion_A_Dataset_and_Benchmark_with_both_Spatial_and_Temporal_Annotation_for_Fine_grained_Motion_Generation_and_Editing|FineMotion]] 式时空细粒度注释补关键 failure slice；
  - 用 [[paperAnalysis/Motion_Generation/ICLR_2025/2025_PedGen_Learning_to_Generate_Diverse_Pedestrian_Movements_from_Web_Videos_with_Noisy_Labels|PedGen]] 式部分可信标签利用策略，提高 web data 利用率而不盲信伪标签。

### 4. 全局上下文建模有限

- **表面问题**：窗口内足够平滑，但窗口外不一定足够合理。
- **深层根因**：HY-Motion 当前更像 local dynamics generator，而不是 explicit global planner。
- **更合理的解法方向**：
  - 引入 root/phase/keypose 级中间计划；
  - 让 [[paperAnalysis/Motion_Generation/CVPR_2024/2024_FlowMDM_Seamless_Human_Motion_Composition_with_Blended_Positional_Encodings|FlowMDM]]、[[paperAnalysis/Motion_Generation/ICLR_2024/2024_PriorMDM_Human_Motion_Diffusion_as_a_Generative_Prior|PriorMDM]]、[[paperAnalysis/Motion_Generation/NeurIPS_2025/2025_TransPhase_Deep_Compositional_Phase_Diffusion_for_Long_Motion_Sequence_Generation|TransPhase]] 这些“多段/过渡”想法变成大模型的上层结构，而不是事后 stitching。

### 5. RL 阶段 reward 覆盖不足

- **表面问题**：脚滑和 root drift 被管住了，但全局轨迹和事件级失败没被真正管住。
- **深层根因**：reward 仍偏局部、偏后验，没有把“完成什么”和“如何完成”拆开。
- **更合理的解法方向**：
  - 事件级 reward：[[paperAnalysis/Motion_Generation/CVPR_2025/2025_AToM_Aligning_Text_to_Motion_Model_Event_Level_GPT4Vision_Reward|AToM]]
  - process reward / refinement reward：[[paperAnalysis/Motion_Generation/arXiv_2025/2025_IRG_MotionLLM_Interleaving_Motion_Generation_Assessment_and_Refinement_for_Text_to_Motion_Generation|IRG-MotionLLM]]
  - style / complete / catch-up reward：[[paperAnalysis/Motion_Generation/ECCV_2024/2024_MHC_Generating_Physically_Realistic_and_Directable_Human_Motions_from_Multi_Modal_Inputs|MHC]]

## 如果我是组里的实习生，我会怎么切

### 第一优先级：先补“看得见问题”的诊断层

1. 保留原始 prompt，不再只把 rewritten prompt 喂给主干。
2. 在现有 eval 之外，加事件级评测：
   - 完整性；
   - 时序；
   - 频率；
   - style preservation；
   - 全局轨迹合理性。
3. 做一个 failure set：
   - duration 冲突样本；
   - 多阶段动作样本；
   - 左右/局部部位约束样本；
   - 高难动作轨迹样本。

### 第二优先级：补“结构化中间层”，而不是先动 backbone

1. planner sidecar：
   - 原始 prompt → 事件级 plan；
   - plan → duration/phase/keypose/root sketch；
   - HY-Motion 负责高保真生成。
2. constraint adapter：
   - 先支持 key poses / sparse root path / body-part emphasis；
   - 再逐步扩到更强 controllability。

### 第三优先级：再考虑 reward 和数据升级

1. 先离线构建事件级偏好数据，再蒸馏 reward。
2. 在高价值失败 slice 上补 FineMotion 风格的时空标注。
3. 不急着全量重训 3000h；先做小规模高价值数据闭环，确认结构化 supervision 真能修问题。

## 不建议直接做的几件事

- 不建议把小模型上的离散 token trick 直接替换成 HY-Motion 主范式。大模型的优势就在连续高保真和大规模先验，轻易回退到小 token 范式，很可能伤了质量上限。
- 不建议先把 RL 做得更重。reward 没补齐之前，更多 online RL 容易只是更强地优化错误目标。
- 不建议先靠“更长窗口”解决长程问题。没有显式 plan 时，更长窗口只会更贵，不一定更会规划。

## 一句话总结

HY-Motion 现在最缺的不是更大的生成器，而是一个位于 `user intent` 和 `motion prior` 之间的 **结构化中间层**。谁把这个中间层做好，谁就更有机会把“动作大模型”从强单段生成器推进到强可控动作基础模型。
